# NovelForge 开源边界、界面与文本质量审计

审计日期：2026-09-14

## 1. 结论

当前仓库已经具备作为开源桌面应用发布的主体结构，但正式公开前仍有两个阻塞项：仓库没有 `LICENSE`，并且依赖审计还剩 8 条只能通过破坏性大版本迁移解决的生产依赖告警。没有许可证并不等于默认开源，外部用户通常无权复制、修改或分发代码。需要先明确选择 MIT、Apache-2.0、GPL-3.0 等许可证，再补许可证正文和 README 徽章。

本轮已删除不可达页面、废弃状态层、一次性样例/验收脚本与已失效入口，共 88 个受版本控制文件；保留后的 TypeScript/TSX 文件均可从生产入口或测试入口到达。剩余 `scripts/` 都有 `package.json` 或其他维护脚本引用，不再包含只适用于作者本机、指定小说或旧任务卡的入口。

产品功能不宜按“页面多就是多余”直接删除。写作、合同、回写、修订和质量页共同构成长篇生产闭环；可调整的是入口层级、默认可见性和页面职责，而不是删掉底层数据能力。

## 2. 哪些内容应公开

### 2.1 开源源码仓库应包含

- `src/`：前端界面、共享类型与规则。
- `electron/`：桌面主进程、数据库、服务与 IPC/Web RPC 能力。
- `build/`：图标、安装器资源及构建所需文件。
- `scripts/`：被 npm 命令或其他维护脚本实际调用的构建、检查、测试脚本。
- 测试文件：它们是回归证据，也是外部贡献者理解契约的重要入口。
- `package.json`、`package-lock.json`、TypeScript/Vite/Vitest/ESLint/Drizzle/Electron Builder 配置。
- README、产品/架构文档、贡献说明、许可证和安全说明。

### 2.2 安装包终端用户需要

- 打包后的应用代码、运行时依赖、图标和必要资源。
- README/帮助入口、许可证及第三方许可声明。
- 不需要源码、测试、开发脚本、开发数据库或验收证据。当前 Electron Builder 的 `files` 边界以构建产物和 `package.json` 为主，方向正确。

### 2.3 不应公开或不应提交

- `node_modules/`、`out/`、`dist/`、`dist-electron/`、覆盖率、临时测试目录和运行日志。
- `.idea/`、`.vscode/`、TypeScript build info 等个人 IDE/缓存文件。
- `.env*`、API Key、模型密钥、个人数据库、真实小说正文和用户导出数据。
- `.pem`、`.key`、`.p12`、`.pfx`、签名口令和证书。
- 指向作者电脑固定盘符、固定 Windows SDK 或个人软件目录的脚本。
- 为某一本样例小说写死的回填/检查/生成脚本，以及历史任务卡截图、阶段验收证据。

## 3. 文件与脚本清理结果

### 已完成

- 删除两个已被 Studio 工作台替代、且生产入口不可达的 Guide/GuidedStep 页面及样式。
- 删除未被生产代码使用的 `aiDraft`、`ui`、旧工作模式/工作区 stores。
- 删除只包一层调用、且仅由自身测试引用的章节 CRUD/查询/修订契约包装层和地图旅行服务。
- 删除 NF 任务卡验收、旧 UI 截图、真人模型验收、指定样例小说生成/回填/诊断脚本。
- 删除失效的 `eval:platform-samples` 命令及 Playwright 依赖。
- 将仓库标记为 `private: true`，防止误执行 `npm publish`；这不影响 GitHub 开源。
- 修复 NSIS、7-Zip、SignTool 的作者机器绝对路径，改为环境变量、项目依赖、系统目录和 PATH 的可移植发现顺序。
- 增加密钥、证书、IDE、临时证据目录的忽略规则；允许正式 `docs/` 文档进入版本控制。
- 修复 Windows Web RPC 测试删除临时目录时的短暂文件占用竞态。
- 修复 CommonJS Web RPC 运行时加载 ESM-only 本地向量模型失败的问题，避免语义召回静默降级为关键词。
- 升级 MCP SDK 与 React Router 6 的最新兼容版本，并用同主版本 overrides 修复 Hono、Node Server、fast-uri、ip-address、qs、brace-expansion、nanoid；官方生产依赖审计由 16 条降到 8 条。

### 保留原因

- 长篇 soak、迁移、FTS5、接口契约、布局治理、工作流恢复、章节完整性等脚本虽然不是日常入口，但都对应持续有效的产品风险，不能按“平时不运行”删除。
- `build/` 是安装器和图标的构建输入，不是可清理产物。
- `package-lock.json` 应保留，以便贡献者和 CI 得到可复现依赖。

## 4. 逐界面用户审计

浏览器在 1618×887 桌面视口下实际打开了 40 个路由，未发现整页横向溢出。下表中的“保留”表示功能有明确用户价值，不表示当前入口和布局已经最优。移动端仍需补 375、768、1024 宽度的真实交互验收。

### 4.1 全局页面

| 页面 | 必要性 | 用户视角问题 | 建议 |
| --- | --- | --- | --- |
| 我的小说 `/novels` | 核心 | 新建、搜索、进入项目路径清楚；信息密度适中 | 保持为唯一项目入口，后续补最近打开和备份状态即可 |
| 模型配置 `/models` | 必要但高级 | 未选模型时右侧空间偏空；密钥、提供商和模型参数对新用户认知负担高 | 首次配置用向导；高级参数折叠；明确“仅本机保存” |

## 5. 什么才是“人类角度的语言”

“像人写的”不是口语越多越好，也不是禁用某几个连接词。可靠标准是：这句话只能由当前人物在当前处境下说出或注意到，并且它改变了读者对行动、关系、信息或后果的理解。

### 5.1 读者能感到自然的特征

- 视角有限：人物只知道自己有依据知道的事，判断可以偏、可以错。
- 注意力有方向：紧张时先看到威胁，熟人见面先读关系，专业人物先看职业证据。
- 对白有目的：回答、回避、试探、压价、安慰都来自关系，不是轮流播报设定。
- 句子节奏有原因：短句来自压力或动作，长句来自观察或回忆，而不是机械交替长短句。
- 细节有后果：伤口影响动作，天气影响选择，物品影响证据；不按字数配额添加气味、触感和环境描写。
- 留白可推断：动作和对白已经表现出来的意思，旁白不再总结一遍。
- 题材体验具体：悬疑靠证据与误判，职场靠利益与程序后果，感情靠关系温度，不把所有题材写成同一套“阻力—代价—反转”。
- 风格可持续：作者样章、已有正文和角色口吻优先于通用“高级感”建议。

### 5.2 典型 AI 味来源

- 连续使用对称排比、相同句式和相近段长，让每段都像完整小作文。
- 人物做完动作后，旁白再解释情绪、意义和主题。
- “然而、与此同时、某种、仿佛”承担了本应由事件因果承担的衔接。
- 配角只负责递资料、说结论、等主角提问，没有自己的目的和代价。
- 抽象判断多于可观察证据，例如只说局势复杂、气氛微妙、命运改变。
- 为显得生动而无依据地补感官、口误、方言或口头禅。
- 每章被同一套推进/阻力/代价配额切成相同结构。

### 5.3 当前代码已经具备的能力

- 运行时题材自然度校准，不要求所有题材执行同一固定配额。
- 作者样章/人工风格锁优先，以及风格指纹和 A/B 对照。
- Planner、Writer、Reviewer、Rewriter 共享自然度约束。
- 上一章关键先验、章节衔接桥、长期故事记忆、线程/伏笔、人物与世界状态、上下文版本。
- 均匀句段节奏、解释腔、模板连接、对白过度高效、非自然搭配等启发式检测。
- 回写候选、正典确认、版本历史和发布前检查，能避免生成结果直接污染正典。

这些能力说明问题不在“再堆一份禁止词表”，而在真实模型效果验证、用户可见的生成前预检，以及对规则误报的治理。

## 6. 上下文连贯性应如何判断

每次生成至少要让用户能核对一张简短的“章节交接单”：

1. 上一章最后的时间、地点、视角人物和未完成动作。
2. 角色当前伤势、情绪、关系、立场、能力限制和信息边界。
3. 关键物品归属、资源消耗、地图位置和世界规则。
4. 正在推进、到期应回收、明确延后的线程与伏笔。
5. 本章合同要求的目标、冲突结果、禁止事项和章尾压力。
6. 本次实际命中的上下文版本、被裁剪内容及原因。

连贯不等于每章复述上一章。好的承接通常只需一个仍在继续的动作、一个未消散的情绪后果、一个位置/时间信号，或人物对既有信息的自然反应。系统应拦截无解释跳变，不应强迫正文把数据库状态逐项念出来。

## 7. 修复与扩展优先级

### P0：开源发布前

- 维护者选择许可证并新增 `LICENSE`；同步补 `CONTRIBUTING.md`、`SECURITY.md` 和第三方许可说明。
- 建立独立依赖迁移分支，处理剩余 8 条审计告警：`drizzle-orm` 0.30 → 0.45、React Router 6 → 7，以及将已停留在旧 ONNX/Sharp/Protobuf 链的 `@xenova/transformers` 迁移到受维护的兼容方案。当前代码中的数据库标识符、路由目标和本地模型名主要由程序固定，降低了直接利用面，但不能把“暂未发现外部输入路径”当成漏洞已修复。
- CI 固定执行 lint、typecheck、unit、smoke 和应用构建。
- 做一次干净 clone 安装/构建，证明清理后不依赖作者机器、忽略目录或本地数据库。
- 检查仓库历史是否曾提交密钥或真实正文；当前工作树扫描不能替代历史扫描。

### P1：可立即实施的产品修复

- 统一 Structure 页的 shared chrome/action contract。
- 顶部操作只保留一个主动作；“下一步”和“推荐下一步”合并，页面自己的次要动作收进更多菜单。
- 高密度表单按必须/建议/高级分层，优先处理人物、主题与文风、时间轴、合同。
- 写作区增加常驻上下文预检摘要，不要求用户先打开诊断面板才知道生成条件。
- 时间轴等页面的大段阻塞列表改为“首要三项 + 查看全部”，每项直接跳到修复页面。
- 修正 React Flow 隐藏挂载和 Ant Design 表单未连接告警，并为路由切换增加控制台零告警验收。

### P2：信息架构优化

- “小说地图”更名为“叙事地图/叙事看板”，“地图结构”统一为“地点资料”。
- 术语库和场景模板共用“知识与模板”入口。
- 信息差和伏笔账本共用“线索与伏笔”工作区。
- 人物弧线从人物详情进入；完整模式保留跨人物总览。
- 批次工作台只在批量任务存在或任务恢复时出现。
- 题材画像控制成长系统等专业模块的默认可见性。

### P2：语言与上下文质量

- 生成前展示章节交接单，并允许作者将关键事实标记为“必须保留”。
- 审校结果分成“事实/连续性”“角色声音”“语言读感”三组，避免一键润色误改剧情。
- 每条 AI 味判断必须附短证据和可执行改法；单词命中不直接判失败。
- 从作者已接受的正文中学习项目基线，比较“偏离本书”而不是只比较通用阈值。
- Style Lab 增加匿名 A/B 盲选，把作者选择反馈回风格指纹，而不是只展示句长和段长分数。
- 建立跨题材真实样本集：悬疑、现实、言情、历史、玄幻等分别评估，不用单一样例代表全部题材。

### P3：验证体系

- 同一章节至少比较：无风格锁、作者样章锁、通用自然度修订三种结果。
- 由真人盲评“愿不愿继续读、人物是否像同一个人、是否发现无解释跳变”，与规则分数分开记录。
- 记录生成输入的上下文版本、实际命中资产、裁剪原因和输出版本，确保问题可复现。
- 自动测试只能证明契约、顺序和启发式规则没有回归；真实模型输出、人类读感和长篇多章连贯性必须单独验收。

### P3：代码结构债务

- 复杂度审计当前为 230 项，低于仓库基线 258，但仍然偏高。
- 优先拆分 `electron/database/db.ts` 的迁移注册、MapExplorer、CharacterWorkspace、ItemsWorkspace、Contracts、Structure、CoreSettings 和 Timeline workspace hook。
- 拆分目标不是追求小文件，而是把数据加载、表单状态、生成任务、视图呈现和路由同步分开，使每一部分能独立测试。

## 8. 本轮验证边界

本轮包含静态可达性分析、脚本引用分析、桌面浏览器逐路由巡检、TypeScript、ESLint、单元测试、Smoke、Web RPC、应用构建、复杂度和生产依赖审计。浏览器使用隔离测试数据，没有读取或改写用户真实小说。

尚未证明的部分：真实模型生成质量、真人盲评、移动端全部视口、生产签名安装包、干净 clone，以及多章长时间真实写作。它们不能由代码通过或规则分数代替。
