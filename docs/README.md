# NovelForge 系统说明

## 1. 系统简介

NovelForge 是一个面向长篇小说创作的桌面端 AI 创作系统。它不是单纯的“让 AI 一次性写完全文”，而是把小说创作拆成可管理、可追踪、可复用的多个环节，让作者在统一工作台中完成立项、设定、资产建设、结构规划、正文写作、修订收口和质量监控。

当前系统基于 Electron 运行，必须通过桌面应用启动。直接在普通浏览器中打开前端页面时，系统会提示缺少 `window.electron` 桥接，无法正常使用。

系统当前覆盖的核心资产包括：

- 小说项目
- 卷、部、章等结构信息
- 角色、势力、地图、物品、设定词典、终局承诺
- 故事线程、人物弧线、反派阻力、章节大纲、时间轴事件、信息差事实
- 章节合同、场景合同、章节正文、版本历史、章后回写、修订任务
- 质量评分、语言漂移、召回风险、状态风险

## 2. 系统能做什么

NovelForge 适合以下使用场景：

- 从一个模糊想法快速建立完整小说项目
- 用 AI 辅助补齐背景、设定、角色、物品、线程和结构资产
- 用统一工作台持续推进长篇或连载写作
- 把正文写作拆成“场景计划 -> 初稿 -> 审校 -> 重写定稿”的流水线
- 通过修订中心和质量监控，持续发现并处理一致性、节奏、语言和召回问题
- 将成稿导出为 `TXT`、`Markdown`、`DOCX`、`EPUB`

系统的基本思路是：

- 先把小说底盘搭稳
- 再把可复用资产补全
- 然后规划结构、时间轴和章节推进
- 最后进入持续写作、修订和质量收口

## 3. 系统整体结构

### 3.1 全局入口

系统顶层提供以下全局入口：

- `小说列表`：创建、搜索、排序、继续编辑、删除、导出小说项目
- `模型管理`：维护 AI 模型配置，支持 OpenAI、Anthropic Claude、DeepSeek、阿里通义、百度文心，以及自定义 OpenAI 兼容接口
- `模板系统`：维护文风模板、世界观模板、步骤提示词模板
- `任务中心`：查看后台任务、流式任务和工作流任务的执行状态、摘要、失败信息与恢复入口
- `提示词管理`：查看和调试系统中的关键提示词模板

### 3.2 小说工作台

进入某本小说后，工作台主要分为四组能力。

#### 总览

- `创作总览`：查看当前进度、风险、阻塞项和推荐下一步
- `基础信息`：维护书名、简介、背景、目标字数和当前完成度

#### 底盘

- `项目立项`：明确读者承诺、卖点、禁区、项目边界
- `基础设定`：明确作品定位、核心钩子、主角起点、底层约束、语言边界和去 AI 腔规则
- `主题与文风`：固定主题、情绪核心、叙事视角、时态、风格规则、对白规则

#### 世界与资源

- `世界规则`：建立题材规则、时间制度、世界约束和创作边界
- `终局设计`：锁定最终冲突、主题答案、兑现承诺和最后一幕
- `地图结构`：组织地点层级、路线与地理承载关系
- `势力系统`：维护势力组织及其关系结构
- `角色系统`：维护主角、反派、配角、人际关系与角色定位
- `人物弧线`：维护角色弧、关系弧和阶段推进
- `反派与阻力`：维护人物反派、势力反派、环境阻力和制度阻力
- `物品装备`：维护关键道具、资源、装备和可回收线索
- `设定词典`：沉淀术语、阶位、材料、专有名词
- `场景模板`：沉淀高频场景的节拍与复用骨架

#### 推进与写作

- `故事线程`：管理主线、支线、伏笔线和回收计划
- `故事设计`：围绕故事目标、核心冲突、主线、支线、结局和节奏进行总体设计
- `故事大纲`：将设计落实到章节推进与关键转折
- `卷级设计`：定义每卷承诺、压力、高潮和卷末状态变化
- `结构规划`：拆卷、拆部、拆章、拆场景，稳定长篇节奏
- `时间轴`：维护事件顺序、因果链、时间锚点与人物参与
- `信息差谜题板`：维护谜题、线索、真相和视角已知信息
- `伏笔与回收账本`：维护伏笔埋设、回收状态和欠账情况
- `成长资源代价`：维护成长轨道、资源稀缺、奖励与代价
- `章节合同 / 场景合同`：把章节目标、推进约束和场景执行要求写成显式合同
- `正文写作`：围绕章节展开计划、生成、审校、定稿和历史版本管理
- `章后状态回写`：把正文中的事实、状态变化和推进结果统一写回资产总账
- `修订中心`：统一管理待处理的一致性问题、上下文同步任务和人工修订项
- `质量监控`：从章节热力图、语言与对白、结构推进、召回与状态等维度观察风险

## 4. 快速开始

### 4.1 启动系统

如果你是本地开发或本机使用者，可以使用以下命令启动系统：

```bash
npm install
npm run dev
```

常用说明：

- `npm run dev` 会启动 Electron 开发环境
- 系统应通过 Electron 窗口使用，而不是直接打开浏览器页面
- 若需要运行测试，可执行 `npm run test`

### 4.2 创建一部新小说

小说列表页提供新建向导，实际流程分为四步：

1. `题材与模板`
   选择题材，可选文风模板、世界模板、使用模型，并设置写作类型标签。
2. `原始背景`
   用自己的话输入故事背景、冲突、氛围或关键设定。
3. `AI 补全背景`
   系统会基于输入生成扩展背景、标题建议和简介，这一步内容可以继续编辑。
4. `最终确认`
   确认最终标题、最终简介和目标字数，然后创建小说。

创建完成后，系统会进入对应小说的工作台。

### 4.3 第一次进入工作台时建议先做什么

建议按下面顺序开始：

1. 先看 `创作总览`，确认当前项目的完成度和推荐下一步。
2. 补齐 `基础信息`，确保书名、简介、背景和目标字数完整。
3. 再进入 `项目立项`、`基础设定`、`主题与文风`，把写作底盘先固定住。
4. 底盘稳定后，先补 `世界规则` 与 `终局设计`，再补世界资产、角色资产和故事资产。

## 5. 推荐创作步骤

下面是最适合当前系统的一套使用顺序。它既符合系统的引导逻辑，也符合长篇创作的真实工作流。

1. `创作总览` / `基础信息`
   先看当前风险、推荐下一步，再补齐标题、简介、背景和目标字数。
2. `项目立项`
   锁定读者承诺、卖点、禁区和项目边界。
3. `基础设定`
   固定作品定位、主角起点、底层约束和语言护栏。
4. `主题与文风`
   固定主题、情绪核心、叙事视角、时态和对白规则。
5. `世界规则`
   搭好题材底层规则、时间制度和世界边界。
6. `终局设计`
   提前锁定最终冲突、主题答案、兑现承诺和最后一幕。
7. `地图结构`、`物品装备`、`角色系统`、`势力系统`
   把地点、资源、人物、组织补成稳定资产。
8. `人物弧线`、`反派与阻力`、`设定词典`、`场景模板`
   把变化轨迹、阻力来源、专有名词和高频场景骨架补齐。
9. `故事线程`、`故事设计`
   把主线、支线、伏笔线挂成可追踪推进，并统一设计整本书的主冲突与节奏。
10. `故事大纲`、`卷级设计`、`结构规划`、`时间轴`、`信息差谜题板`、`伏笔与回收账本`、`成长资源代价`
   把结构、因果、信息揭示、伏笔债务和成长循环全部挂到显式结构上。
11. `章节合同 / 场景合同`
   把章节目标、必须推进的线程、弧线、资产、钩子和场景要求写成显式合同。
12. `正文写作`
   围绕章节执行“计划 -> 草稿 -> 审校 -> 重写 / 定稿”的流水线。
13. `章后状态回写`
   把正文里的事实、状态变化和推进结果重新写回资产总账。
14. `修订中心`、`质量监控`
   持续清理一致性问题、追踪长期风险，避免长篇推进中后段失控。

### 建议穿插补充的模块

以下模块不一定非要集中一次做完，但建议在主流程中穿插维护：

- `势力系统`：当角色归属、阵营关系开始复杂时及时补
- `人物弧线 / 反派阻力`：当章节已经开始连续推进时，尽快把角色变化和外部压力挂到显式资产上
- `设定词典`：一旦出现稳定术语就及时登记
- `场景模板`：当某类桥段反复出现时沉淀模板
- `伏笔账本 / 信息差谜题板`：一旦出现长期欠账、谜题揭示或禁止提前透露的信息，就尽早登记
- `修订中心`：一旦发现问题就建任务，不要等忘了再找

## 6. 重点页面如何使用

### 6.1 创作总览

`创作总览` 是工作台的第一站。它的价值不是“展示信息”，而是告诉你现在应该做什么。

你可以在这里看到：

- 当前底盘是否完整
- 当前资产是否缺失
- 当前上下文是否过期
- 当前有哪些高优先问题或阻塞
- 系统建议的下一步动作

适合什么时候看：

- 新建项目刚进入工作台时
- 一段时间没打开项目时
- 写完若干章之后，准备回头补底盘或修订时

### 6.2 正文写作

`正文写作` 是系统里最核心的生产页面，围绕章节展开。

章节状态包括：

- `待写`
- `写作中`
- `草稿`
- `审校中`
- `已完成`

系统内置的章节流水线是：

1. `场景计划`
2. `正文初稿`
3. `自动审校`
4. `修订定稿`

写作页还分为四个子区：

- `编辑器`：查看和编辑正文
- `上下文`：查看当前章节上下文、记忆和约束注入情况
- `审校`：查看自动审校结果、关键修订建议、对白和节奏风险
- `历史`：查看章节历史版本并回溯修改

建议用法：

1. 先确认章节编号、目标和状态
2. 跑场景计划，确认每个场景要覆盖什么
3. 再生成初稿
4. 审校后先修高优先问题，再决定是否定稿
5. 若章节被上游设定变化影响，要及时关注待同步提示

### 6.3 修订中心

`修订中心` 用来收口那些“不是现在马上重写一章，但必须处理”的问题。

这里适合管理的内容包括：

- 连续性问题
- 时间线错误
- 人物设定冲突
- 地图或势力关系不一致
- 因前文变化导致的上下文同步任务
- 人工登记的修订清单

你可以在这里：

- 查看系统自动发现的问题
- 手动创建修订任务
- 给任务分优先级、状态和关联页面
- 直接跳转到相关页面处理问题

建议习惯：

- 发现问题先记任务，不要只靠记忆
- 高优先问题优先清理
- 章节已经推进较多时，修订中心应成为日常入口之一

### 6.4 质量监控

`质量监控` 是面向长期写作的风险仪表盘。它不是替代人工判断，而是帮助你更早发现“正在变坏”的地方。

当前主要分为四个标签：

- `总览`
- `语言与对白`
- `结构与推进`
- `召回与状态`

它重点关注的方向包括：

- 章节评分热力图
- 语言漂移和 AI 味退化
- 对白同质化、角色辨识度下降
- 主角受挫、代价兑现、节奏推进
- 故事弧推进异常
- 召回风险、状态风险、世界状态漂移

适合什么时候看：

- 连续写了几章之后
- 大改过底盘或结构之后
- 准备进入下一卷或下一阶段前

### 6.5 模型管理

如果你要切换或维护 AI 模型配置，就去 `模型管理`。

这里可以做的事：

- 新建模型配置
- 维护 provider、model id、base URL、API Key
- 调整 temperature、最大输出、最大上下文、最大并发
- 测试模型是否可用
- 设置默认模型

适合什么时候用：

- 首次接入模型时
- 需要分题材或分任务切换模型时
- 当前模型稳定性或成本不合适时

### 6.6 模板系统

`模板系统` 用于沉淀复用能力，而不是一次性输入。

当前模板类型包括：

- `文风模板`
- `世界观模板`
- `步骤提示词`

建议使用方式：

- 当某种文风经常复用时，做成文风模板
- 当某类世界底盘经常复用时，做成世界模板
- 当某类步骤提示词需要标准化时，沉淀为步骤模板

### 6.7 任务中心

`任务中心` 用于观察后台 AI 执行情况，尤其适合批量生成、长流程和失败排查。

你可以在这里：

- 按状态或类型筛选任务
- 查看任务摘要、输入输出和错误信息
- 查看流式执行过程
- 判断任务是否可重试、可恢复
- 跳转回原始业务页面继续处理

当你感觉“系统没反应”时，先看任务中心，通常比反复点击更有效。

### 6.8 提示词管理

`提示词管理` 适合需要审阅、复制、比对或调试提示词的场景。

当前系统中的提示词覆盖了多个关键生成环节，例如：

- 时间轴事件生成
- 章节拆场景
- 章节初稿
- 章节审校
- 人物重做

如果你要排查某个生成结果为什么总是偏掉，这一页很有价值。

## 7. 日常使用建议

### 7.1 新项目建议流程

建议按下面节奏推进一部新书：

1. 创建项目并补完基础背景
2. 做完项目立项、基础设定、主题与文风
3. 生成并整理世界规则、地图、物品、角色
4. 补故事线程与场景模板
5. 完成故事设计、结构规划、时间轴、大纲
6. 进入正文写作
7. 每写若干章就处理修订中心和质量监控中的问题

### 7.2 连载或长篇日常迭代流程

如果项目已经开始写正文，建议按这个节奏日常推进：

1. 打开 `创作总览` 看风险和推荐下一步
2. 去 `正文写作` 推进当前章节
3. 检查 `修订中心` 是否积压高优先问题
4. 定期看 `质量监控`，避免语言、节奏和召回持续劣化
5. 若资产发生变化，及时回补角色、线程、时间轴和词典

## 8. 导出、测试与构建

### 8.1 小说导出

小说列表页支持以下导出格式：

- `TXT`
- `Markdown`
- `DOCX`
- `EPUB`

适合场景：

- `TXT`：纯文本交付或进一步手工处理

- `DOCX`：交付编辑、审稿或排版前处理
- `EPUB`：电子阅读器或移动端预览

## 9. 使用注意事项

- 系统必须通过 Electron 桌面应用启动，直接打开浏览器页面不能正常工作。
- AI 生成结果需要人工复核，尤其是设定、时间轴、伏笔回收、结局和大纲层内容。
- 一旦修改底盘信息，后续章节和资产可能需要同步更新，应及时关注修订中心和待同步提示。
- 不要把角色、物品、线程只当展示资料。它们真正的价值在于约束后续写作、承接冲突和回收伏笔。
- 长篇项目应定期查看质量监控，而不是只在出问题后回头排查。

## 10. 一句话总结

NovelForge 的最佳使用方式不是“让 AI 自己写”，而是“让 AI 在你定义好的底盘、资产、结构和规则中稳定协作”。  
底盘越稳、资产越清、流程越完整，最终正文越容易写出连续性、风格和节奏都更稳定的长篇作品。
