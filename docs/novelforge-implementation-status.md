# NovelForge 长篇能力实施状态

更新时间：2026-08-05

状态含义：

- `已完成`：代码、测试和必要的运行证据均具备；
- `进行中`：已有代码基础，但仍缺关键闭环或验证；
- `待实现`：设计已确定，尚未进入代码；
- `待真实验证`：静态检查通过，但需要真实模型、数据库或长篇运行证据。

## 当前基线

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 分阶段创作窗口 | 已完成 | `creative_stages` 与阶段资产已有代码和测试 |
| 阶段 handoff | 进行中 | 有草稿和确定性回退，尚缺完整审批后的正典提交 |
| 章节/场景合同 | 已完成 | 已接入章节流水线，仍需 100 章质量验证 |
| 上下文预算分配 | 进行中 | 有硬/软预算，但原始数据仍存在全量读取 |
| 章节摘要/连续性召回 | 进行中 | 有召回链路，覆盖面和增量性不足 |
| 本地向量检索 | 进行中 | 有本地 embedding 和关键词回退，暂无 ANN 与 profile 隔离 |
| 角色状态版本 | 进行中 | 有历史表和投影，角色追踪范围与知识边界不足 |
| 世界/地图状态 | 进行中 | 有地图树、关系和状态表，缺旅行约束 |
| 章后 Canon Diff | 进行中 | 有候选差异与审批入口，尚未统一事件账本 |
| Pipeline checkpoint | 进行中 | 能识别部分恢复点，尚无不可变节点快照与租约 |
| Worker/后台投影 | 待实现 | 当前尚未形成持久化 outbox 与写入器边界 |
| 100/300/500 章连续性验证 | 待真实验证 | 当前仅有较小规模运行记录 |

## 本轮实施顺序

1. 设计文档和数据契约；
2. 正典事件/状态提交层；
3. 节点 artifact、租约和精确重试；
4. 增量上下文与混合检索；
5. Worker、outbox、人物知识和地图旅行约束；
6. UI Diff、智能侧栏、时间轴和深色专注模式；
7. 运行 20/50/100/300 章验证并逐项更新本表。

## 禁止提前宣称完成的事项

- `pipelineStatus=complete` 不等于章节质量通过；
- typecheck/build 不等于真实模型和读者质量通过；
- 向量召回命中不等于事实正确；
- checkpoint 存在不等于可以从精确失败节点恢复；
- SQLite 能保存文本不等于全量扫描性能可接受。
