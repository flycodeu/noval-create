## 一、当前架构概述

### 1.1 三阶段上下文组装

```
Stage 1: Base Assembly     → 收集所有候选上下文片段
Stage 2: Recall Injection  → 向量检索追加相关历史片段
Stage 3: Budget Allocation → 按优先级分配 token 预算
```

### 1.3 Token 估算机制

```
中文字符: 1.0 token/char
英文字符: 0.25 token/char
标点符号: 0.5 token/char
安全裕度: +10%
截断估算: 0.6 token/char (保守)
```

## 二、已识别的问题

### 2.1 硬约束溢出（P0）

**问题描述**：`HardConstraintOverflowError` 表明硬约束可能超出预算。

**发生场景**：
- 世界观复杂（100+ 条规则）
- 角色众多（20+ 角色状态）
- 伏笔密集（10+ 到期伏笔）
- 以上同时出现时，仅硬约束就可能占据 50%+ token 预算

**影响**：
- 部分硬约束被丢弃 → 生成内容违反已有设定
- 用户不知道哪些约束被丢弃了

**建议**：
1. 硬约束溢出时，显示**被丢弃约束列表**，让用户选择保留哪些
2. 增加硬约束**压缩模式**——当溢出时，自动将长约束压缩为短摘要
3. 按约束的"最近相关性"排序——与本章场景/角色直接相关的约束优先

### 2.2 摘要质量衰减（P0）

**问题描述**：previousSummaries 存储前 3-5 章的摘要。但 100+ 章后，早期摘要被丢弃，中期摘要被二次压缩，信息损失严重。

**具体表现**：
- 第 1-5 章的关键伏笔细节可能在第 50 章时完全丢失
- longTermMemory 检查点理论上解决此问题，但检查点本身也有容量限制
- 没有监控摘要信息密度是否下降

**建议**：
1. 增加**摘要信息密度评分**——检查摘要是否还保留了关键实体和事件
2. 当密度评分低于阈值时，触发**智能重压缩**——回到原文重新提取关键信息
3. 对"高价值信息"（伏笔、角色状态变化、重大事件）做**独立持久化**，不受摘要窗口限制

### 2.3 向量召回质量不可控（P1）

**问题描述**：embedding.service 的向量检索质量取决于 embedding 模型。

**风险**：
- 小模型 embedding 可能无法正确理解中文修仙/武侠领域术语
- 召回的"相似场景"可能只是表面词汇相似，实际语境不同
- 召回噪声会占用宝贵的 token 预算

**建议**：
1. 召回结果增加**相关性阈值**——相似度低于 0.6 的片段直接丢弃
2. 召回后做**轻量级验证**——检查召回片段是否包含当前章节涉及的角色/地点
3. 在质量日志中记录每次召回的命中率，供用户调整

### 2.4 上下文同步延迟（P1）

**问题描述**：contextStatus 追踪 staleChapterCount 和 staleCheckpointCount，但同步机制可能存在延迟。

**具体风险**：
- 批量生成时，第 N+1 章可能在第 N 章回写完成前就开始生成
- 回写失败后没有自动重试机制
- 用户不知道某次回写是否成功

**建议**：
1. 回写操作增加**乐观锁**——检查目标记录版本号是否与回写前一致
2. 回写失败自动重试 3 次，仍失败则**阻塞后续生成**
3. 在 Studio Dashboard 显示上一次回写的结果（成功/失败/待重试）

### 2.5 上下文窗口动态调整的盲区（P2）

**问题描述**：`resolveRecentContextWindow()` 根据小说规模在 8-40 章之间调整窗口大小。

**潜在问题**：
- 窗口大小只看章节数量，不看章节内容复杂度
- 一个 3000 字的过渡章和一个 8000 字的高潮章占用相同窗口位
- 某些早期章节对当前章极其重要（如第一章的世界观建立），但可能已滑出窗口

**建议**：
1. 窗口大小同时考虑**章节重要性标签**——标记为"关键章"的章节不从窗口滑出
2. 或者维护一个"永久章节摘要列表"——收集每个被标记为重要的章节的核心信息

## 三、长篇小说（50万字+）特有的上下文挑战

### 3.1 角色状态爆炸

- 20 个角色 × 每人 5 个状态变量 = 100 个状态需要追踪
- 不是所有角色都出现在每一章，但状态需要正确
- **建议**：只注入本章涉及角色的状态，非涉及角色的状态放入压缩摘要

### 3.2 伏笔回收追踪的 token 成本

- 100 章后可能有 30+ 未回收伏笔
- 每个伏笔描述 50-100 字
- 总计 1500-3000 字 = 约 1500-3000 token
- **建议**：按照与当前章节的相关性排序，只注入前 10 个最相关的伏笔，其余放入"远期伏笔"摘要

### 3.3 世界观规则膨胀

- 修仙小说的功法体系可能有 50+ 条规则
- 不是每条规则都与每章相关
- **建议**：世界观规则做**场景标签化**——每条规则标注适用场景（战斗/修炼/社交），只注入当前场景相关的规则
