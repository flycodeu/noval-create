# P0 - 批量生成仅拆批未持久化断点（长任务中断后无法可靠续跑）

> 优先级：P0（致命）
> 影响范围：批量生产稳定性、长任务可恢复性
> 实现难度：中高

## 问题

当前系统已经具备“拆批生成”的意识，但大多数批量链路仍只是把一次大请求拆成多个小请求，在同一个服务函数内 `for/while` 循环调用模型。  

这解决了“一次生成几十个对象会炸 prompt”的问题，但没有解决“任务中断后如何继续”的问题。对于百万字项目，人物、物品、支线、线程、时间轴都可能出现一次需要生成几十个条目的真实场景。如果执行到第 4 批时失败，当前系统往往只能重新发起，或者依赖已经落库的一部分结果继续人工补洞，缺少稳定的 batch checkpoint、resume 和前批摘要回灌机制。

具体失败模式：

- 生成 30 个角色，跑到第 5 批失败，无法从第 5 批继续
- 生成一半后关闭窗口、重启应用，任务中心无法恢复大多数批量链路
- 下一批 prompt 虽然能看到已落库结果，但没有严格持久化“上一批核心摘要”和“批次进度游标”
- 出现重复、漏生成、批次间风格漂移时，只能依赖后验去重，不能可靠回到断点修补

## 原因

- `character.service.ts` 使用 `while (newIds.length < totalCount ...)` 进行批量人物生成
- `item.service.ts` 使用 `for (generatedCount += batchSize)` 循环生成物品
- `timeline.service.ts` 使用 `for (generatedCount += batchSize)` 循环生成时间轴
- `story-thread.service.ts` 使用 `for (offset += batchSize)` 循环生成故事线程
- `core-settings.service.ts` 的支线生成也按批次循环推进
- 这些链路虽然都有拆批、去重、失败警告，但大多没有统一的持久化 batch state
- 对照之下，`workflow-task.service.ts` 中只有 `map_auto_generate`、`world_rules_auto_generate` 这类 `runnerType: 'workflow'` 任务支持 `resumeWorkflowTask()`

## 为什么前三轮修复后仍然可能发生

前三轮已经修掉了并发控制、任务竞态、流式可靠性等问题，但这些修复主要解决的是“请求别乱、状态别错、输出别丢”。  

第五轮暴露的是另一层问题：**批量生成的状态机还没有全面工程化。** 也就是说，系统已经从“全量一次性生成”进化到“可拆批”，但还没有进化到“可恢复批处理工作流”。

## 解决方式

1. 为人物、物品、线程、时间轴、支线等批量链路统一引入 `workflow` 型任务，而不是只在服务函数里循环
2. 持久化每个批量任务的进度状态：
   - 当前批次序号
   - 已接受结果 ID
   - 被拒绝摘要或签名
   - 下一批需要携带的最小上下文卡
3. 让任务中心的“继续执行”覆盖所有批量链路，而不是只覆盖地图/世界规则
4. 每一批执行完后，回写一份紧凑的“前批摘要卡”，供下一批使用，避免只依赖数据库全量重新拼 prompt
5. 为批量工作流增加幂等策略：
   - 同一批次重复执行不重复落库
   - 已通过的结果不被下一次恢复覆盖

## 是否解决

已解决 — 2026-04-05

当前状态：已闭环

- 新增 `character_auto_generate`、`item_auto_generate`、`timeline_auto_generate`、`story_thread_auto_generate`、`subplot_auto_generate` 五类可恢复 workflow
- 批量任务统一持久化 `progressJson/controlJson/currentChildTaskId`，记录批次进度、已接受结果、warnings、resumeCursor 与 batchDigest
- `resumeWorkflowTask()` 已覆盖上述 5 类 workflow，应用重启后仍可从任务中心继续执行
- 人物、物品、时间轴、故事线程旧入口保留兼容壳，但实际执行已收敛到 workflow
- 核心设定页的“重排支线”已切到 `subplot` workflow，不再走不可恢复的页面内整批循环
- 任务中心与工作区的“继续后台流程”已覆盖全部 5 类批量任务

## 预期效果

- 一次生成几十个资产时，失败后可以从断点继续，而不是整批重来
- 拆批任务之间能稳定继承上一批核心结果，不会在长任务里逐批失忆
- 任务中心真正成为批量生产中枢，而不是只展示部分长任务状态
