# 修订中心与质量闭环

## 问题
- 质量问题、系统任务、自动修复和页面内修补之间仍然存在跳转成本。
- 一些风险分类在不同页面里的叫法不够统一。

## 原因
- 质量看板、修订中心、正文页、总控台分别承担了不同环节，但没有统一呈现层。
- 修复动作部分在页面内，部分在修订中心，用户容易来回找。

## 解决措施
- 修订中心接入步骤指引，并把系统诊断、人工任务、AI 修复放到同一张任务板里处理。
- 质量看板接入步骤指引，统一“阻塞 / 高优先 / 中优先 / 低优先”显示口径。
- Writing、Outline、QualityDashboard、RevisionCenter、TaskCenter 的旧“高风险 / 提醒 / 信息”文案统一替换为新的优先级表达。
- TaskCenter 和 PromptManager 的双栏页补上独立滚动，避免继续出现“看左边丢右边”的工作台问题。
- 全局警告消息同步改成“修补提示”，让质量问题、修订问题和普通说明不再共用“提醒”。

- 是否解决：是
