# 故事弧推进检测章节化与卷级推进曲线扩展

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

当前故事弧推进检测已经能提示“本章推进不足”，但这仍然是章节级视角。百万字小说真正需要的是卷级和全书级推进曲线，而不是只看单章有没有推进。

## 2. 当前代码现状

- `electron/services/chapter.service.ts` 已有 `arc_progress_risks`。
- 同文件已实现弧推进 checkpoint warning。
- `electron/services/context.service.ts` 会将当前弧和弧摘要注入 prompt。
- `electron/services/story-memory.service.ts` 已有 `arcSignals`。
- 当前没有卷级推进面板和弧线增长曲线。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：系统已经知道要检测故事弧推进。
- 部分解决：已有单章推进风险和 checkpoint 警告。
- 未解决：卷级与全书级推进节奏无法量化。

当前判断：`部分解决`

## 4. 潜在风险

- 章节看似都在写主线，但整卷实际没有实质增长。
- 中后期容易出现多章空转、重复铺垫。
- 关键检查点前后没有真正兑现阶段目标。

## 5. 原因分析

- 当前弧线检查是“本章有没有推进”，不是“这段时期推进得好不好”。
- 缺少阶段目标、卷级目标和空转率统计。
- 缺少对“推进质量”的衡量，只能看是否提到了推进。

## 6. 扩展方案

- 按卷和阶段为故事弧建立目标节点。
- 统计每卷每弧的推进率、空转率、兑现率。
- 对关键弧引入“25% / 50% / 75% / 收束”阶段目标与验收条件。
- 质量页新增“故事弧推进曲线”和“连续空转章节”告警。

## 7. 建议的数据结构 / 指标 / 页面能力

- `arcPhaseTargets`
- `arcProgressCurve`
- `stalledArcChapterCount`
- `arcPayoffRate`
- 页面新增“卷级故事弧看板”

## 8. 实施优先级

等级：`S级`

等级说明：主线推进是否空转是中后期最容易失控的问题之一。

原因：长篇读感中最容易被读者察觉的就是“主线有没有真的在动”。

## 9. 验收标准

- 每条主要故事弧都有卷级推进曲线。
- 连续空转章节可被自动识别。
- 检查点前后的兑现质量可视化。
- 长篇中段的主线停滞问题能被提前暴露。
