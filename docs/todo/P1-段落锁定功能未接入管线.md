# P1 - 段落锁定功能未接入生成管线

> 优先级：P1（严重）
> 影响范围：用户手动润色被覆盖
> 实现难度：低
> 类别：后端-写作管线

---

## 问题

数据库已有 `lockedParagraphsJson` 字段，重写prompt已提及"【锁定】或 [LOCKED] 标记"保护，但**实际代码中没有将锁定段落数据传递给重写prompt**。`buildChapterRewritePrompt()` 从未接收 `lockedParagraphsJson` 字段，导致AI重写时覆盖用户手动编辑的段落。

## 原因

- `chapter.service.ts` 中调用 `buildChapterRewritePrompt()` 时未传入 `lockedParagraphsJson`
- Schema定义和prompt指令存在，但中间的数据传递链路断裂
- 缺少集成测试验证端到端锁定功能

## 解决方式

1. **补全数据传递链路**：在 `buildChapterRewritePrompt()` 调用处读取 `lockedParagraphsJson`，将锁定段落标记注入到内容中
2. **在重写前预处理**：将锁定段落用 `【锁定】` 标记包裹后传入prompt
3. **重写后验证**：对比重写前后的锁定段落内容，如有改动则回退
4. **添加集成测试**：验证锁定段落在完整生成管线中不被修改

## 是否解决

已解决

## 预期效果

- 用户标记为锁定的段落在重写/重生成时100%保留
- 人工润色成果不再丢失
- 增强人机协作信任度
