# 反 AI 味前置抑制器

## 一、目标

把“生成后发现 AI 味”改成“生成前主动压制 AI 味”。系统需要把高频 AI 套话、模板句式、结构套路和本书复现问题转成下一章的硬约束，并把命中情况沉淀成可追踪的跨章数据。

## 二、当前已完成

- `content-guardrails.ts` 已补齐可导出的 prompt 级 anti-AI 规则目录，覆盖禁用表达、禁用句式、结构套路和正向替代表达。
- `anti-ai-rule.service.ts` 已完成 anti-AI 命中采集、语言漂移派生规则、跨章复现统计、连续两章升级和 5 章窗口高风险预警。
- `context.service.ts` 已把反 AI 味规则注入 `hardConstraintContext`，Writer / Draft / Review / Rewrite 共用同一组前置硬约束。
- `chapter.service.ts` 已在生成完成后把 guardrail 命中和 language drift 命中写入 `anti_ai_rule_hits`，并保留原有 `anti_ai_failed` 强制修复兜底。
- `quality-dashboard.service.ts` 与 `QualityDashboard` 已展示 anti-AI 复现章节数、升级规则、高风险告警、卷级复现摘要和章节命中详情。
- `revision_tasks` 已复用现有 system task 机制，对 5 章内出现 3 次的高风险规则发出修订任务信号。

## 三、已落地闭环

### 3.1 生成前注入

当前 `hardConstraintContext` 已稳定注入以下结构：

- `【必须避免-禁用表达】`
- `【必须避免-禁用句式】`
- `【必须避免-结构套路】`
- `【正向替代表达】`

其中同时包含：

- 全局 anti-AI 规则。
- 题材专属 anti-AI 规则。
- 本书 `antiAiFlavor / bannedTerms` 自定义规则。
- 连续 2 章复现后自动升级的动态规则。

### 3.2 命中沉淀

`anti_ai_rule_hits` 已作为独立表落地，记录：

- `novelId / chapterId / chapterNum`
- `ruleCode / ruleTitle / scope / severity`
- `excerpt / source / detail`
- `promotedToHardConstraint`
- `createdAt / updatedAt`

### 3.3 动态升级

- 单章命中继续保留原有生成后修复。
- 连续 2 章同类问题会自动升级为下一章硬约束。
- 5 章内同类问题出现 3 次会进入高风险告警，并同步 system revision task。
- 仪表盘会显示高频问题、升级规则、近期告警和卷级复现摘要。

## 四、验收结果

- 已能在生成 prompt 的硬约束区看到动态 anti-AI 约束。
- 已能把同类问题连续 2 章命中后自动升为下一章禁写项。
- 已完成独立持久化表，不再依赖 `reviewNotesJson` 临时回填。
- 已在质量仪表盘展示跨章复现率、升级规则和近期高风险告警。
