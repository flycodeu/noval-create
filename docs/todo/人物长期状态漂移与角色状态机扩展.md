# 人物长期状态漂移与角色状态机扩展

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

当前系统会记录人物变化，但更多是章节级连续性摘要。对于百万字项目，人物的伤势、立场、欲望、资源、关系温度、认知变化如果没有状态机，会逐渐出现漂移。

## 2. 当前代码现状

- `electron/services/chapter.service.ts` 会更新 `continuityStateJson`。
- `electron/services/story-memory.service.ts` 会汇总 `characterLedger`。
- `electron/services/context.service.ts` 会构建 `characterStates` 并注入 prompt。
- `electron/database/schema.ts` 与 `electron/database/db.ts` 已新增 `character_state_versions` 表，用于记录角色结构化状态版本。
- `electron/services/character-state.service.ts` 已开始按章节写入主要角色的 `injury/resource/stance/mental/relationship/goal` 状态快照，并生成轻量漂移告警。
- `src/pages/Novel/Writing/index.tsx` 的长文记忆区已新增“角色当前状态”卡片，展示最新状态与近期跳变告警。
- 当前仍是角色层状态机 v1，尚未扩到势力、物品和世界总账。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：项目已经记录人物变化，并会写入上下文。
- 部分解决：角色结构化状态版本、写前注入和写作页展示已经补上，但漂移检测仍以规则判断为主，历史回溯和更细状态分类还不够完整。
- 未解决：角色状态还没有扩展到更高阶的人物弧路线、势力/物品联动和更强的回滚校验。

当前判断：`部分解决`

## 4. 潜在风险

- 角色前一卷受过的伤，后一卷像不存在。
- 角色立场和关系温度忽高忽低，没有过程。
- 角色成长常被写成总结句，而不是事件推动后的阶段变化。

## 5. 原因分析

- 当前系统更重“章节结果摘要”，不重“角色当前状态”。
- 人物状态散落在连续性、关系、审校和正文描述中。
- 缺少角色弧路线与状态版本管理。

## 6. 扩展方案

- 已为主要角色建立长期状态机 v1。
- 已按章节记录角色的伤势、目标、资源、关系、心理、立场变化。
- 已开始记录“因什么事件发生了什么改变”，并把 `eventCause / changeReason` 写入版本表。
- 已将状态机接入写前约束和写作页记忆展示；卷级统计和更强校验仍待继续补齐。

## 7. 建议的数据结构 / 指标 / 页面能力

- `characterArcLedger`
- `characterStateVersion`
- `injuryState`、`resourceState`、`stanceState`、`mentalState`
- `characterArcProgress`
- 页面已新增“角色当前状态卡”，下一步补“角色近期关键变化”与更强的卷级统计

## 8. 实施优先级

等级：`S级`

等级说明：人物稳定性直接决定长篇读感，也是对白、关系和代价体系的基础。

原因：人物长期稳定性是百万字小说最直观的阅读体验问题之一。

## 9. 验收标准

- 主要角色已具备可查询的当前状态。
- 状态变化已能回溯到章节事件摘要与 `changeReason`。
- 章节生成前已优先注入角色当前状态，而非只注入摘要拼接。
- 人物伤势、关系、立场跨章节错写率的持续下降，还需要在更多章节样本上继续验证。
