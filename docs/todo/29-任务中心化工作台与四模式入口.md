# 任务中心化工作台与四模式入口

## 一、目标

把当前偏“页面导航”的小说工作台，改成偏“作者任务推进”的工作台。系统不只展示有哪些模块，而要优先回答四个问题：

- 我今天该先做什么。
- 哪一步最影响下一章产出。
- 当前有哪些阻塞项。
- 改了设定以后会影响哪些地方。

## 二、为什么现在要做

当前系统的模块能力已经很强，但作者进入工作台后仍需要自己在导航里做路径规划。对长篇作者来说，这会带来两个问题：

- 能力很多，但第一次进入时不容易判断最值钱的下一步。
- 后期项目跨页面跳转频繁，阻塞项和恢复入口分散。

因此，这一层不是在替代现有页面，而是在已有页面之上提供更强的任务化编排。

## 三、当前已覆盖基础

- 现有 `创作总览` 已能展示风险、阻塞和推荐下一步。
- 现有 `任务中心` 已能展示后台工作流状态、失败信息和恢复入口。
- `14-百万字总控与卷批次规划` 已具备“可继续推进 / 需处理问题”的继续提示。
- `修订中心`、`质量监控`、`正文写作` 已经能承担不同阶段的高频动作入口。

## 四、边界重写

- `29` 不新增独立的“作者任务中心”页面。
- `29` 只负责在 `创作向导 + 创作总览` 上方增加任务化工作流层。
- 全局 `/tasks` 保持为“后台任务中心”，只承接批处理状态、失败排查和恢复动作。
- `30-创作总览行动化与零状态引导` 负责把 `创作总览` 进一步重做为更强的行动页和零状态页。
- `32-资产变更影响分析与写作闭环自动化` 负责更深的自动影响分析、待同步任务生成和闭环自动化，不在本项内一次做完。

## 六、详细设计

### 5.1 入口分层

保留现有全局 `任务中心`，但命名口径明确为“后台任务中心”。

不新增独立小说内页，而是在已有页面上加一层“作者工作流”：

- `创作向导` 承担完整模式切换、主任务、备选任务、阻塞项、影响提示。
- `创作总览` 承担轻量只读摘要，保证用户在总览页也能知道当前最该做什么。

### 5.2 四种工作模式

| 模式 | 目标 | 典型场景 |
| --- | --- | --- |
| 快速启动模式 | 15-30 分钟内进入可写的第一章 | 新项目、灵感落地 |
| 资产建设模式 | 补底盘、角色、世界与结构资产 | 开书前中段、补资产 |
| 日更推进模式 | 今天推进一章、一场景或一批章节 | 连载期、稳定更新 |
| 修订收口模式 | 清理高优先修订和系统性风险 | 中后期、卷末、发布前 |

### 5.3 主任务卡

每次只展示 1 个主任务：

- 标题
- 预计耗时
- 完成后解锁的能力
- 推荐原因
- 直接动作入口

同时提供 2 个备选任务，避免用户卡死在唯一入口。

### 5.4 阻塞项与风险影响

阻塞项卡聚焦“为什么现在不建议继续下一步”，风险影响卡聚焦“这个变更会波及什么”，与 `32-资产变更影响分析与写作闭环自动化` 联动。

## 七、当前实现情况

- 已落地共享 `author-workflow.ts`，负责模式判定、主任务、备选任务、阻塞项和影响提示生成。
- 已落地 `author-work-mode.store.ts`，支持系统推荐与手动模式切换并持久化。
- `创作向导` 已成为四模式主入口。
- `创作总览` 已接入同一套主任务摘要，避免再次做第二套推荐器。
- 全局 `/tasks` 未被改成创作页，仍保持后台任务职责。
- `创作向导` 已补上阶段折叠、阶段完成率和“可写下一章 / 先清 blocker / 待同步”强状态。
- `任务中心` 的空状态、详情状态和恢复入口文案已改为动作化提示，不再空转。

## 八、验收标准

- 作者进入工作台后，3 秒内能看到一个明确主任务。
- 同时存在后台执行任务和业务任务时，用户不会混淆两个入口的职责。
- 每个模式都能映射到一组稳定的主动作，而不是简单换皮导航。
- 阻塞项能够指向可处理页面或直接动作。

## 九、风险与建议

- 不要让“任务中心化”退化成再造一层大导航。
- 四模式数量要固定，避免随版本膨胀。
- 主任务卡必须有推荐理由，否则用户仍会回到凭感觉点页面。
