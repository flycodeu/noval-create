# P1 - 剧情逻辑与因果链断裂

> 优先级：P1（严重）
> 影响范围：故事完整性
> 实现难度：高

---

## 问题

百万字小说的核心挑战是维持**全局因果链**的完整性。当前系统的 `openLoops`（未关闭的剧情线）和 `storyThreads`（故事线追踪）在长篇中会爆炸性增长，导致：大量支线被遗忘永不收束、因果关系跨度过大时断裂、情节发展与前文矛盾。

## 原因

- `storyThreads` 表有 `targetPayoffChapter` 字段但缺少**主动提醒机制**——临近收束期的线索不会被自动注入上下文
- `openLoops` 在连续性状态中只是文本列表，无结构化管理，容易在摘要压缩时丢失
- 缺少**因果图**：事件A导致事件B的因果链没有显式建模，仅靠AI在文本层面维持
- 没有**全局剧情仪表盘**：作者和系统都无法一目了然地看到哪些线索已收束、哪些悬空
- 记忆检查点的 `resolvedThreadsJson` 和 `activeThreadsJson` 粒度不够，无法表达线索间的依赖关系

## 解决方式

1. **剧情线生命周期管理**：
   - 为每条线索添加状态机：`planted → developing → climax → resolved`
   - 在 `targetPayoffChapter` 前N章自动注入提醒到上下文
   - 超过deadline仍未收束的线索触发警告
2. **因果关系图**：建立 `plot_causality` 表，记录事件→事件的因果边，生成时参考因果链前驱
3. **线索密度控制**：限制每个章节段落的活跃线索数量（建议3-5条），避免信息过载
4. **剧情一致性验证器**：每N章运行一次全局一致性检查，比对所有活跃线索与实际章节内容
5. **支线自动衰减**：长期未提及的低优先级支线自动标记为可丢弃，释放上下文空间

## 是否解决

已解决 — 2026-04-04

已实施以下修复：
1. 伏笔追踪字段（`plantedChapter`、`lastReferencedChapter`、`reminderInterval`）已添加到 `storyThreads`
2. `buildActiveThreadsContext()` 自动识别超过提醒间隔未引用的线索并标注 `[已N章未提及，需适当回顾]`
3. 即将到期线索标注 `[即将回收第X章]`，活跃线索显示上限从 6→10
4. 场景计划prompt增加线索密度控制指令：每章活跃支线不超过 3-5 条
5. 审校prompt增加因果链检查：检查事件触发原因、角色行为一致性、伏笔推进情况
6. 审校 `missing_payoffs` 增加对标注线索的专项检查

## 预期效果

- 所有伏笔在合理时机收束，无悬空线索
- 因果链跨越百章仍保持逻辑严密
- 作者可在仪表盘查看剧情线全貌
