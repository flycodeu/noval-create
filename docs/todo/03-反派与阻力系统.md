# 反派与阻力系统

## 一、目标

把“主角的对立面”从静态人设，扩成可持续升级的阻力网络，覆盖人物反派、势力反派、环境阻力和制度阻力。

## 二、当前已完成

- [x] `characters.roleType` 已支持 `antagonist`。
- [x] `factions` 表已支持目标、资源、外部关系与阶段状态。
- [x] `story_threads` 支持 `main / subplot / mystery / payoff / relationship`，可承载冲突线。
- [x] `timeline_events` 可记录阶段事件与因果。

## 三、当前未完成

- [ ] 没有独立的 `反派与阻力系统` 页面。
- [ ] 没有“反派目标 / 情报来源 / 升级策略 / 阶段胜利 / 失败后反制”的结构化模型。
- [ ] 没有把环境阻力、制度阻力纳入统一阻力面板。
- [ ] 没有“反派对主角认知变化”追踪。
- [ ] 没有章节级“本章阻力应如何出手”的约束。

## 四、为什么现在要补

- 长篇最容易出现“主角一直在推进，但阻力没有升级”。
- 反派缺少阶段性胜利和反制路径时，冲突会越来越虚。

## 五、建议新增内容

- 新增页面：`反派与阻力系统`
- 统一管理四类阻力：
  - `人物反派`
  - `势力反派`
  - `环境阻力`
  - `制度阻力`
- 核心字段：
  - `目标`
  - `资源`
  - `情报来源`
  - `升级策略`
  - `对主角认知变化`
  - `阶段性胜利点`
  - `失败后反制`

## 六、页面与交互

- 允许从角色、势力、线程、时间轴四处跳入。
- 提供“当前主要阻力是谁 / 当前出手方式 / 最近一次胜利点 / 下一次升级点”总览。
- 支持把阻力节点直接挂到卷级设计和章节合同。

## 七、数据结构 / 状态字段

- 建议新增：
  - `resistance_tracks`
  - `resistance_beats`
- v1 最少字段：
  - `sourceType`
  - `sourceId`
  - `resistanceKind`
  - `goal`
  - `intelSource`
  - `resourcePool`
  - `escalationPlan`
  - `heroKnowledgeShift`
  - `stageVictory`
  - `counterMove`

## 八、与现有模块的关系

- `人物弧线中心` 关心角色变化。
- `反派与阻力系统` 关心阻力如何施压。
- `故事线程` 负责冲突线推进。
- `时间轴` 负责让阻力动作落到事件上。

## 九、验收标准

- 能独立查看主阻力来源与阶段升级路径。
- 至少支持一条人物反派线和一条势力阻力线。
- 阻力节点能被卷级设计与章节合同引用。
- 写作后能回写“阻力是否真的出手 / 是否取得阶段胜利”。
