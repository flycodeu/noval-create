# P2 - 批量生成无并发控制

> 优先级：P2（中等）
> 影响范围：批量操作触发API限流失败
> 实现难度：中
> 类别：后端-任务队列

---

## 问题

`createTask()` 不限制并发API请求数量。用户同时生成20个角色时，20个并行请求发送到AI模型，触发API速率限制（429错误），后续请求批量失败。无排队机制、无并发上限、无退避策略。

## 原因

- `task.service.ts:203-215` 的 `createTask()` 无并发控制
- 缺少全局请求队列
- 无API速率限制感知
- 批量角色/时间线/物品生成均存在此问题

## 解决方式

1. **实现模型级任务队列**：`task.service.ts` 现已按模型配置做排队，同一模型达到并发上限后进入等待队列
2. **速率限制感知**：检测 429 / rate limit / quota exceeded 等错误，chat 任务自动退避重试，stream 任务在首包前失败时允许重试
3. **排队任务可取消、重启可恢复**：等待中的任务支持直接取消，应用重启后遗留的 pending/running 任务会自动收尾
4. **用户可配置并发数**：`model_configs.max_concurrency` 与模型管理页已接通，用户可按自己的 API 配额调整模型并发上限

## 是否解决

已解决

## 预期效果

- 批量生成20个角色不再因限流而批量失败
- API调用有序执行，充分利用配额
- 用户可根据自己的API限额优化吞吐
