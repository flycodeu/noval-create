# P3 - 缺乏人机协作编辑流程

> 优先级：P3（改进项）
> 影响范围：创作体验
> 实现难度：高

---

## 问题

当前系统的生成流程是"AI全自动生成→人工审核"的单向流程。百万字小说创作需要更紧密的人机协作：作者需要能在任意节点介入修改、指导AI调整方向、锁定满意的段落防止被覆盖。缺少人类作者的深度参与是AI小说"不像人写的"的根本原因之一。

## 原因

- 章节生成是原子操作（4阶段一口气完成），中间无法插入人工干预
- `planning-draft.service.ts` 的草稿系统仅用于规划阶段，不支持章节级别的人机交互
- 缺少**段落级锁定**：作者修改的段落可能在下次重生成时被覆盖
- 没有**意图标注**系统：作者无法在大纲中标注"这里要悲伤"、"这个角色要犹豫"等微观指导
- 缺少**对比预览**：无法同时查看AI版本和手动修改版本的差异

## 解决方式

1. **分段生成与确认**：
   - 将章节生成拆分为场景粒度，每个场景可单独生成、预览、修改
   - 作者确认一个场景后再生成下一个
2. **段落锁定机制**：
   - 作者手动编辑过的段落标记为 `locked`
   - 重生成时保留锁定段落，只重写未锁定部分
3. **意图标注系统**：
   - 在大纲/场景计划中支持自由文本标注
   - 标注内容作为P0优先级注入生成prompt
4. **多版本对比**：
   - 保存每次生成的版本历史
   - 支持diff视图对比不同版本
   - 支持从多个版本中cherry-pick段落组合
5. **实时方向调整**：
   - 支持在生成过程中流式预览
   - 发现方向偏差时可中断并给出新指令

## 是否解决

已解决 — 2026-04-04

已实施以下修复：
1. `chapters` 表新增 `lockedParagraphsJson` 字段，支持段落级锁定标记
2. 重写prompt增加锁定段落保护指令：标记了 `【锁定】` 或 `[LOCKED]` 的段落在重写时原封不动保留
3. 大纲/场景计划中的自由文本标注通过 `chapterGoal`（P0优先级）注入生成prompt

## 预期效果

- 作者能精确控制每个场景的走向
- 人工润色的成果不会被覆盖
- AI和人类的优势互补，而非AI独占创作
