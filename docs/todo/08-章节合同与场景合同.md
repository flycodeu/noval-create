# 章节合同与场景合同

## 一、目标

把“写作前约束”从软提示升级为显式合同，让 Planner 负责合同，Writer 只按合同写现场，不再直接吞大纲话术。

## 二、当前已完成

- [x] 章节已有 `outline`、`scenePlanJson`、`targetWords`、`emotionTone`。
- [x] `chapter_segments` 已有 `purpose / timeAnchor / locationName / inputState / outputState`。
- [x] 写作流水线已经先做 `场景计划`，再做 `初稿 / 审校 / 重写`。
- [x] 当前上下文已包含 `chapterGoal`、`dueForeshadows`、`writingContractSummary`、`hardConstraintContext`。
- [x] 已新增独立 `chapter_contracts / scene_contracts` 表与 `/novels/:id/contracts` 页面。
- [x] 章节合同已支持 `chapterGoal / servedThreadIds / requiredArcProgress / requiredAssetRefs / requiredEndgameCommitmentIds / requiredForeshadowIds / hookType / forbiddenActions / acceptanceNotes`。
- [x] 场景合同已支持 `pov / timeLocation / sceneGoal / obstacle / conflictType / emotionShift / revealPayload / resultState / linkageMode / requiredEndgameCommitmentIds / requiredForeshadowIds`。
- [x] 写作上下文现在会在场景规划、初稿、审校、重写四个阶段强注入章节合同与场景合同约束。
- [x] 正文流水线启动前会严格校验章节合同与场景合同；章节合同未进入 `ready / locked`、章节目标缺失或场景核心字段不全时直接阻塞生成。
- [x] 发布检查已新增“合同完成度对账”，会核对章节合同状态、弧线推进、阻力出手、伏笔处理和场景合同完整度，并持久化到 `chapters.contractAuditJson`。

## 三、本轮边界

- 当前合同链路已经成型，后续只继续补更细的自动验收与提示词压缩策略。

## 四、模块价值

- 直接从大纲跳正文，是长篇漂移的最主要来源之一。
- 只有把章节合同和场景合同拆开，才能真正管住信息、弧线、节奏和钩子。

## 五、当前能力结构

- 已形成两个合同层：
  - `章节合同`
  - `场景合同`
- 章节合同当前包含：
  - `本章目标`
  - `服务哪条主线 / 支线`
  - `必须推进的角色弧`
  - `必须出现的设定 / 物品 / 线索`
  - `结尾钩子类型`
  - `禁止做什么`
- 场景合同当前包含：
  - `POV`
  - `时间地点`
  - `场景目标`
  - `障碍`
  - `冲突类型`
  - `情绪变化`
  - `信息揭示`
  - `结果状态`
  - `与下场衔接方式`

## 六、页面与交互

- 在 `正文写作` 页前置 `合同` 入口。
- 允许从大纲、线程、时间轴预填章节合同。
- 场景合同按场景列表逐条编辑，并与 `chapter_segments` 同步。
- Writer 启动前先做合同校验，缺关键合同项则不进入正文生成。

## 七、数据结构 / 状态字段

- 当前已落地：
  - `chapter_contracts`
  - `scene_contracts`
- 对账结果持久化到：
  - `chapters.contractAuditJson`
- 关键字段：
  - `chapterGoal`
  - `servedThreadIds`
  - `requiredArcProgress`
  - `requiredAssetRefs`
  - `hookType`
  - `forbiddenActions`
  - `pov`
  - `conflictType`
  - `revealPayload`
  - `resultState`

## 八、与现有模块的关系

- `writing contract` 继续作为全书级约束。
- `章节合同` 负责本章约束。
- `场景合同` 负责场景现场约束。
- `章节验收门` 负责写后检查合同是否兑现。

## 九、验收标准

- 章节写作前必须具备可审阅的章节合同。
- 每个场景都能绑定 POV、目标、冲突和结果状态。
- Writer 只能读取合同化上下文，而非直接读取泛化大纲说明。
- 写作后可对账“哪些合同兑现了、哪些没兑现”。
