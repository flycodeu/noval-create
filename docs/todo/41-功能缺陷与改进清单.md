# 41 - 功能缺陷与改进清单

## 一、功能性缺陷

### 1.1 章节衔接机制缺失（P0）

**现状（2026-05-03）**：已补 `Chapter Bridge` 生成与注入链路，正文写作页可展示地点承接、时间承接、情绪承接和首场景约束；当前仍不是独立工作流步骤，而是服务层与写作页里的桥接能力。

**缺陷**：
- 没有显式的"衔接规划"步骤
- 地点转移、时间跳跃、情绪变化依赖 AI 自行判断
- 长篇小说中容易出现"传送门"现象（角色突然出现在新地点，无过渡）

**修复方案**：
- 在 Scene Plan 之前增加 Chapter Bridge 微步骤
- 输入：上一章最后 300 字 + 当前章目标 + 上一章情绪基调
- 输出：地点过渡方式、时间跳跃幅度、开场情绪过渡策略
- 将 Bridge 指令注入第一个 scene 的约束

### 1.2 批量生成的竞态条件（P0，基础已修复）

**现状（2026-05-03）**：批量链路已具备回写等待、`blockedGeneration` / `readyForNextChapter` 状态和下一章阻塞逻辑，写作页也能明确显示“等待回写完成”。

**缺陷**：
- 第 N 章回写完成前，第 N+1 章可能已开始生成
- 导致 N+1 章使用过时的角色状态/伏笔信息
- 用户不知道这个问题存在

**修复方案**：
- 批量模式强制串行：生成 N → 回写 N → 验证 N 回写完成 → 生成 N+1
- 或：增加"回写锁"，回写未完成时阻塞下一章生成，UI 显示等待状态

### 1.3 Prompt Override 安全边界不明确（P1，基础已修复）

**现状（2026-05-03）**：服务层已有 `PROTECTED_RULES`、`prompt_override_audits` 和运行时审计；提示词页本轮补了“系统保留规则”可见性，但尚未做独立审计查看页。

**缺陷**：
- 没有保护列表——GLOBAL_WRITING_RULES 的核心约束理论上可被覆盖
- 覆盖没有审计日志
- 用户可能无意中削弱 AI 味约束

**修复方案**：
- 定义 "不可覆盖" 列表（禁用词黑名单、角色差异化规则、心理维度因果链要求）
- Override 时跳过这些受保护规则
- 每次 override 记录到操作日志

### 1.4 重试变体的确定性问题（P1，基础已修复）

**现状（2026-05-03）**：主章节链路之外，本轮已补齐 `character / timeline / story-thread / item / faction` 的结果级相似度去重闭环：服务会在质量审校通过、候选解析成功后再做摘要相似度校验，过近时自动拒绝并进入下一次尝试或返回 warning。`map / core-settings / world-rules` 仍可继续纳入同一策略，但重点非章节链路已不再裸奔。

**缺陷**：
- 确定性选择意味着相同序号总是相同提示
- 没有检查变体输出是否真正与前次不同
- 如果核心上下文过于约束，不同 hint 可能产生近似输出

**修复方案**：
- 追加前次失败输出的前 200 字作为"避免"约束
- 对变体输出做快速相似度检查（字符级 Jaccard > 0.7 判定为无效变体）
- 无效时自动切换下一个 hint

## 二、体验性问题

### 2.1 Studio Dashboard 信息过载

**现状（2026-05-03）**：Dashboard 已完成首屏与后续刷新分离，blocker 紧凑化，并在本轮新增“参考层”折叠，把活动、风险和修订反推从主行动层里下沉。仍可继续打磨信息密度与卡片层级。

**问题**：用户进入后不知道先看哪里。所有信息平等排列，缺乏视觉层级。

**改进**：
- 将信息分为三层：**行动层**（当前任务 + 下一步）> **状态层**（指标 + 阶段）> **参考层**（活动 + 风险）
- 行动层放在视口正中央，使用更大字号和高对比色
- 参考层折叠/收起，用户主动展开

### 2.2 Writing 页面复杂度失控（基础已修复）

**现状（2026-05-03）**：`Writing/index.tsx` 仍然偏大，但右侧 `editor / context / review / history` 已改为真实 `Routes` 视图切换，4 个 route 文件也不再是旧的空壳透传。当前状态更接近“完成第一轮真实拆分，后续仍需继续 hook/store 化收口”，而不是“所有子路由都还塞在单文件里无效切换”。

**问题**：
- 维护困难，新功能难以添加
- 状态管理复杂度高，组件重渲染范围大
- 代码审查几乎不可能

**改进**：
- 拆分为 5 个独立路由文件：EditorView, ContextView, HistoryView, ReviewView, SettingsView
- 共享状态提取到 `writingView.store.ts`（已有基础）
- 每个 View 文件控制在 500 行以内

### 2.3 创建向导步骤不直观

**现状（2026-05-03）**：专业模式与极速模式都已有中文占位示例、字段说明和 AI 补全反馈提示；但向导仍可继续增强为更强的流式预览与更细粒度的新手引导。

**问题**：
- "AI 补全背景"这步需要等待 AI 响应，但 UI 没有清晰的"正在生成"状态
- 用户在第 2 步写的"原始背景"是什么格式？没有示例
- 快速模式的字段（protagonistStart, coreHook, coreConflict, tabooRules, endgameDirection）名称对普通用户不友好

**改进**：
- 每个输入字段添加占位符示例（中文提示）
- AI 补全步骤增加 streaming 显示
- 快速模式字段中文化：主角出发点、核心钩子 → 故事卖点、核心冲突、禁忌规则 → 绝对不写的内容

### 2.4 角色系统缺少批量操作

**现状（2026-05-03）**：角色页已提供 `AI 生成·主角`、`AI 生成·人物网络`、关系网络修复等批量/半批量入口，因此该问题不再是“完全缺失”，更接近“批量编辑与模板复制仍可增强”。

**问题**：一部小说可能有 15-20 个角色，逐个填写 18 维心理模型非常耗时。

**改进**：
- 增加"批量生成配角"功能——用户只描述角色功能和数量，AI 批量生成
- 增加"角色模板"——从已有角色复制框架，修改关键差异点
- 已有 `batchCharacter` 提示词，但 UI 层是否有对应的批量入口需要确认

## 三、可靠性问题

### 3.1 AI JSON 解析的边界情况

**现状**：`safeParseJson()` 工具处理 AI 返回的 JSON。

**已知风险**：
- AI 可能返回 Markdown 代码块包裹的 JSON（```json ... ```）
- AI 可能返回带注释的 JSON
- AI 可能返回截断的 JSON（token 不足导致输出被截断）

**建议**：
- 确认 `safeParseJson` 是否处理了以上三种情况
- 对截断 JSON 增加"修复尝试"——补全缺失的 `]` `}` 后重试解析
- 解析失败时记录原始输出到调试日志

### 3.2 网络中断的恢复能力（基础已修复）

**现状（2026-05-03）**：章节正文流式阶段已增加 partial content 持久化；写作页能显示“存在中断草稿”，并提供“从断点继续 / 从头重来”双动作。`resumeContent` 现在会优先基于已保留正文走 continuation 续写，而不是一律整章重跑。当前实现属于业务级断点续写，不是底层模型协议级真正断点续传。

**缺陷**：
- 生成中途网络断开时，已产出的内容是否保留？
- 是否有断点续传能力？
- 流式生成中断后能否从断点恢复？

**建议**：
- 流式生成增加**中间缓存**——每 500 字保存一次
- 中断后可选择"从断点继续"而非"从头重来"
- 超时和网络错误区分处理——超时可重试，网络错误提示用户检查连接

### 3.3 数据库并发安全

**现状**：better-sqlite3 是同步的，理论上无并发写入问题。

**但**：
- 回写操作和用户手动编辑可能同时发生
- 批量生成时多个任务可能同时更新同一张表
- better-sqlite3 在 Electron 主进程中运行，阻塞可能影响 UI 响应

**建议**：
- 确认关键写入操作是否在事务内
- 考虑将耗时的批量操作移到 worker thread

## 四、优先级总览

| 优先级 | 问题 | 类型 | 影响 |
|--------|------|------|------|
| P0 | 章节衔接机制 | 功能缺陷 | 直接影响生成质量 |
| P0 | 批量生成竞态 | 功能缺陷 | 可能导致内容矛盾 |
| P1 | Prompt Override 保护 | 安全 | 可能削弱质量控制 |
| P1 | 重试变体去重 | 功能优化 | 影响重试效果 |
| P1 | Dashboard 信息层级 | 体验 | 影响用户效率 |
| P1 | Writing 页面拆分 | 可维护性 | 影响开发效率 |
| P2 | 创建向导优化 | 体验 | 影响新手上手 |
| P2 | 角色批量操作 | 体验 | 影响创作效率 |
| P2 | JSON 解析边界 | 可靠性 | 偶发解析失败 |
| P2 | 网络中断恢复 | 可靠性 | 偶发内容丢失 |
| P3 | 数据库并发安全 | 可靠性 | 极端场景 |
