# 长期上下文压缩与记忆失真问题

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

当前系统已经有长期记忆摘要，但百万字场景下仍存在“历史信息被压缩后失真”的问题。核心不是完全没有记忆，而是长期信息在进入 prompt 前会被阶段摘要、线程摘要、时间锚点等结构进一步压缩，导致细节丢失。

## 2. 当前代码现状

- `electron/services/story-memory.service.ts` 已提供 `phaseDigest`、`plotMilestones`、`arcSignals`、`characterLedger`、`worldLedger`、`activeThreads`、`timelineAnchors`、`itemLedger`。
- `electron/services/story-memory.service.ts` 已支持 `standard / longform / epic / mega` 四种模式。
- `electron/services/context.service.ts` 通过 `buildStoryMemoryPromptSummary` 将长期记忆汇总后注入章节上下文。
- `electron/services/context.service.ts` 仍以文本摘要块形式组织长期信息，而不是按实体状态强约束注入。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：系统已经有长期记忆摘要与检查点，不是写完即忘。
- 部分解决：长篇模式、checkpoint、阶段摘要已经上线。
- 未解决：细粒度状态长期保存、召回与校验仍然不足。

当前判断：`部分解决`

## 4. 潜在风险

- 角色伤势、资源消耗、关系态度会被概括成一句话，失去执行精度。
- 某些重要历史细节在后续生成时只剩模糊标签，正文容易写偏。
- 卷级和全书级的重要状态可能只保留“发生过”，而不是“目前仍然有效”。

## 5. 原因分析

- 长篇文本天然不能把完整历史全文带入 prompt。
- 当前压缩策略以摘要为中心，适合降 token，不适合维护状态机。
- 长期记忆是“信息集合”，不是“状态约束集合”。

## 6. 扩展方案

- 将长期记忆从“摘要主导”改为“摘要 + 状态账本”双层结构。
- 保留 `phaseDigest` 这类叙事摘要，同时新增实体状态账本。
- 在生成前先注入强约束状态，再注入可裁剪的背景摘要。
- 对关键状态引入“当前值 + 变更来源章节 + 最近验证章节”。

## 7. 建议的数据结构 / 指标 / 页面能力

- `characterArcLedger`：人物当前状态、阶段目标、阻力、代价。
- `worldStateLedger`：地理、制度、秩序、势力、资源现状。
- `stateConfidence`：某条状态最近一次被验证的章节。
- 质量页新增“长期状态覆盖率”“状态失真风险数”。

## 8. 实施优先级

等级：`S级`

等级说明：这是百万字生成的底层约束问题，后续长期治理都依赖它。

原因：这是百万字生成最底层的问题，后续伏笔、人物弧、节奏治理都依赖它。

## 9. 验收标准

- 长期状态不再只以摘要文本存在，至少有一层结构化账本。
- 关键角色、关键势力、关键物品、关键事件状态可查询当前值。
- 新章节生成时能显式带入这些当前值，而不是只带阶段摘要。
- 连续 100 章以上的设定回查中，状态丢失率显著下降。
