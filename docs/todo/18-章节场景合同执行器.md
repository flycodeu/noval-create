# 章节场景合同执行器

## 一、目标

把章节合同和场景合同从“生成前任务说明”升级为“正文兑现标准”。每个合同项都要能在正文里找到证据，缺失时能生成明确的重写任务。

## 二、当前已完成

- `chapter_contracts` 已记录章节目标、服务线程、人物弧、关系弧、阻力线、终局承诺、伏笔、钩子、禁用动作、验收要求。
- `scene_contracts` 已记录 POV、时间地点、场景目标、障碍、冲突类型、情绪变化、揭示内容、结果状态。
- `validateChapterContractsForGeneration` 会阻断缺合同、缺 POV、缺场景目标、缺障碍、缺结果状态的章节。
- 章节门已能检查合同兑现率、POV 纯度、线程推进等。

## 三、当前缺口

- 现有检查偏“结构化记录是否存在”，不等于“正文是否写出来”。
- 缺少正文级 `ChapterContractValidator`。
- 支线“提及”和“推进”没有区分。
- 合同失败后无法定位到具体段落或场景。
- Rewriter 还不能按合同失败项做局部重写。

## 四、详细设计

### 4.1 ChapterContractValidator

新增服务 `chapter-contract-validator.service.ts`。

输入：

- 章节正文。
- 章节合同。
- 场景合同。
- 场景计划。
- 审校意见。

输出：

```ts
ChapterContractValidationResult {
  status: 'pass' | 'warning' | 'blocker'
  summary: string
  itemResults: ContractValidationItem[]
  rewriteHints: string[]
}
```

单项结果：

```ts
ContractValidationItem {
  contractItemType: string
  contractItemId?: number
  expected: string
  verdict: 'pass' | 'weak' | 'missing' | 'contradicted' | 'overdelivered'
  evidenceExcerpt: string
  segmentId?: number
  rewriteHint: string
}
```

### 4.2 MVP 验证项

第一版只做高价值项：

- 章节目标是否被正文完成。
- 每个场景是否有可见冲突。
- 每个场景结果状态是否落地。
- 必要支线是否推进，而不只是提及。
- 必要伏笔是否埋设、推进、回收或说明延期。
- 章节钩子是否存在。

### 4.3 verdict 定义

| verdict | 含义 |
|---|---|
| pass | 正文有明确证据 |
| weak | 有迹象但不充分 |
| missing | 正文未体现 |
| contradicted | 正文与合同冲突 |
| overdelivered | 写了合同外重大信息，可能破坏后续 |

### 4.4 与章节门集成

- `missing` 或 `contradicted` 命中关键项时，章节门进入 blocker。
- `weak` 累计过多时进入 warning。
- 结果写入 `chapterGateRuns` 或单独 validation run。
- Rewriter 消费 `rewriteHints` 生成修复稿。

## 五、建议新增数据结构

P1 可新增：

```ts
chapter_contract_validation_runs {
  id
  novelId
  chapterId
  status
  summary

  rewriteHintsJson
  createdAt

```

P0 可先不建表，把结果写入 `reviewNotesJson` 或 `chapterGateRuns.topIssueKeysJson`。

## 六、实施步骤

1. 新增合同验证服务，先用规则 + LLM 审核混合方式。
2. 在 Critic 后、Rewriter 前执行验证。
3. 将验证失败项合并到审校意见和章节门。
4. 为支线和伏笔定义“提及/推进/回收”判定。
5. 将失败项转成局部重写提示。

## 七、验收标准

- 任意章节能列出合同项和正文证据。
- 合同项缺失时能说明缺哪个场景、缺什么动作或结果。
- 支线推进不再把“提到名字”算作推进。
- 合同失败能触发重写，而不是只显示 warning。

## 八、风险与建议

- 不要第一版验证全部合同字段，先做最影响长篇稳定性的 5-6 类。
- 自动证据抽取可能误判，需要保留人工确认入口。
- 合同过重会让正文僵硬，验证应关注关键承诺，不要把所有建议都变 blocker。
