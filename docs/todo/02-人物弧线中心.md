# 人物弧线中心

## 一、目标

把人物从“静态档案”提升为“有持续变化轨迹的角色系统”。重点覆盖主角弧、关键角色弧和关系弧。

## 二、当前已完成

- [x] `characters` 表已有 `surfaceDesire / deepNeed / coreFear / selfDeception / trauma / contradiction / characterArc`。
- [x] `character_relations` 已有 `relationLabel / tensionLevel / interactionStyle / subtextRule`。
- [x] `character-state.service.ts` 会按章节刷新人物状态版本。
- [x] `dialogue-fingerprint.service.ts` 与质量看板已经在做对白区分与漂移检测。
- [x] 已新增独立 `人物弧线中心` 页面，并接入 Novel 工作区导航、角色系统入口和创作总览入口。
- [x] 已支持 `主角弧 / 关键角色弧 / 关系弧` 统一视图，支持按角色与按角色对切换。
- [x] 已支持维护 `初始状态 / 角色想要什么 / 角色真正需要什么 / 核心恐惧 / 误信 / 第一次裂缝章节 / 关键改变事件 / 最终状态 / 当前状态`。
- [x] 已新增 `character_arcs / character_arc_beats / relationship_arcs` 持久化结构。
- [x] 已支持把时间轴事件绑定到角色改变与关系改变。
- [x] `章节合同` 已支持引用“本章必须推进的人物弧 / 关系弧”。
- [x] 写作后已支持在 `人物弧线中心` 与 `章节合同` 中手动登记“本章推进”，并回写弧线状态。

## 三、本轮落地

- [x] `章节验收门` 已会结合章节合同绑定的人物弧、人物状态 delta 和自动推进记录判断“本章是否真的推动了对应弧线”。
- [x] 正文写后刷新人物状态时，已会按章节合同自动补写人物弧推进节点，并回填最近推进章节。
- [x] `人物弧线中心` 已补上按角色 / 关系定向打开 `修订中心` 的直达入口。

## 四、模块价值

- 人物设定完整，不代表人物真的在变化。
- 长篇失速时，常见症状是“人物一直在做事，但没发生价值和关系变化”。

## 五、当前能力结构

- 已有独立页面：`人物弧线中心`
- 当前核心板块：
  - `主角弧`
  - `关键角色弧`
  - `关系弧`
- 每条弧当前至少包含：
  - `初始状态`
  - `角色想要什么`
  - `角色真正需要什么`
  - `核心恐惧 / 误信`
  - `第一次裂缝章节`
  - `关键改变事件`
  - `最终状态`

## 六、页面与交互

- 从 `角色系统` 进入，但独立于角色档案页。
- 支持按角色查看个人弧线，按角色对查看关系弧。
- 每条弧线显示最近一次推进章节与当前停滞状态。
- 支持一键跳转到相关角色页、章节合同与相关工作区，并可按当前角色 / 关系定向打开修订中心。

## 七、数据结构 / 状态字段

- 已新增：
  - `character_arcs`
  - `character_arc_beats`
  - `relationship_arcs`
- 当前核心字段：
  - `characterId / relationPair`
  - `startState`
  - `surfaceWant`
  - `deepNeed`
  - `coreFear`
  - `misbelief`
  - `firstCrackChapter`
  - `changeEvent`
  - `endState`
  - `currentStatus`

## 八、与现有模块的关系

- `角色系统` 是静态画像与资料维护。
- `人物弧线中心` 是动态变化维护。
- `章节合同` 需要引用“本章必须推进的人物弧”。
- `章节验收门` 需要判断本章是否真的推动了对应弧线。

## 九、验收标准

- [x] 至少可为主角和 1 名关键角色建立完整弧线。
- [x] 关系弧支持绑定两名角色，并记录阶段变化。
- [x] 写作前能从章节合同中引用弧线目标。
- [x] 写作后能把实际推进回写到弧线状态。
- [x] `章节验收门` 已能自动识别合同绑定弧线是否被推进。
- [x] 正文级状态刷新已能自动回写人物弧推进。
- [x] 修订任务已支持从人物弧线中心定向直达。
