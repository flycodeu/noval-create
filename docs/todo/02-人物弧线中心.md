# 人物弧线中心

## 一、目标

把人物从“静态档案”提升为“有持续变化轨迹的角色系统”。重点覆盖主角弧、关键角色弧和关系弧。

## 二、当前已完成

- [x] `characters` 表已有 `surfaceDesire / deepNeed / coreFear / selfDeception / trauma / contradiction / characterArc`。
- [x] `character_relations` 已有 `relationLabel / tensionLevel / interactionStyle / subtextRule`。
- [x] `character-state.service.ts` 会按章节刷新人物状态版本。
- [x] `dialogue-fingerprint.service.ts` 与质量看板已经在做对白区分与漂移检测。

## 三、当前未完成

- [ ] 没有独立 `人物弧线中心` 页面。
- [ ] 没有“初始状态 -> 裂缝 -> 转折 -> 最终状态”的弧线节点。
- [ ] 没有主角弧、关键配角弧、关系弧的统一视图。
- [ ] 没有“哪个事件让角色改变”的明确绑定。
- [ ] 没有章节层面的“本章必须推进哪条人物弧”约束。

## 四、为什么现在要补

- 人物设定完整，不代表人物真的在变化。
- 长篇失速时，常见症状是“人物一直在做事，但没发生价值和关系变化”。

## 五、建议新增内容

- 新增页面：`人物弧线中心`
- 页面核心板块：
  - `主角弧`
  - `关键角色弧`
  - `关系弧`
- 每条弧至少包含：
  - `初始状态`
  - `角色想要什么`
  - `角色真正需要什么`
  - `核心恐惧 / 误信`
  - `第一次裂缝章节`
  - `关键改变事件`
  - `最终状态`

## 六、页面与交互

- 从 `角色系统` 进入，但独立于角色档案页。
- 支持按角色查看个人弧线，按角色对查看关系弧。
- 每条弧线显示最近一次推进章节与当前停滞状态。
- 支持一键跳转到相关章节、关系、修订任务。

## 七、数据结构 / 状态字段

- 建议新增：
  - `character_arcs`
  - `character_arc_beats`
  - `relationship_arcs`
- v1 最少字段：
  - `characterId / relationPair`
  - `startState`
  - `surfaceWant`
  - `deepNeed`
  - `coreFear`
  - `misbelief`
  - `firstCrackChapter`
  - `changeEvent`
  - `endState`
  - `currentStatus`

## 八、与现有模块的关系

- `角色系统` 是静态画像与资料维护。
- `人物弧线中心` 是动态变化维护。
- `章节合同` 需要引用“本章必须推进的人物弧”。
- `章节验收门` 需要判断本章是否真的推动了对应弧线。

## 九、验收标准

- 至少可为主角和 1 名关键角色建立完整弧线。
- 关系弧支持绑定两名角色，并记录阶段变化。
- 写作前能从章节合同中引用弧线目标。
- 写作后能把实际推进回写到弧线状态。
