# 势力物品关系状态不同步与世界状态总账扩展

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

当前项目中势力、物品、关系、时间线等数据已经存在，但这些信息仍然分散管理。百万字小说中，一旦这些状态不同步，就会直接表现为世界观失稳和剧情承接失真。

## 2. 当前代码现状

- `electron/services/context.service.ts` 会拼装 `itemSummary`、`relationSummary`、`worldRules`、`timelineSummary`。
- `electron/services/story-memory.service.ts` 已有 `itemLedger`、`worldLedger`、`timelineAnchors`。
- `electron/services/consistency.service.ts` 已检查角色、时间线、物品、关系、地图等多类问题。
- 当前没有统一的“世界状态总账”来给出这些实体的当前状态。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：相关实体数据已存在，且能被拼接进上下文。
- 部分解决：一致性体检能发现部分冲突。
- 未解决：没有全局统一状态源。

当前判断：`部分解决`

## 4. 潜在风险

- 某件物品已经损坏，后文却继续正常使用。
- 某势力关系已恶化，但章节生成里仍按旧关系输出。
- 时间线、关系、物品状态之间出现相互矛盾。

## 5. 原因分析

- 多个实体状态来自不同表、不同摘要和不同阶段生成结果。
- 当前更像“运行时拼装资料”，不是“统一读取当前事实”。
- 实体间缺少共享状态与版本控制。

## 6. 扩展方案

- 新增 `worldStateLedger` 作为统一事实层。
- 将势力、物品、关系、地点、制度状态统一抽象成当前值和变更历史。
- 章节生成前优先读取总账，而不是临时拼多份摘要。
- 审校阶段对章节中出现的世界状态进行反向校验。

## 7. 建议的数据结构 / 指标 / 页面能力

- `worldStateLedger`
- `factionState`
- `itemState`
- `relationState`
- `locationState`
- `worldStateConflictCount`
- 页面新增“世界状态概览”“冲突实体列表”

## 8. 实施优先级

等级：`A级`

等级说明：世界状态治理关键，但更适合建立在前置状态建模和角色账本基础上。

原因：这是保证世界观长期稳定的基础设施，尤其适合在状态机体系一起建设。

## 9. 验收标准

- 主要势力、物品、关系、地点具备统一的当前状态来源。
- 章节生成和审校都能引用同一套状态。
- 一致性体检可以直接指出状态冲突来源。
- 世界状态冲突数量随章节增加不再线性放大。
