# P0 - 流式解析器竞态条件（SSE分块丢字）

> 优先级：P0（致命）
> 影响范围：章节内容静默丢失
> 实现难度：中
> 类别：后端-适配器

---

## 问题

OpenAI和Anthropic适配器的流式解析器在处理SSE（Server-Sent Events）响应时，多行JSON可能跨`reader.read()`调用被分割。当前解析器按`\n`分割并期望完整的`data: `行，但SSE可以在JSON中间断开，导致**静默丢失段落内容**。

示例：
```
Chunk 1: 'data: {"choices":[{"delta":{"con'
Chunk 2: 'tent":"这是一段话"}}]}\ndata: {"...'
```

代码 `text.split('\n').filter(l => l.startsWith('data: '))` 会丢失第一个不完整chunk。

## 原因

- `electron/adapters/openai.adapter.ts:66-86` 按行分割但未缓存不完整行
- `electron/adapters/anthropic.adapter.ts:53-72` 同样存在此问题
- 没有跨`reader.read()`调用的状态追踪
- 未使用标准SSE解析器

## 解决方式

1. **实现行缓冲器**：在`reader.read()`调用间维护未完成行的缓冲区
2. **跨chunk状态追踪**：记录上一个chunk的尾部，与下一个chunk头部拼接
3. **使用标准SSE解析**：采用`for await`配合累积缓冲区的模式
4. **添加数据完整性校验**：每个chunk解析后验证JSON完整性

## 预期效果

- 5000字以上长章节不再出现段落丢失
- 流式生成内容100%完整
- 消除因网络分块导致的叙事跳跃
