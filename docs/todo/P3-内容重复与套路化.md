# P3 - 内容重复与套路化

> 优先级：P3（改进项）
> 影响范围：长篇可读性
> 实现难度：中

---

## 问题

AI在生成百万字内容时，容易陷入重复模式：相似的情节走向反复出现（每10章一次"突然遭遇危机→主角化险为夷"）、描写手法重复（总是"阳光洒在脸上"、"心中一紧"）、场景布局雷同。

## 原因

- `generationHistory` 表的 `outputDigest` 仅保存前300字符，无法检测段落级重复
- `variation-control.service.ts` 的相似度检测（`computeCandidateSimilarity`）基于bigram，精度有限
- 缺少**全局重复检测**：不会跨章节检测描写/情节/用词的重复模式
- prompt中缺少对"避免重复"的具体指导——不是告诉AI"不要重复"，而是需要告诉它"第X章已经用过这个情节模式"
- 缺少**情节模式库**：没有追踪已使用过的叙事桥段

## 解决方式

1. **全局重复检测引擎**：
   - 构建已使用描写片段的嵌入向量库
   - 新生成内容与历史内容进行语义相似度对比
   - 相似度超过阈值时触发重写
2. **情节模式追踪**：
   - 记录每个弧使用的核心情节模式（"遭遇危机"、"获得新能力"、"失去同伴"等）
   - 生成时注入已使用模式列表，要求使用新模式
3. **描写手法多样性检查**：
   - 统计近10章的高频描写词汇
   - 将高频词加入当前章节的"避免用词"列表
4. **转折点差异化**：
   - 确保每个弧的高潮使用不同的叙事手法
   - 维护"高潮手法库"并标记已使用条目

## 是否解决

已解决 — 2026-04-04

已实施以下修复：
1. 新增 `collectHighFrequencyRepetitions()` 函数，检测章节内高频重复词组（4次以上的2-4字中文词组），自动标记为质量问题
2. `content-guardrails.ts` 检测规则扩展到 20+ 条，覆盖：
   - `ai_description_cliche`：高频描写套路（"阳光洒在""月光如水"）
   - `ai_action_cliche`：高频动作套路（"深吸一口气""瞳孔骤然收缩"）
   - `ai_repetitive_structure`：连续使用相同句式结构
   - `high_frequency_repetition`：章节内高频重复词组
3. `buildGuardrailCriticalFixes()` 增加重复词组修复指令
4. `GLOBAL_WRITING_RULES` 中的对比示例教AI用新鲜表达替代套路
5. 质量检测上限从 6 条扩展到 8 条

## 预期效果

- 每个弧的情节模式都有新意
- 描写手法丰富多样
- 读者不会产生"又来了"的疲劳感
