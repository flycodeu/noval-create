# P1 - 工作流门禁只校验存在不校验新鲜度与质量

> 优先级：P1（严重）
> 影响范围：流程完整性、长线一致性
> 实现难度：中

---

## 涉及模块

- `src/pages/Novel/workflow.ts`
- `electron/services/context-impact.service.ts`
- `electron/services/revision-task.service.ts`
- 关联影响：`src/pages/Novel/Writing/index.tsx`、`electron/services/embedding.service.ts`

## 问题

原始问题是：工作流虽然已经具备 blocker 和推荐步骤，但门禁核心长期停留在“这个模块有没有数据”，而不是“这个数据是不是最新、是否通过质量门槛、是否和上游版本保持同步”。

这会导致一个典型问题：  
系统允许用户进入下一步，但进入时携带的是**旧上下文、旧资产、旧记忆、低质量结果**。

具体失败模式：

- 世界规则改动后，人物、物品、线程仍是旧版本，系统却允许继续写正文
- 主角设定、主题基调、立项信息已调整，时间轴/故事设计没有重新同步，流程仍放行
- 长文记忆或检查点已过期，但正文入口只看 `outlineCount`、`timelineCount`、`threadCount`
- 某些上游资产虽然存在，但内容空泛、AI 味重、偏离背景，流程仍视为“已准备完毕”

## 当前状态

这条问题已经**部分解决**，但还没有完全闭环。

已经补上的能力：

- `context-impact.service.ts` 已能标记章节上下文过期，并统计 `staleChapterCount`
- `revision-task.service.ts` 已把高优先级一致性问题汇总为修订 blocker
- 写作页已有 `publish check`，能检查摘要、连续性记忆、上下文版本、高优先级结构风险、AI 体检、审校状态
- `workflow.ts` 现已把这些信号接入关键入口：
  - `outline` 会拦高优先级修订 blocker
  - `timeline` 会拦高优先级修订 blocker
  - `writing` 会同时拦高优先级修订 blocker 和旧上下文章节
- continuity fragment 的 embedding 生成逻辑已经补上，新生成或重刷的章节会写入更完整的 continuity 向量片段

## 仍未解决的部分

当前剩余缺口主要在**资产层 freshness**，不是章节层 freshness：

- 世界规则改动后，人物、物品、线程、时间轴本身还没有统一的 `stale` 元数据与依赖快照
- 因此系统还不能可靠判断“这批资产是不是基于最新上游重新生成的”
- 现在真正升级的是**章节写作入口**和**关键结构入口**，不是所有资产页都完成了依赖版本化
- 老项目里已有章节的 embedding 不会自动重建；如果要让历史章节也吃到 continuity fragment 修复，需要手动执行一次 `embedding:reindex`

## 为什么前三轮修复后仍然可能发生

前三轮修复的重点更多是上下文容量、模型适配、章节质量和局部可靠性。  

这些修复提高了“单个模块能不能生成好”，但没有把“模块之间何时允许流转”升级成严格的 freshness / quality gate，所以工作流会把“存在但陈旧”的资产当成可用资产。

## 解决方式

1. 已完成的部分：
   - 写作入口增加章节上下文新鲜度门禁
   - 结构关键入口增加高优先级修订 blocker
2. 剩余待补的部分：
   - 为关键资产模块增加“新鲜度门禁”：
   - 记录依赖快照或 `contextVersion`
   - 当上游数据变更后，下游模块标记为 `stale`
3. 为关键资产入口增加“质量门禁”：
   - 世界规则、人物、物品、线程、时间轴等至少通过基础校验后才算 ready
4. 把“可运行”与“建议运行”拆开：
   - `ready`: 数据存在且新鲜
   - `recommended`: 质量较高，适合进入下一步

## 是否解决

部分解决 — 2026-04-05

当前状态：章节入口已闭环，资产入口仍半闭环

- `outline / timeline / writing` 已接入质量或新鲜度 blocker
- `writing` 不再只看有没有大纲、线程、时间轴，也会检查旧上下文章节和高优先级修订问题
- 但世界规则 -> 人物 / 物品 / 线程 / 时间轴 这一层仍缺统一 freshness 判定

## 预期效果

- 用户不会在“旧章节仍引用旧上下文”或“高优先级结构问题未处理”的状态下误入正文写作
- 工作流开始承担一部分真实的质量闸门职责，而不是只做步骤导航
- 后续继续补资产层 freshness 后，才能真正防止“上游设定已改、下游资产未同步”这一整条链路漏检
