# 章节验收门

## 一、目标

把“本章写完了”与“本章可进入完成态”分开，通过更强的门禁控制一致性、推进度、口吻和钩子质量。

## 二、当前已完成

- [x] `context-impact.service.ts` 已实现 `runChapterPublishCheck`。
- [x] 写作页在标记完成时会重新执行发布检查。
- [x] 当前已检查阻塞项、预警项、召回风险和部分一致性问题。
- [x] 审校环节与质量看板已经能识别对白漂移、代价蒸发、AI 味等问题。
- [x] 发布检查已新增章节合同与场景合同完成度对账，并把结果持久化到 `chapters.contractAuditJson`。
- [x] 发布检查已升级为 `通过 / 预警 / 阻塞 / 退回重写` 四级门禁，并返回 `gateLevel / rewriteTarget / scoreBreakdown`。
- [x] 已新增 `POV 纯度`、`钩子强度`、`线索 / 线程推进度`、`卷目标一致性`、`角色口吻一致性`、`本章是否真的推进了某条线`、`润色可解 / 必须重写` 的验收项。
- [x] 失败项已支持同步为 `system` 来源修订任务，并附带定位信息与去重 `issueKey`。
- [x] 写作页已扩展为可展开的验收报告，`gateLevel` 会直接影响章节能否进入完成态。

## 三、后续可扩展

- [x] 已细化正文级语义评分阈值，并把更多 AI 审校信号转成可量化分数。
- [x] 已补“按历史章节趋势回看门禁漂移”的纵向分析，不影响当前模块完成判定。

## 四、模块价值

- 当前发布检查更接近“基本可用”，还不是“长篇稳定可交付”。
- 百万字系统里，很多问题不是润色能解决的，而是需要退回合同或场景重写。

## 五、当前能力结构

- 当前验收结果分成四级：
  - `通过`
  - `预警`
  - `阻塞`
  - `退回重写`
- 当前重点检查项：
  - `事实一致性`
  - `风格一致性`
  - `角色口吻一致性`
  - `POV 纯度`
  - `合同兑现率`
  - `线索 / 伏笔 / 线程推进度`
  - `钩子强度`
  - `卷目标一致性`

## 六、页面与交互

- 保留当前写作页发布检查弹窗，但扩展成可展开的验收报告。
- 阻塞项支持一键跳回对应合同、场景、修订点。
- `退回重写` 时直接进入对应场景或选中文段重写流程。
- 支持把验收失败项转成修订任务。

## 七、数据结构 / 状态字段

- 当前在现有发布检查结果上扩展，不另建孤立系统。
- 核心字段：
  - `gateLevel`
  - `contractScore`
  - `hookScore`
  - `povPurityScore`
  - `threadProgressScore`
  - `rewriteRecommended`
  - `rewriteTarget`

## 八、与现有模块的关系

- `章节合同与场景合同` 提供验收基准。
- `章节验收门` 负责判断是否达标。
- `修订中心` 负责接收失败项。
- `质量监控` 负责显示长期趋势，而不是替代单章门禁。

## 九、验收标准

- 发布检查能区分“可发布但预警”和“必须退回重写”。
- 至少覆盖 POV、合同兑现、线索推进、钩子强度、角色口吻五类新规则。
- 失败项可直接定位到章节或场景。
- 门禁结果会影响章节状态流转，而不是只弹提示。
