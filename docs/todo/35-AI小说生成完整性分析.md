# 35 - AI 小说生成完整性分析

## 总体评估

当前系统是**专业级 AI 中文小说生成平台**，而非简单的 AI 文本生成器。从架构设计到提示词工程，系统体现了对中文网文创作的深刻理解。

**综合完成度：85-90%**

---

## 一、生成流程完整性

### 1.1 已实现的完整链路（13 步引导流程）

```
立项 → 项目简报 → 故事核心 → 文风设定 → 世界底盘 →
终局设计 → 地图结构 → 道具系统 → 角色名册 →
故事线程 → 故事大纲 → 卷级规划 → 正文写作
```

**每一步都有质量门控**：进入下一阶段前，系统会检查前置条件是否满足。例如进入正文写作前必须具备：大纲、时间轴、线程，且无上下文过期章节。

### 1.2 正文生成五阶段流水线

| 阶段 | 功能 | 质量控制 |
|------|------|----------|
| Scene Plan | 场景结构分解 | 验证场景目标与章节合同匹配 |
| Draft | 初稿生成 | 上下文注入、硬约束保护 |
| Review | AI 审校 | 连续性、角色一致性、AI 味检测 |
| Rewrite | 问题修复 | 基于审校报告定向重写 |
| Finalize | 终稿锁定 | 合同验收、状态回写 |

### 1.3 缺失或薄弱环节

1. **章节间过渡衔接**：系统通过 `lastChapterEnding` 保持连续性，但缺少显式的"过渡策略规划"——如何从上一章的情绪/节奏自然过渡到新章节
2. **多 POV 切换管理**：角色系统支持多人物，但缺少明确的 POV 轮转规划和视角切换时的信息差控制
3. **长篇节奏宏观调控**：单章节奏控制到位（情绪基调 → 句式长度映射），但百万字级的整体节奏曲线（高潮分布、低谷调节）尚无自动化规划
4. **读者钩子自动化**：章末悬念、章首承接 hook 在提示词中有要求，但缺少系统级的 hook 质量评分和连贯性追踪

## 二、AI 味抑制体系评估

### 2.1 已实现的反 AI 措施（极为全面）

**禁用词/短语黑名单**（prompt-library.ts GLOBAL_WRITING_RULES）：

| 类别 | 禁用示例 | 替代要求 |
|------|----------|----------|
| 情绪描写 | "心中涌起一股复杂的情绪" | "他把烟掐灭了，手指尖被烫得发白" |
| 命运修辞 | "命运的齿轮开始转动" | "审批单被驳回的第三天，他等来了另一封信" |
| 感官陈词 | "阳光洒在脸上" | "防水布拉开一条缝，刺目的光让他眯了眼" |
| 过渡虚词 | "突然""不由得""这一刻" | 直接写动作，删除过渡词 |
| 拟人滥用 | "城市哭泣""门感到愤怒" | 精确动词（破败、卡住、瘫痪） |

**角色差异化强制**：
- 每个角色必须有独立口头禅、用词水平、句式偏好
- 对白允许打断、省略、不回答、沉默
- 上下级/亲疏/紧张/放松场景语气必须不同

**心理维度因果链**：
- 18 个深层心理字段不是独立填写，必须互相咬合
- core_fear 必须解释 self_deception 为什么成立
- trauma 必须影响 inner_conflict 的具体内容

### 2.2 题材特化规则

| 题材 | 核心约束 |
|------|----------|
| 武侠 | "写见闻、挫败和行路中的选择，别磨成打怪线" |
| 修仙 | "闭关失败、资源枯竭、师承压力要有长期影响" |
| 末世 | "成长重点是判断、纪律、信任和取舍，不是突然无敌" |
| 悬疑 | "标题从证据载体、地点纹理取词，不堆'迷雾''深渊''命运'" |

### 2.3 仍可能出现 AI 味的风险点

1. **规则执行层与设计层脱节**：提示词层面规则极好，但 AI 模型在 token 压力下可能忽略部分规则。Review 阶段能补救，但若模型本身能力不足（如使用廉价模型），审校质量也打折扣。
2. **重复模式积累**：同一部小说写到 50+ 章后，即使单章质量好，**跨章节的表达重复**会逐渐暴露 AI 味。目前无"全局去重"机制检测跨 10 章以上的表达复用。
3. **角色声音长期一致性**：dialogue-fingerprint.service 做了声音锁定，但随着角色成长/变化，声音应该**可控进化**而非固定不变。
4. **情感高潮区的公式化**：当多个章节都到达情感高潮时，AI 容易使用相似的**修辞升级模式**（句子变短 → 碎片化 → 反复 → 收束），即使内容不同，结构模式的雷同也会暴露 AI。

## 三、上下文管理系统评估

### 3.1 架构优势

- **三阶段组装**：base → recall → allocation，不是简单的拼接
- **智能 token 估算**：中文 1.0、英文 0.25、标点 0.5，加 10% 安全裕度
- **硬约束保护**：关键上下文（章节目标、角色状态、世界规则）优先注入
- **向量召回**：embedding.service 做相似场景检索
- **决策日志**：每个上下文部分都有 status/reason/allocation 记录

### 3.2 潜在问题

1. **硬约束溢出**：HardConstraintOverflowError 说明硬约束可能超出预算。当世界观复杂、角色众多时，刚性需求可能无法全部注入。
2. **向量召回质量**：取决于 embedding 模型质量。如果用小模型做 embedding，召回的"相似场景"可能不相关，反而注入噪声。
3. **长篇累积压力**：小说写到 100+ 章后，"最近 N 章摘要"的信息密度会急剧下降。系统用 resolveRecentContextWindow（8-40 章窗口），但摘要本身的质量衰减未被监控。
4. **上下文版本同步**：有 staleChapterCount / staleCheckpointCount 追踪，但同步操作本身是否可靠（批量回写是否全部成功）缺少可见的重试/补偿机制。

## 五、总结建议

### 高优先级

1. 增加**跨章节表达去重**检测，标记 10 章内出现 3 次以上的相同修辞模式
2. 完善**长篇摘要质量衰减**监控，当摘要信息密度低于阈值时触发重新压缩
3. 增加**章节过渡策略**模块，规划情绪/节奏/场景的自然衔接

### 中优先级

4. 实现 **POV 轮转规划器**，管理多视角叙事的信息差和视角分配
5. 添加**情感节奏宏观曲线**，在卷/全书级别规划高潮分布
6. 强化**角色声音进化**，允许角色语言风格随成长弧线缓慢变化

### 低优先级

7. 道具系统增加剧情关联推荐
8. 向量召回增加 fallback 策略
9. 上下文同步增加重试/补偿机制
