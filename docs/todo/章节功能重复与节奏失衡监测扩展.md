# 章节功能重复与节奏失衡监测扩展

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

百万字小说最容易出现的不是某一章崩坏，而是很多章都“还能看”，但功能重复。比如连续几章都在铺垫、解释、装氛围，导致整体节奏失衡。

## 2. 当前代码现状

- `electron/services/story-prompts.ts` 已包含节奏指导和关键章节要求。
- `electron/services/chapter.service.ts` 的审校里有 `reader_hook_risks`。
- `electron/services/quality-dashboard.service.ts` 只展示评分趋势，不展示章节功能分布。
- 当前没有 `chapterFunctionTags` 或节奏功能统计。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：prompt 已有一定节奏意识。
- 部分解决：审校可发现部分追读风险。
- 未解决：章节功能和节奏模式没有结构化统计。

当前判断：`未解决`

## 4. 潜在风险

- 连续多章重复做铺垫或解释，读者会感到“在原地踏步”。
- 爆发、喘息、回收之间缺乏节奏层次。
- 同一个剧情功能被反复承担，章节存在感变弱。

## 5. 原因分析

- 当前系统没有给章节定义明确的功能标签。
- 节奏控制主要靠 prompt 要求，不靠结果回收。
- 质量看板没有观察节奏结构的能力。

## 6. 扩展方案

- 为章节引入功能标签：铺垫、推进、反转、回收、喘息、爆发、解释、收束。
- 统计连续相同功能章节数。
- 检查卷内功能分布是否过度偏科。
- 对关键章节设置最低功能要求，避免名义关键章实际只做过渡。

## 7. 建议的数据结构 / 指标 / 页面能力

- `chapterFunctionTags`
- `repeatedFunctionRunLength`
- `rhythmBalanceScore`
- `chapterPurposeCoverage`
- 页面新增“章节功能分布图”“节奏异常区段”

## 8. 实施优先级

等级：`A级`

等级说明：对注水和空转识别价值高，但略后于主线推进和代价体系。

原因：它对中后期空转和“注水感”识别非常有效。

## 9. 验收标准

- 每章具备至少一个主功能标签。
- 连续重复功能章节可自动识别。
- 卷级和全书级可展示节奏分布。
- 节奏失衡问题可从“主观感觉”转为“可量化风险”。
