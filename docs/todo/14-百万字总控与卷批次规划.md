# 百万字总控与卷批次规划

## 一、目标

把当前“单章生成能力”提升为“百万字生产调度能力”。系统要能围绕 80-120 万字项目，按卷、批次、章节组织生成和验收，而不是让用户手动连续点击 300 次。

推荐默认规模：

- 总字数：80-120 万字。
- 章节数：250-400 章。
- 每章：2500-4000 字。
- 每卷：25-35 章。
- 每批：8-15 章。
- 每 10 章强制形成一个长期记忆 checkpoint。

## 二、当前已完成

- 已有卷级设计、故事弧、章节合同、场景合同、章节门和任务中心。
- `chapter.service.ts` 已有单章角色化流水线。
- `tasks` 已能记录任务状态、流水线角色、耗时、恢复入口。
- `story_memory_checkpoints` 已能承载长篇压缩记忆。
- 质量仪表盘已经具备卷级和章节级趋势展示基础。

## 三、当前缺口

- 没有“百万字生产计划”实体，缺少总字数、卷数、批次大小、抽检频率和暂停条件。
- 没有批次级状态，无法表达“第 41-55 章正在生成，已完成 9 章，2 章待重写，1 章待回写”。
- 进入下一批前没有质量总灯，用户不知道当前是否适合继续生成。
- 缺少批次失败恢复策略：某章合同阻塞、上下文溢出、召回失败、Canon 待确认时应怎么处理。

## 四、详细设计

### 4.1 百万字生产计划

第一阶段不必立刻建表，可以先以项目配置 JSON 形式保存：

```ts
MillionNovelPlan {
  targetTotalWords: number
  targetChapterCount: number
  volumeCount: number
  batchSize: number
  chapterWordRange: [number, number]
  checkpointInterval: number
  qualityGatePolicy: Record<string, unknown>
  humanReviewPolicy: Record<string, unknown>
}
```

默认值：

- `batchSize = 10`
- `checkpointInterval = 10`
- `chapterWordRange = [2800, 3500]`
- 每批抽检 2-3 章。

### 4.2 批次运行阶段

每个批次应有固定阶段：

| 阶段 | 含义 |
|---|---|
| plan | 补齐本批章节合同和场景合同 |
| draft | 逐章生成正文 |
| gate | 逐章跑章节门和合同兑现验证 |
| canon | 准备或确认状态回写 |
| checkpoint | 形成批次记忆和质量摘要 |
| paused | 等待用户处理阻塞 |
| completed | 本批可进入下一批 |

### 4.3 批次质量总灯

进入下一批前必须检查：

- 章节门 ready 率 >= 90%。
- 合同兑现 blocker = 0。
- Canon 回写待确认 <= 3 章。
- AI 味跨章复现率 <= 10%。
- 向量召回连续降级 <= 2 章。
- 超期伏笔/支线没有未处理项。

如果不达标，批次进入 `paused`，并生成任务中心修复任务。

### 4.4 执行策略

- 合同和场景计划可以批量准备。
- 正文生成默认按章节顺序执行。
- 如果某章失败，不应污染后续章节；失败章进入 `blocked` 队列。
- 已通过的章节和已确认的回写不得被自动重跑覆盖。

## 五、建议新增数据结构

P2 阶段建议新增：

```ts
novel_generation_batches {
  id
  novelId
  volumeId
  chapterStart
  chapterEnd
  status
  qualityPolicyJson
  summaryJson
  startedAt
  completedAt
}
```

第一阶段可以先复用 `tasks`，把批次信息写入 `inputJson/outputText/recoveryHintJson`。

## 六、实施步骤

1. 在创作总览增加“百万字生产设置”：总字数、章节数、每批数量、checkpoint 间隔。
2. 在任务中心增加批次任务视图，聚合本批所有子章节任务。
3. 为批次执行定义状态机：`plan -> draft -> gate -> canon -> checkpoint -> completed`。
4. 接入质量总灯，未达标时阻止自动进入下一批。
5. 每批结束自动生成 `story_memory_checkpoint` 和批次摘要。

## 七、验收标准

- 用户能看到当前处于第几卷、第几批、第几章。
- 批次可以启动、暂停、恢复、失败重试。
- 单章失败不会导致整批状态不可用。
- 进入下一批前系统能明确给出“可继续 / 需修复”的总灯。
- 批次结束后能追溯本批生成质量、状态回写和主要风险。

## 八、风险与建议

- 不建议第一版就做全自动 100 万字一键生成，风险太高。
- 先支持 3 章试生产，再支持 10 章批次，最后再扩展到整卷。
- 批次状态必须可中断和可恢复，否则长任务失败后用户成本过高。
