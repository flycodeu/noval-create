# P1 - 适配器缺失重试与上下文窗口感知

> 优先级：P1（严重问题）
> 影响范围：多模型适配质量
> 实现难度：中

---

## 问题

1. **阿里通义和百度文心适配器未接入 `executeManagedRequest` 重试机制**：OpenAI/Anthropic/DeepSeek 适配器通过 `executeManagedRequest` 获得了超时管理和网络级自动重试，但 `AliyunAdapter` 和 `BaiduAdapter` 直接裸调 `fetch`，网络波动时整章丢失。

2. **`BaseAdapter.countTokens()` 仍使用粗糙的 `Math.ceil(text.length / 1.5)`**：`context.service.ts` 中已修正为中英分类计算（误差 10%），但 `BaseAdapter.countTokens()` 仍然使用旧公式。`task.service.ts` 的 `tokensUsed` 统计依赖此方法，导致 token 用量统计失真 20-30%。

3. **各适配器的 `maxContextTokens` 硬编码且不可配置**：`CustomAdapter` 固定 32000、`BaiduAdapter` 固定 8192，但用户可能使用的模型窗口大小不同（如 Ollama 运行 128K 模型）。系统没有根据 `maxContextTokens` 自适应调整上下文预算，可能导致小窗口模型收到超长 prompt 而截断。

## 原因

- `AliyunAdapter` 和 `BaiduAdapter` 早于 `request-support.ts` 编写，未同步接入
- `BaseAdapter.countTokens()` 在第一轮修复中被遗漏
- `maxContextTokens` 目前未在 `context.service.ts` 的预算分配逻辑中使用

## 解决方式

1. 将 `AliyunAdapter` 和 `BaiduAdapter` 的 `chat()` / `stream()` 接入 `executeManagedRequest`，百度的 access token 拉取也纳入统一超时与网络重试管理
2. 将 `BaseAdapter.countTokens()` 升级为与 `context.service.ts` 一致的中英分类估算，修正任务 token 统计失真
3. 为 `model_configs` 增加可配置的 `max_context_tokens`，模型管理页支持编辑，并在 `buildChapterContext()` 中按模型窗口大小夹紧预算；任务执行默认也会尊重模型配置里的 `maxTokens`

## 是否解决

已解决

## 预期效果

- 所有适配器均有重试保护，网络波动不会丢章
- token 统计误差从 20-30% 降至 10% 以内
- 小窗口模型不再收到超长 prompt
