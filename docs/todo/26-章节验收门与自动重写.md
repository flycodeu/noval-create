# 章节验收门与自动重写

## 一、目标

把章节门从“发布前检查清单”升级为“自动重写调度器”。章节门发现合同失败、POV 漂移、AI 味复现、支线空转等问题后，应能生成范围明确的重写任务。

## 二、修复状态

- 已完成 RewritePlanner 落地：`context-impact.service.ts` 已把章节门失败项映射为结构化 `rewritePlan`，输出 `scope / targetSegmentId / targetExcerpt / goals / preserve / recheckItems`。
- 已完成 任务元数据接线：章节门生成的 `revision_tasks.originMetaJson` 已写入 `rewritePlan`、复检项和自动修复开关，合同重排类任务会自动降级为人工处理。
- 已完成 修订中心自动执行：`revision-task.service.ts` 已能识别章节门重写计划，记录 `rewriteAttempts / maxRewriteAttempts / lastRecheckFailedItems`，并在重写上限后转人工确认。
- 已完成 发布后定向复检：章节门结果会返回推荐重写粒度，章节流水线失败信息已优先采用 `rewritePlan.scope` 和 `targetSegmentId`，不再只按“整章/场景”粗分。
- 已完成 回归验证：`context-impact.service.test.ts` 已覆盖 `scene_rewrite / paragraph_patch / scene_rewrite(contract)` 等映射和任务元数据落库。

## 三、当前已完成

- `chapterGateRuns` 已持久化章节门结果。
- 章节门已覆盖正文、摘要、连续性、上下文版本、AI 体检、审校、主角节奏、场景计划、召回、合同兑现、对白、POV、钩子、线程推进等。
- `chapter.service.ts` 已支持生成后强制修复和 Rewriter。
- 锁定段落保护已存在。

## 四、当前缺口

- 验收门主要给结论和修复方向，不一定能自动把失败项转成局部重写任务。
- AI 味能触发修复，但合同失败、POV 失败、支线推进失败的自动重写策略还不够细。
- 重写后需要复跑同一验收项，直到通过或进入人工确认。

## 五、详细设计

### 4.1 RewritePlanner

新增 `RewritePlanner`。

输入：

- 章节门失败项。
- 合同验证结果。
- 审校意见。
- 锁定段落。
- 场景合同和场景计划。

输出：

```ts
RewritePlan {
  scope: 'paragraph_patch' | 'scene_rewrite' | 'chapter_rewrite' | 'contract_replan'
  targetSegmentId?: number
  targetExcerpt?: string
  goals: string[]
  preserve: string[]
  recheckItems: string[]
}
```

### 4.2 重写粒度

| 粒度 | 适用场景 |
|---|---|
| paragraph_patch | 套话、非自然搭配、少量解释腔 |
| scene_rewrite | POV 漂移、场景目标未完成、冲突弱 |
| chapter_rewrite | 整章结构偏离、合同大面积缺失 |
| contract_replan | 合同本身不可执行或互相冲突 |

### 4.3 复检策略

- AI 味：复跑 guardrails 和 language drift。
- 合同失败：复跑 ChapterContractValidator。
- POV：复跑 PerspectiveController。
- 状态失败：复跑 Canonizer diff 或状态跳变检查。
- 对白失败：复跑 dialogue fingerprint。

### 4.4 与修订中心集成

- 自动重写任务写入 `revision_tasks`。
- 用户可以选择自动执行、人工编辑或退回合同。
- 自动重写不得覆盖锁定段落。

## 六、实施步骤

1. 将章节门失败项映射为 rewrite reason。
2. 新增 RewritePlanner，生成重写计划。
3. 将重写计划接入 Rewriter。
4. 重写后自动复跑对应验收项。
5. 多次失败后转人工确认。

## 七、验收标准

- 章节门失败能生成可执行重写任务。
- 重写范围明确，不默认整章重写。
- 锁定段落不会被改动。
- 重写后自动复检。
- 连续重写失败能转人工，而不是无限循环。

## 八、风险与建议

- 不要所有 warning 都触发重写，避免过度自动化。
- 局部重写要保证上下文衔接，否则会修局部坏整体。
- 合同失败严重时应退回 Planner，不要强行润色。
