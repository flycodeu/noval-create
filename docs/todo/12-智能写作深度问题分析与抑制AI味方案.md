# 智能写作深度问题分析与抑制 AI 味方案

> 生成日期：2026-04-15  
> 范围：NovelForge 小说生成管线整体健康度  
> 目标：识别当前 AI 写作流程的结构性缺陷，给出可落地的抑制 AI 味、贴近真人写作的改造方案

---

## 一、总体诊断结论

NovelForge 已经构筑了一个非常完整的"结构化上下文 + 多维审校"体系（10 张数据表、60+ services、46 条内容护栏规则、5 项语言漂移指标），但从真实成稿质量角度看，**核心瓶颈不在"检测能力"，而在"生成闭环"**：

> **系统有能力识别 AI 味，但几乎不会在生成之前主动压制 AI 味；能识别问题却不能把问题反哺进下一次硬约束。**

具体表现为 5 大维度的系统性弱点，优先级排序如下：

| # | 维度 | 现有覆盖 | 强制性 | 反馈闭环 | 紧急度 |
|---|------|---------|--------|----------|--------|
| 1 | 剧情/步骤关联 | 50% | 低 | 仅审校后 | 🔴 P0 |
| 2 | 上下文关联 | 70% | 低 | 无 | 🔴 P0 |
| 3 | AI 味检测 | 60% | 无（仅检测） | 部分 | 🔴 P0 |
| 4 | 提示词设计 | 50% | 部分 | 无 | 🟡 P1 |
| 5 | 视角/感官多样性 | 20% | 无 | 无 | 🟡 P1 |

---

## 二、维度一：上下文关联缺陷（Context Correlation）

### 2.1 先验文本馈送严重不足

- **位置**：`electron/services/context.service.ts:2230`
- **现状**：上一章仅以 `previousChapter.content.slice(-300)` 形式馈入 prompt
- **问题**：对于 2000～5000 字章节，馈送覆盖率仅 5–15%。AI 拿不到章节中段伏笔、转折铺垫、节奏轮廓
- **后果**：
  - 伏笔→回收链断裂，经常在新章"生硬接入"上一章未提及的事物
  - 同一场景出现"同一动作被写两遍"、"同一情绪被重复揭示"
  - 情节节奏感跨章失控（上一章刚到高潮，下一章冷启动）

### 2.2 角色状态追踪停留在章节粒度

- **位置**：`context-impact.service.ts:80-200`、`character-state.service.ts`
- **现状**：状态字段记录 `第 N 章：X 状态`，缺少 `在事件 E 之后进入 Y 状态` 的事件锚点
- **问题**：章节内多次转折（交战→受伤→觉醒）被塌缩成一个终态，因果链丢失
- **后果**：下一章开头常出现"角色状态跳变"——上一章最后他还愤怒，这一章开头已经平静，且无解释

### 2.3 向量召回降级不可监控

- **位置**：`context.service.ts:2341-2345`
- **现状**：向量服务失败时静默降级到结构化状态
- **问题**：没有记录"本次生成是否用了召回""召回命中率"，降级导致的结构漂移对用户不可见
- **风险**：连续多章可能在嵌入服务异常时全部走结构化兜底，隐性质量下滑

### 2.4 改造方案

1. **分层先验文本**：上一章必须馈入 ≥ 1000 字（场景切点、对话、决策点按重要性采样），而不是结尾 300 字
2. **事件锚点化状态卡**：`character-state` 表补充 `triggerEventId`、`stateDelta`，在 prompt 中以因果链形式注入
3. **召回质量打点**：每次生成记录 `retrievalUsed / retrievalHitCount / fallbackReason`，在质量仪表盘可追溯

## 三、维度二：步骤/剧情关联缺陷（Plot Correlation）

### 3.1 场景节拍无强制验证

- **位置**：`story-prompts.ts:84-96`、`chapter.service.ts`
- **现状**：prompt 要求"每个场景含开场动作、冲突、悬念"，但**没有任何生成后验证机制**
- **后果**：AI 频繁输出"思考 + 对话"型弱场景，完全跳过物理动作、冲突升级

### 3.2 支线回收链条松散

- **位置**：`subplot.service.ts:55-135`、`context-cards.ts:586-628`
- **现状**：有 `targetPayoffChapter` / `lastReferencedChapter` 字段，但只提示"已 N 章未提及"
- **问题**：
  - "提及"与"推进"未区分，AI 把提及一个名字当作推进
  - `payoffCondition` 多为抽象短语（"冲突升级"），无法翻译成具体场景诉求
- **后果**：同一条支线反复悬空警告却始终未推进

### 3.3 审校→生成的反向闭环缺失

- **位置**：`story-prompts.ts:149-184`（review prompt）
- **现状**：审校阶段有 20+ 检查点（代价兑现、悬念曲线、追读风险等），但这些**只在事后生效**，并未写入下一次生成的硬约束
- **后果**：同样的问题（如"代价蒸发"）在多章之间反复复现

### 3.4 改造方案

1. **章节合同校验器（ChapterContractValidator）**：
   - 生成后自动提取：冲突点数量、支线推进次数、伏笔引用、人物压力值变化
   - 未达标 → 自动触发局部重写而非人工审校
2. **支线推进硬约束**：context 注入时明确"本章必须推进 X 条支线、提及 Y 条"，而不是柔性建议
3. **审校结果回写机制**：`chapterGateRuns` 中的复现问题（出现 ≥ 2 次）自动写入下一章 prompt 的 `【必须避免】` 段

## 四、维度三：AI 味检测缺陷（AI-ness Detection）

### 4.1 检测是事后的、被动的

- **位置**：`ai-score.service.ts:53-68`
- **现状**：正则/关键词检测发生在生成**之后**
- **后果**：能识别"心中涌起一股""命运的齿轮"等 20+ AI 套话，但生成阶段从未把这些作为禁用词投喂给模型
- **最低成本改进**：把 `ai_slogan` + `ai_emotional_cliche` 列表直接合并进 system prompt 的 `【禁用表达】` 白盒注入

### 4.2 检测维度偏浅

- **位置**：`content-guardrails.ts:10-146`、`language-drift.ts:10-52`
- **问题**：
  - **假阴性**：换个词即可绕过（"紧紧握住"→"用力握"，套路骨架未变）
  - **假阳性**：部分规则对文艺/环境描写本就合理（"微风拂过"不是问题）
  - **结构级 AI 味盲区**：铺陈→转折→金句三段式、无真实决策的独白链，现有检测全部抓不到
  - 修饰词表仅 30 项，抽象词表仅 31 项，远不及中文网文陈词滥调真实规模（数百项量级）

### 4.3 风格指纹"分析"与"应用"脱节

- **位置**：`style-analysis.service.ts:38-178`、`context.service.ts:2284`
- **现状**：参考文本仅抽样 8000 字前 4 块；抽取出的 `forbiddenPatterns` 进入 `styleTemplateSummary` 文本，但**无硬约束**确保生成遵循
- **后果**：用户精心导入的风格参考，几乎只起到"背景氛围"作用，并未真正改变输出

### 4.4 改造方案

1. **前置抑制**：
   - 建立动态"禁用词/禁用句式"库（初始种子 100+ 条），按章节注入 prompt 的 `【硬约束-不得出现】`
   - 对高频 AI 搭配（如 "X 的 Y"+"Z 之间"）使用 ngram 统计检测
2. **中深层检测补强**：
   - **中层**：章节内 ngram 重复率、段落结构相似度（检测"换词不换骨"）
   - **深层**：段落功能序列分析（铺陈/动作/对话/独白的组合模式是否过度规整）
3. **风格指纹硬约束化**：`forbiddenPatterns` 从文本建议升级为 prompt 的 `【必须避免】` 段，并在生成后做命中率检查
4. **复现率反馈闭环**：统计每种 AI 味类型的跨章复现率，复现 ≥ 2 章自动升级为 P0 禁用

## 五、维度四：提示词设计缺陷（Prompt Design）

### 5.1 全是"负向列举"，缺正向范例

- **位置**：`story-prompts.ts:125-135`
- **问题**：大量"不要 X""避免 Y"，但没有"应为 Z"的具体示例
- **后果**：AI 理解"不要华丽"，但容易矫枉过正（变成干瘪流水账）或视而不见

### 5.2 硬约束与建议无优先级区分

- **位置**：`story-prompts.ts` 的 `appendPromptSection`
- **现状**：所有内容都用 `【】` 包裹，在 token 预算紧张时被平等截断
- **风险**：真正的硬约束可能被 prompt 长度压缩"踢出"生成视野（现 prompt 常突破 15k token）

### 5.3 中文网文特有 AI 陷阱覆盖不足

- 华丽辞藻堆砌（"古老而神秘的光影在 XX 之间交错"）
- 无限扩展（一个转折写 3000 字，应该 300 字）
- 刻画过详（主角去便利店配 5 分钟心理活动）
- 单一旁白视角
- 偏离主题（本章应推主线，却跑去展开支线家族史）

上述"中文网文 AI 套路五毒"现有 prompt 几乎没有针对性抑制。

### 5.4 改造方案

1. **三级优先级标签**：
   - `【必须】`（L1 硬约束，不得截断）
   - `【重点】`（L2 建议，通常保留）
   - `【参考】`（L3 背景，token 紧张时先丢）
   - 在 `context.service.ts` 的 token 预算分配阶段按优先级分桶裁剪
2. **负向 + 正向对照**：每个禁用项附带 1 例正面改写
   - ❌ "古老而神秘的光影在雕梁间交错"
   - ✅ "阳光从破窗斜进来，落在旧档案的毛边上"
3. **章节密度控制器**：
   - 目标字数区间 + 允许偏差上限（如 ±15%）
   - 心理描写占比上限（如 ≤ 20%）
   - 环境描写占比上限（如 ≤ 15%）
   - 超过触发重写
4. **动态反 AI prompt 模板**：基于上一章检测到的问题类型，自动合成本章的"专项抑制段"

## 六、维度五：视角/感官多样性缺陷（Perspective & Sensory Variety）

### 6.1 默认第三人称全知，无 POV 管理

- **现状**：系统完全没有"谁的视角"这个字段
- **后果**：
  - 无法制造真实信息不对等 → 悬念张力骤降
  - 多角色场景变成"摄像机视角"
  - 配角秘密被全知视角直接披露，后续无戏

### 6.2 感官描写单调

- `language-drift.ts` 完全不统计感官词
- 无"一章至少覆盖视/听/触/嗅/味中的 3 种"的约束
- 生成常见"看到—听到—想了想"三段简陋结构

### 6.3 对话/动作/内心比例失衡

- 有的章节全对话（情绪判断无依据）
- 有的章节全内心（冗长无趣）
- `dialogue-fingerprint.service.ts` 只分析对话内部质量，不管全章比例

### 6.4 改造方案

1. **POV 字段化**：
   - 场景级新增 `povCharacterId`
   - prompt 注入"本场景只能展现 POV 角色可感知的信息"
   - 多角色章强制要求 ≥ 1 个配角独立 POV 段
2. **感官雷达**：
   - 生成后统计视/听/触/嗅/味 5 类命中数
   - 覆盖 < 3 类触发"补充感官描写"重写
3. **对话/动作/内心比例表**：
   - 按章节基调（高潮/推进/过渡）配置目标比例
   - 偏差 > 20% 触发结构调整

## 七、落地路线图

### Phase 1（2 周，P0 止血）

1. **上一章馈送扩容**：`context.service.ts:2230` 改为按重要性采样 1000+ 字
2. **禁用词前置注入**：把 `ai_slogan` + `ai_emotional_cliche` 合并为 prompt 硬约束段
3. **章节合同校验器 MVP**：冲突点数 / 支线推进数 / 伏笔引用数的自动抽取，低于阈值触发重写
4. **prompt 三级优先级标签**：`【必须】/【重点】/【参考】`，在 token 裁剪时按级别丢弃

### Phase 2（3 周，P1 结构补强）

5. 审校→下一章硬约束的反向闭环（`chapterGateRuns` → next prompt `【必须避免】`）
6. 事件锚点化角色状态
7. 感官雷达 + 对话/动作/内心比例表
8. 风格指纹从"文本建议"升级为"硬约束命中率检查"

### Phase 3（4 周，P2 深度 AI 味治理）

9. POV 字段与多角色章强制 POV 切换
10. ngram 重复率 + 段落功能序列检测（结构级 AI 味）
11. AI 味复现率仪表盘 + 自动升级禁用词
12. 中文网文"五毒"专项检测器（华丽辞藻 / 无限扩展 / 刻画过详 / 单一视角 / 偏题）

## 九、结论

> **问题不在于"检测得还不够多"，而在于"生成前的硬约束太少、审校后的反馈没有回流"。**

建议把 Phase 1 的四项视为"止血关键路径"——它们改造成本低（主要改 prompt 构造与 token 裁剪），但能在 2 周内把最刺眼的 AI 味症状（套话、断章、支线悬空）明显压下去。之后再逐步补齐结构级检测和 POV/感官雷达，走向真正"贴近真人写作"的输出。
