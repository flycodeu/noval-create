# P1 - 向量召回查询过窄导致关键上下文漏召回

> 优先级：P1（严重）
> 影响范围：长程一致性、背景主题对齐、伏笔回收准确度
> 实现难度：中

---

## 涉及模块

- `electron/services/context.service.ts`
- `electron/services/embedding.service.ts`
- 关联影响：章节正文生成、后续长程记忆召回

## 问题

系统已经接入向量召回，这一步本身是正确方向。  

但当前召回 query 仍然过窄，主要基于“当前章节大纲 + 当前故事弧目标”做语义检索。这会让很多真正重要、但没有直接写在当章大纲里的约束漏召回。

具体失败模式：

- 当前章节涉及某段旧关系张力，但大纲里没有明确写出关系关键词，相关历史片段没被召回
- 当前章节命中了某个世界规则禁忌，但大纲只写了事件流程，没有写规则词，旧规则片段没被召回
- 某条长期支线或母题需要回收，但因为 query 没带主题/线程信号，召回结果偏向表面剧情
- 角色、地点、物品跨卷回归时，只要大纲提法变化，历史关键片段就容易被漏掉

## 原因

`electron/services/context.service.ts` 中当前向量召回的 query 主要是：

- `currentChapter?.outline`
- `currentArc?.arcGoal`

随后直接调用 `findSimilarFragments()`。

这说明召回能力已经存在，但检索信号仍然缺少以下重要维度：

- 活跃线程标题与回收位
- 当前章节提及的人物/地点/物品名
- 关系摘要与冲突摘要
- 主题关键词、母题关键词
- 世界规则中的禁忌、代价、边界条件

## 为什么前三轮修复后仍然可能发生

前三轮把“最近章节上下文”和“长文记忆摘要”做强了，也把向量召回能力接进来了。  

但召回是否好用，不只取决于有没有 embedding，还取决于 query 是否真正代表“当前最需要找回什么”。这一层在前三轮里还没有被系统化补完。

## 解决方式

1. 把召回 query 改成多信号拼装，而不是只用大纲和弧目标
2. 至少引入以下召回信号：
   - 章节目标
   - 当前弧目标
   - 活跃线程标题
   - 章节提及的人物/地点/物品名
   - 关系冲突摘要
   - 主题/母题关键词
   - 世界规则冲突点
3. 按类型分桶召回：
   - 角色相关记忆
   - 规则/背景相关记忆
   - 线程/伏笔相关记忆
4. 对召回结果做简化重写，只把最关键的 1-2 行约束送进最终 prompt，避免检索命中后又被冗长文本淹没

## 是否解决

未解决 — 2026-04-05（第五轮新增）

当前状态：半闭环

- 系统已经具备向量召回能力
- 但 query 设计仍偏窄，尚未形成“背景/主题/关系/规则”多信号检索

## 预期效果

- 跨卷角色、地点、物品、规则能在真正需要时被更稳定地召回
- 主题回收和长期伏笔不再过度依赖“是否刚好写在本章大纲里”
- 背景偏移、关系失真、规则遗漏会在召回层提前减少
