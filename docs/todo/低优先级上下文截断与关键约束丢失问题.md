# 低优先级上下文截断与关键约束丢失问题

关联总文档：[百万字小说生成问题分析与扩展方案](./百万字小说生成问题分析.md)

## 1. 问题定义

当前章节上下文分配依赖预算和优先级。在预算不足时，低优先级上下文会被截断或直接丢弃。对于百万字项目，这会造成“并非不重要，但只是没排到高优先级”的关键约束消失。

## 2. 当前代码现状

- `electron/services/context.service.ts` 中 `allocateChapterContext` 会按 `priority` 分配预算。
- 同文件中 `createStagePriorityMap` 会根据 `scenePlan / draft / review / rewrite` 设定不同上下文优先级。
- 当预算不足时，会出现 `truncated` 或 `dropped` 的上下文警告。
- 长篇时会提高部分上下文优先级，但不会改变“上下文块竞争预算”的基本模型。

## 3. 目前已解决 / 部分解决 / 未解决

- 已解决：系统已经具备预算控制和优先级策略。
- 部分解决：长篇时会提高 `longTermMemory` 等块的优先级。
- 未解决：不存在“绝不能被裁掉”的硬约束层。

当前判断：`部分解决`

## 4. 潜在风险

- 关键角色关系约束在某一章被裁掉，角色说话或行为突然失真。
- 关键伏笔、长期限制、地图与资源边界被裁掉后，正文出现低级违和。
- 用户会感受到“明明系统前面知道，后面怎么又忘了”。

## 5. 原因分析

- 当前上下文系统仍然围绕 token 预算展开。
- 所有信息都以“块”的形式参与竞争，没有强弱约束分层。
- 优先级是经验分配，不是事实等级分配。

## 6. 扩展方案

- 将上下文分成“硬约束”和“软参考”两层。
- 硬约束包括：角色当前伤势、关键关系、关键物品去向、必须回收伏笔、章节目标。
- 软参考包括：风格模板、部分历史摘要、非关键背景补充。
- 为硬约束设置独立预算，不参与普通块竞争。

## 7. 建议的数据结构 / 指标 / 页面能力

- `hardConstraintContext`：不可裁剪上下文区。
- `softContextBudgetUsage`：软上下文预算使用率。
- `droppedConstraintCount`：被裁掉的重要约束计数，应始终为 0。
- 写作页新增“本章关键约束已注入”可视提示。

## 8. 实施优先级

等级：`S级`

等级说明：关键约束会掉块，不先收敛会持续放大其他问题。

原因：这是所有连贯问题中最容易在长篇场景放大的技术原因。

## 9. 验收标准

- 生成链路中新增硬约束层，且不被普通预算裁剪。
- 关键状态在章节生成时可追踪是否注入成功。
- 上下文告警里不再出现关键状态被丢弃的情况。
- 高价值角色、物品、关系、伏笔的错写率明显下降。
