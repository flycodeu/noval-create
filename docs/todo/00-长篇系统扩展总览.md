# 长篇系统扩展总览

## 一、目标

把当前系统从“已经具备长篇底盘的 AI 小说工作台”，扩成“可以稳定推进百万字长篇”的结构化创作系统。重点不是新增更多页面，而是补齐长篇真正依赖的收束、弧线、合同、回写和门禁。

## 二、当前代码已覆盖能力摘要

- 已有全书级底盘：基础信息、项目立项、基础设定、主题与文风、世界规则。
- 已有第一版 `终局设计`：独立页面、`endgame_design` 字段、工作流就绪度、上下文与时间轴摘要接入。
- 已有中观结构：故事设计、故事大纲、结构规划、时间轴、故事线程。
- 已有章节生产流水线：`planning -> drafting -> reviewing -> rewriting`。
- 已有章节发布检查：写作页在标记完成前会执行 `runChapterPublishCheck`。
- 已完成四级 `章节验收门`：覆盖 `通过 / 预警 / 阻塞 / 退回重写`，并补齐 POV、钩子、线程推进、卷目标一致性和修订任务联动。
- 已有伏笔相关基础：`story_threads` 包含 `plantedChapter / targetPayoffChapter / resolvedChapter`，并提供 `getForeshadowSnapshot`。
- 已有状态回写基础：章节后会刷新 `characterStateVersions`、`worldStateVersions`、时间线锚点、故事记忆和部分实体发现。
- 已有质量基础：对白指纹、语言漂移、代价蒸发、召回风险、状态风险、故事弧推进预警。
- 已有上下文分层基础：硬约束、软上下文、故事核心、当前弧线、人物状态、世界状态、伏笔压力、时间轴、长期记忆。

## 三、当前关键缺口

- 当前核心模块已全部收口，后续主要进入验收阈值、纵向趋势和审计细化。

## 四、优先级

| 优先级 | 模块 |
| --- | --- |
| P0 | 无 |
| P1 | 已完成模块的自动验收、联动回写与审计细化 |
| P2 | 纵向趋势分析与门禁漂移监控 |

## 五、建议实施顺序

1. 继续细化已完成模块的自动验收、联动回写与审计能力。
2. 再补纵向趋势分析和门禁漂移监控。

## 八、推荐长篇流程

基础信息 -> 项目立项 -> 基础设定 -> 主题与文风 -> 世界规则 -> 终局设计 -> 人物弧线中心 -> 地图结构 -> 物品装备 -> 角色系统 -> 成长资源代价系统 -> 信息差与谜题板 -> 伏笔与回收账本 -> 故事线程 -> 故事设计 -> 卷级设计 -> 结构规划 / 时间轴 / 大纲 -> 章节合同 -> 场景合同 -> 正文写作 -> 自动审校 -> 章后状态回写 -> 修订中心 -> 质量监控 -> 卷后审计

- `卷后审计 / 长线债务清理` 暂不单独拆文件，先并入 `卷级设计中心` 与 `章节验收门` 的后续扩展范围。
- 所有模块状态判定统一使用本目录文档中的 `状态` 字段，不再口头判断。
