# 信息差与谜题板

## 一、目标

管理长篇里最关键的可读性变量：谁知道什么、读者知道什么、真相何时揭示、假线索何时撤销。

## 二、当前已完成

- [x] `story_threads` 已支持 `mystery` 类型线程。
- [x] `timeline_events` 能记录事件先后与章节锚点。
- [x] 正文写作已支持 POV、上下文、审校、召回风险的部分约束。

## 三、当前未完成

- [ ] 没有独立 `信息差与谜题板` 页面。
- [ ] 没有谜题、线索、真相、假线索的独立数据模型。
- [ ] 没有“读者已知 / 主角已知 / 角色已知 / 禁止提前透露信息”字段。
- [ ] 没有卷级真相揭示比例控制。
- [ ] 没有写作前的“本章允许揭示什么”约束。

## 四、为什么现在要补

- 事件很多，不等于悬念成立。
- 没有信息差管理时，AI 很容易把真相说太早，或一直拖而不揭示。

## 五、建议新增内容

- 新增页面：`信息差与谜题板`
- 新增对象：
  - `谜题`
  - `线索`
  - `真相`
  - `假线索`
- 每条对象至少维护：
  - `当前状态`
  - `读者视角已知`
  - `角色视角已知`
  - `禁止提前透露信息`
  - `目标揭示章节 / 卷`

## 六、页面与交互

- 以看板方式展示 `已出现 / 半揭示 / 待回收 / 已解释`。
- 支持从时间轴、故事线程、章节合同跳转。
- 支持按角色视角过滤已知信息。
- 支持输出“本卷必须揭示的真相比例”提醒。

## 七、数据结构 / 状态字段

- 建议新增：
  - `mystery_boards`
  - `mystery_clues`
  - `reveal_rules`
- v1 最少字段：
  - `mysteryTitle`
  - `clueType`
  - `status`
  - `readerKnown`
  - `heroKnown`
  - `characterKnownIds`
  - `forbiddenEarlyReveal`
  - `targetRevealChapter`
  - `fakeLead`

## 八、与现有模块的关系

- `故事线程` 继续承载故事线。
- `信息差与谜题板` 负责管理揭示顺序。
- `章节合同 / 场景合同` 负责落地“本章揭示哪些信息”。
- `章节验收门` 负责阻止提前泄露或解释过量。

## 九、验收标准

- 能独立维护谜题、线索和真相状态。
- 能区分读者已知与角色已知。
- 能在章节合同中引用“本章可揭示信息”。
- 能在质量监控中识别“真相拖延过久”与“提前泄露”。
