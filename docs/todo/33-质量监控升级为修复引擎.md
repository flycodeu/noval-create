# 质量监控升级为修复引擎

## 一、目标

把 `质量监控` 从“发现问题的看板”升级为“发现问题后直接推动修复的引擎”。每个风险点都要尽可能回答三个问题：

- 为什么会发生
- 应该怎么修
- 现在可以直接执行什么动作

## 二、为什么现在要做

现有质量页已经能识别大量长期风险，但作者发现问题后还要跳回多个页面才能处理。对高频使用来说，这会显著降低质量页的进入意愿。

## 三、当前已覆盖基础

- `27-质量仪表盘与百万字健康指标` 已提供能否继续下一批的总灯和批次健康汇总。
- `26-章节验收门与自动重写` 已经能把一部分问题落成自动重写任务。
- `20-审校反哺与复现率闭环` 已能把复现问题前置到后续章节和质量面板。
- 现有质量页已覆盖语言、对白、结构推进、召回、状态等基础维度。

边界说明：

- `27-质量仪表盘与百万字健康指标` 已完成健康汇总层，负责“是否继续下一批”的生产视角。
- 本文档负责解释、建议和动作层，不回写 `27` 的完成状态。

## 四、待办拆分

- [x] 为每类风险增加“原因解释 + 修法建议 + 直接动作”三段式输出。
- [x] 新增承诺兑现率指标，追踪立项承诺、卷承诺、章节承诺的兑现情况。
- [x] 新增角色声音区分度指标，并与对白修订动作绑定。
- [x] 新增成长-代价平衡指标，识别收益空转与代价蒸发。
- [x] 新增伏笔债务压力指标，并与回收推进或延期标记动作绑定。
- [x] 新增世界状态漂移指标，并可直接触发状态同步或允许偏移。
- [x] 新增信息揭示节奏指标，并可直接触发补桥段、延后揭示或修订场景。
- [x] 为每类风险提供统一动作：生成修订建议、重写场景、补写过桥、同步时间轴、更新角色状态、标记允许偏移。

## 五、详细设计

### 5.1 指标升级方向

新增重点指标：

- 承诺兑现率
- 角色声音区分度
- 成长-代价平衡
- 伏笔债务压力
- 世界状态漂移
- 信息揭示节奏

### 5.2 动作模型

所有风险点至少能落到以下动作之一：

- 生成修订建议
- 重写这一场景
- 补写一段过桥
- 同步时间轴
- 更新角色状态
- 标记为允许偏移

### 5.3 与现有体系联动

质量页负责给出解释和动作入口，真正的执行仍复用：

- `revision-task.service.ts`
- `chapter.service.ts`
- `context-impact.service.ts`

## 六、验收标准

- 作者在质量页发现问题后，可以直接触发至少一种修复动作。
- 风险项不再只有分数和热力图，还能解释成因与修法。
- 高风险指标能直接落入修订中心或章节重写链路。
- 质量页成为高频入口，而不只是排障页。

## 七、风险与建议

- 不要把所有风险都默认映射成自动重写，避免过度修复。
- 修法建议要尽量具体，避免回到泛泛而谈的审校文案。
- 允许偏移必须是显式动作，避免系统自动吞掉 intentional deviation。
