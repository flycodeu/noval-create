# 42 - 小说生成工作区界面整改计划

## Goals

- 让小说生成工作区在桌面端突出“写作主任务”，在平板与手机端优先保证可读、可写、可返回。
- 收敛顶栏、侧栏、正文区之间的职责边界，减少重复信息、重复入口和层级竞争。
- 用可持续的组件拆分和样式 token 整理，降低 `src/pages/Novel/index.tsx` 与 `src/pages/Novel/Writing/index.tsx` 的继续膨胀风险。
- 将关键交互状态做成可感知、可持久、可验证的系统反馈，而不是依赖用户自行推断。

## Confirmed Problems

1. 移动端与平板端外壳仍长期保留完整侧栏横排，占用首屏。
2. 写作工作区没有形成明确的编辑器主导关系，正文区容易被工具区挤压。
3. 顶栏承载项目身份、导航、状态、操作过多，层级混乱。
4. 侧栏重复展示身份与状态信息，与顶栏形成冗余。
5. 侧栏视觉密度高于主画布，导致注意力错误偏向导航而非创作。
6. 宽屏下编辑纸张两侧留白失衡，中央焦点弱。
7. 多层 sticky 叠加，产生遮挡、跳动和滚动负担。
8. 导航提示同时存在侧栏、顶栏、面包屑式引导和局部提示，方向不一致。
9. 工具动作过度依赖 Modal，打断写作连续性。
10. 侧栏展开态不持久，用户每次进入或切换后都要重复整理界面。
11. 模块切换反馈弱，用户难以感知“已经切换成功”“正在加载什么”“当前处于哪一层”。

## Target Experience Direction

- 桌面端采用“稳定外壳 + 单一主焦点”模型：项目级导航退居左侧，章节写作成为中央唯一主舞台。
- 平板端采用“可收合导航 + 单列内容优先”模型：默认展示内容，导航与工具按需抽屉化。
- 手机端采用“任务流”模型：默认只保留必要标题、返回、保存状态与当前主动作，不保留永久多列结构。
- 顶栏只承担全局身份、关键状态与少量高频动作；模块内操作下沉到对应页面局部工具条。
- 用户在任何尺寸下都能立即判断三件事：我在哪个项目、我现在在哪个模块、我下一步最合理的动作是什么。

## Shell Layout Changes

### `src/pages/Novel/index.tsx`

- 将页面壳层重构为三段职责：`shell frame`、`navigation rail/drawer`、`content viewport`，避免顶栏和侧栏互相注入项目摘要。
- 移除移动端/平板端“完整侧栏常驻一行”的布局，改为 `< 1024px` 默认折叠侧栏，使用抽屉或覆盖层进入。
- 统一只保留一个 sticky 顶层容器；模块内二级操作条改为局部吸附或随内容滚动，不再与顶栏叠加。
- 在壳层引入模块切换过渡状态：进入 loading skeleton、模块标题淡入、当前导航项 active bar 过渡。
- 将侧栏展开态、最近打开模块、上次写作视图写入持久存储，至少覆盖刷新、重启、路由返回三类场景。

### `src/components/novel/layout/ProjectTopbar.tsx` / `ProjectTopbar.css`

- 顶栏内容收敛为四类：返回/项目名、当前模块标题、保存/生成状态、2-3 个最高频动作。
- 移除或下沉重复状态块，例如项目阶段、重复计数、次级说明，不再与侧栏信息头并存。
- 压缩顶栏高度与垂直层级，避免多行信息堆叠；宽屏保持单行，窄屏允许拆成“主标题行 + 状态行”两层。
- 将低频操作从顶栏按钮迁移到页面内工具区或侧边面板，不再优先使用 Modal 打断主流程。

### `src/components/novel/layout/ProjectSidebar.tsx` / `ProjectSidebar.css`

- 侧栏改成“轻量项目导航”而不是“信息公告板”，保留模块列表、当前进度摘要、少量上下文提示。
- 删除与顶栏重复的项目身份、状态、说明文案，只保留一处主身份展示。
- 降低侧栏密度：减少字号混用、缩短说明文字、增大导航项留白，让主画布成为视觉重心。
- 支持 collapsed / expanded / drawer 三态，并把 expanded 状态持久化。
- 为当前模块、最近访问模块、存在未完成任务模块提供明确但克制的视觉区分。

### `src/styles/global.css`

- 补齐工作区级 token：壳层高度、顶栏高度、侧栏宽度、编辑器理想宽度、抽屉层级、overlay 背景、过渡时长。
- 统一 sticky z-index 语义层，明确 shell 顶栏、局部工具条、抽屉、popover、modal 的层级顺序。
- 增加响应式断点 token，至少区分手机、平板、标准桌面、超宽桌面四档布局。

## Writing Page Redesign

### `src/pages/Novel/Writing/index.tsx`

- 明确页面主次结构为：`chapter header`、`editor canvas`、`assist panel`，其中正文编辑器始终优先占据横向与视觉主导。
- 将当前写作页拆为“主编辑区”和“可切换辅助区”；辅助区默认收起或窄栏展示，避免长期压缩正文宽度。
- 宽屏改为基于 `editor sheet + flexible gutters + optional side panel` 的布局，保证正文列稳定落在舒适阅读宽度，而不是被固定边栏挤压。
- 顶部仅保留章节标题、保存状态、核心生成动作；历史、上下文、审校等工具转移到辅助区标签或内联面板。
- 用内嵌面板、底部抽屉或右侧滑出替代高频 Modal，例如上下文预览、质量提醒、快捷操作，减少写作中断。
- 为模块切换、章节切换、生成中、保存中、恢复断点等状态提供连续反馈，至少包含可见文案、骨架态或轻量动画。

## Responsive Strategy

- `>= 1440px`：侧栏可展开，编辑器宽度锁定在理想阅读区间，辅助面板按需显示，左右留白保持对称。
- `1024px - 1439px`：侧栏默认窄态，辅助面板默认收起，编辑器保持绝对优先。
- `768px - 1023px`：导航改为抽屉，顶栏简化为返回、标题、状态、主动作，正文单列展示。
- `< 768px`：仅保留任务流必需控件；章节工具、上下文、历史等以分段面板或底部抽屉进入。
- 所有断点都禁止“完整侧栏横向常驻 + 主内容被压缩”的折中状态。

## Component/File Responsibilities

- `src/pages/Novel/index.tsx`
  - 负责项目级壳层、路由出口、响应式布局模式切换、侧栏持久状态与模块过渡反馈。
- `src/pages/Novel/Writing/index.tsx`
  - 负责写作页的信息架构重排、编辑器主导布局、辅助面板切换策略与写作态反馈。
- `src/components/novel/layout/ProjectTopbar.tsx`
  - 只负责全局身份、关键状态和最高频动作，不再承载模块内部复杂工具。
- `src/components/novel/layout/ProjectTopbar.css`
  - 负责顶栏高度、响应式折行、状态密度和交互动效样式。
- `src/components/novel/layout/ProjectSidebar.tsx`
  - 只负责模块导航、少量进度提示、展开收起逻辑与持久化交互。
- `src/components/novel/layout/ProjectSidebar.css`
  - 负责三态侧栏样式、低密度导航节奏、当前项与最近项视觉规则。
- `src/styles/global.css`
  - 负责全局 token、断点、层级体系、工作区共享过渡与壳层尺寸变量。

## Implementation Phases

### Phase 1: Shell Simplification

- 精简 `ProjectTopbar` 与 `ProjectSidebar` 的重复信息。
- 落地单一 sticky shell，去掉多层叠 sticky 的默认结构。
- 完成侧栏三态与持久化状态接线。

### Phase 2: Writing Workspace Rebalance

- 重排 `Writing/index.tsx`，先确保编辑器主导，再接入辅助区切换。
- 将高频 Modal 工具迁入页内面板或抽屉。
- 修正宽屏下编辑纸张与留白比例。

### Phase 3: Responsive Hardening

- 针对手机、平板、标准桌面、超宽桌面逐档校正布局。
- 清理“平板保留整条侧栏”的遗留条件分支。
- 对切换反馈、抽屉开关、状态恢复做一轮交互稳定性检查。

### Phase 4: Visual Density and Feedback Polish

- 降低侧栏信息密度，提升正文区对比与节奏。
- 为模块切换、加载、保存、恢复、未完成任务补足轻量反馈。
- 统一 token 和动画时长，避免局部样式各自为政。

## Verification Checklist

- 手机与平板端默认进入页面时，不再看到完整侧栏横向常驻。
- 写作页在所有桌面断点下都保持编辑器为第一视觉焦点，辅助工具不会长期压缩正文。
- 顶栏和侧栏不再重复展示项目身份、阶段和状态摘要。
- 侧栏展开/收起状态在刷新、路由返回、应用重开后保持一致。
- 宽屏下编辑纸张左右留白基本对称，焦点稳定居中。
- 默认滚动路径中不存在两层以上同时 sticky 的长期叠加。
- 高频工具动作可以在页内完成，不必频繁弹出 Modal。
- 模块切换时有明确 active、loading 或进入反馈，用户能感知当前所在模块。
- `src/pages/Novel/index.tsx` 与 `src/pages/Novel/Writing/index.tsx` 的职责边界比当前更清晰，后续可继续拆分而不放大耦合。
