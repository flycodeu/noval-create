# 角色口吻与对白差异化

## 一、目标

避免多人对白同腔、角色语气漂移、对话只传递信息但没有人物立场。百万字长篇里，角色口吻必须能持续追踪和前置约束。

## 二、修复状态

- 已完成 本章 voice lock 生成：`dialogue-fingerprint.service.ts` 已可基于角色字段、对白指纹、关系语气和章节提及角色生成本章 `DialogueVoiceLock`。
- 已完成 生成前注入：`context.service.ts`、`prompt-library.ts`、`story-prompts.ts` 已把 `角色 Voice Lock` 独立注入 Scene Plan、Draft、Review、Rewrite prompt。
- 已完成 生成后分项检测：对白审校已拆分 `同质化 / 漂移 / 空话风险 / 信息推进密度 / voice lock 摘要`，不再混成单一信号。
- 已完成 连续复现升级：反馈复现文案已明确要求把重复对白问题升级为下一章 voice lock，连续两章同角色漂移会自动生成系统修订任务。
- 已完成 质量面板接入：质量仪表盘和写作页已显示 `需要 Voice Lock 的角色`、`voice lock 摘要`、`对白空转`、`信息密度` 风险。

## 三、当前已完成

- `dialogue-fingerprint.service.ts` 已能建立角色对白指纹。
- `chapter.service.ts` 会把对白分析写入审校意见。
- 质量仪表盘已展示对白相似度、漂移趋势、角色口吻一致性。
- 角色卡会把口头禅、用词、口音、对白画像注入上下文。

## 四、当前缺口

- 口吻约束主要依赖人物卡和审校，缺少生成前“本章出场角色 voice lock”。
- 对白比例不受章节功能控制。
- 对白自然度与信息推进没有分离。
- 角色漂移连续出现后，没有自动升级为下一章硬约束。

## 五、详细设计

### 4.1 DialogueVoiceLock

为本章出场角色生成 voice lock：

```ts
DialogueVoiceLock {
  characterId: number
  characterName: string
  mustKeep: string[]
  mustAvoid: string[]
  relationTone: string
  sampleHint: string
}
```

每个主要角色 3-5 条即可，不要过长。

### 4.2 生成前约束

注入内容：

- 这个角色常用称呼、句长、停顿方式。
- 这个角色在当前关系里的语气。
- 这个角色不会说什么。
- 同场角色之间必须拉开的差异。

### 4.3 生成后检查

检查项：

- 同场角色句长差异。
- 口头禅/称呼一致。
- 跨角色相似度。
- 近期口吻漂移。
- 对白空话比例。
- 对白信息推进密度。

### 4.4 反馈升级

- 单章同声化：写入审校意见。
- 连续 2 章同声化：下一章加入 voice lock 硬约束。
- 某角色连续漂移：重建该角色对白指纹或提醒补人物口吻字段。

## 六、实施步骤

1. 从 `dialogue-fingerprint.service` 和角色字段生成本章 voice lock。
2. 将 voice lock 注入 Writer 和 Rewriter。
3. 将对白检测结果接入反馈闭环。
4. 质量仪表盘增加“需要 voice lock 的角色”列表。
5. 对漂移角色生成修订任务。

## 七、验收标准

- 本章主要出场角色能看到 voice lock。
- 多人对话能检测同声化。
- 角色连续漂移会自动进入下一章硬约束。
- 对白规则进入生成前，而不只在审校后出现。

## 八、风险与建议

- 口头禅不能机械重复，否则会产生新模板味。
- voice lock 应限制在本章主要角色，避免 prompt 过载。
- 对白差异要服务人物关系和当前情境，不是为了差异而差异。
