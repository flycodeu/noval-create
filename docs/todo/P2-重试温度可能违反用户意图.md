# P2 - 重试温度可能违反用户意图

> 优先级：P2（中等）
> 影响范围：AI 生成质量
> 实现难度：低
> 类别：后端-任务系统

---

## 问题

`computeRetryTemperature()` 在内容重试时递增温度，但当 `baseTemperature` 为 0（确定性模式）时，重试会将温度变为 0.05、0.10 等非零值，违反了用户选择确定性输出的意图。

```typescript
function computeRetryTemperature(baseTemperature: number, attemptNumber: number): number {
  if (attemptNumber <= 1) return baseTemperature
  return Math.min(0.95, baseTemperature + (attemptNumber - 1) * 0.05)
}
```

## 原因

- `electron/services/task.service.ts:202-205` 未对 baseTemperature = 0 做特殊处理
- `retryTask()` 会把递增后的温度直接写入 `chatOpts.temperature`
- 当前模型运行时温度范围统一按 `0..1` 归一化，但重试逻辑没有显式表达零温特例

## 解决方式

1. 当 `baseTemperature` 为 0 且进入重试时，温度固定为 `0.01`
2. 非零温度继续沿用小步递增策略
3. 最终结果统一限制在 `0..1` 内，并保留现有 `0.95` 软上限

## 是否解决

已解决 — 2026-04-06

当前状态：

- 零温内容重试不再被抬到 `0.05/0.10/...`
- 手动 `retryTask()` 仍保留 variation message 机制，用来提供“重试但不完全照抄”的差异
- 底层请求级网络/限流重试不受本次修复影响

## 预期效果

- 确定性模式下的重试不会意外引入随机性
- 重试温度始终在合理范围内
