# 角色化章节生成流水线

## 一、目标

保留当前单章流水线优势，并让它成为百万字批次生成的基础执行单元。每章生成必须明确由哪个角色阶段负责，失败时能定位到合同、写作、审校、重写、回写还是收尾。

## 二、当前已完成

- `chapter.service.ts` 已形成 `Planner / Writer / Critic / Rewriter / Canonizer / Finalize` 主链。
- `validateChapterContractsForGeneration` 会在生成前阻断缺少合同、POV、场景目标、障碍、结果状态的章节。
- Writer/Rewriter 会注入硬约束上下文、章节目标、合同摘要、场景计划、人物状态、召回记忆和风格参考。
- Critic 会输出结构化审校意见，包含连续性、故事弧、语言、人机味、代价、反转、章节功能等。
- Canonizer 已接入 `prepareChapterWritebackRun`，生成后会准备状态差异草案。
- Finalize 会刷新摘要、连续性、长期记忆，并异步生成章节向量。
- 锁定段落机制已存在，Rewriter 会保护用户确认过的段落。
- `chapter_write` 工作流与各子任务已写入 `pipelineRole / pipelineStage / recoveryHintJson / progressJson`，任务中心可直接看到当前卡在哪个角色阶段。
- 已补齐标准失败退出码：`contract_blocked / context_overflow / anti_ai_failed / gate_rewrite_required / canon_failed / human_review_required`。
- 章节门已接入 Rewriter 之后的主流程，失败会把重写粒度和目标场景写回流水线快照。
- 已提供 `chapter:resumeContent` 稳定入口，任务中心可从失败阶段继续拉起单章流水线。
- 已为局部重写预留 `rewriteScope / targetSegmentId` 字段，供后续更细粒度重写直接复用。

## 四、详细设计

### 4.1 阶段职责

| 阶段 | 职责 | 不应负责 |
|---|---|---|
| Planner | 确认合同、场景计划和写作输入 | 写正文 |
| Writer | 按合同和硬约束写初稿 | 自行改设定、改合同 |
| Critic | 审校结构、连续性、语言和追读风险 | 大幅改写正文 |
| Rewriter | 按审校结论修正文稿 | 改动锁定段落 |
| Canonizer | 抽取事实和状态 diff | 自动无确认覆盖重要设定 |
| Finalize | 刷新摘要、记忆、向量 | 继续改正文 |

### 4.2 标准失败退出码

建议将失败原因标准化：

- `contract_blocked`：合同缺失、状态未 ready、场景字段不完整。
- `context_overflow`：上下文超预算，硬约束无法完整注入。
- `anti_ai_failed`：反 AI 味强制修复后仍未达标。
- `gate_rewrite_required`：章节门要求重写。
- `canon_pending`：Canon 草案生成成功但需要人工确认。
- `canon_failed`：Canon 草案生成失败。
- `human_review_required`：达到批次抽检或质量阈值，需要人工审。

这些退出码应写入任务输出或 `recoveryHintJson`，供批次总控使用。

### 4.3 批次接入方式

- 批次总控只调度章节流水线，不直接写正文。
- 正文生成默认按章节顺序执行。
- 同一批中已完成章节可以锁定，失败章节进入 blocked 队列。
- 恢复某章时必须重新读取最新合同、上下文版本和锁定段落。

### 4.4 局部重写扩展

Rewriter 后续应支持四种粒度：

- `paragraph_patch`：只替换少量问题段落。
- `scene_rewrite`：重写某个场景。
- `chapter_rewrite`：整章重写。
- `contract_replan`：正文问题源自合同设计，需要退回 Planner。

局部重写输入必须包含：

- 失败项。
- 目标场景或段落。
- 不可改内容。
- 必须保留的状态事实。
- 复检项目。

## 五、落地结果

1. 已补齐流水线任务字段和标准失败退出码。
2. 任务中心已能展示每章当前卡在哪个角色阶段，并显示退出码、重写粒度和目标场景。
3. 已为批次总控提供“启动单章流水线”和“继续单章流水线”的稳定接口。
4. 合同验证、反 AI 检测、章节门失败结果已统一进入流水线失败语义。
5. 已为局部重写预留 `rewriteScope` 和 `targetSegmentId`。

## 六、验收标准

- 单章流水线每一步都有清晰角色归属。
- 缺合同或缺 POV 的章节不能进入 Writer。
- 失败时能明确显示失败阶段和恢复入口。
- 批次总控能调度多个章节流水线，并隔离失败章节。
- Rewriter 不会覆盖锁定段落和已确认状态。

## 七、风险与建议

- 不要让 Writer 同时承担规划、审校和回写，否则百万字后期会漂移。
- 批次并行时要谨慎，正文生成依赖上一章状态，默认串行更稳。
- 当前已经完成失败退出码和批次接入，后续重点应转向真正的段落级/场景级局部重写，而不是继续堆叠整章重跑。
