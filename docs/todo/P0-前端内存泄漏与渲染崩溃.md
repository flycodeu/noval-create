# P0 - 前端内存泄漏与大规模渲染崩溃

> 优先级：P0（致命）
> 影响范围：200+章后UI不可用
> 实现难度：高
> 类别：前端-性能

---

## 问题

前端在处理百万字小说（400+章、50+角色、100+线索）时存在多个致命性能问题：

1. **Writing页面内存无限增长**：切换章节时，前一章的segment/timeline/item状态未清理，400章遍历后内存膨胀到GB级别
2. **Outline页面无虚拟化**：400+章节全量渲染DOM节点，页面卡死
3. **StoryThreads表格无分页**：`pagination={false}`，200条线索全量渲染
4. **Task Store流式数据无限累积**：`streams: Record<number, TaskStream>` 从未主动清理
5. **Novel Store无切换清理**：切换小说时旧数据残留

## 原因

- `Writing/index.tsx:148-250` 多个useState数组无生命周期管理
- `Outline/index.tsx:307-334` 直接 `.map()` 渲染所有弧/章节，无 VirtualList
- `StoryThreads/index.tsx:330-384` 表格 `pagination={false}` 且 `pageSize: 200`
- `stores/task.store.ts` 的 `streams` 字典无自动清理
- `stores/novel.store.ts` 无 `cleanup()` 方法
- 全局无 `ErrorBoundary` 组件，崩溃直接白屏

## 解决方式

1. **Writing页面章节缓存窗口**：仅保留当前章节±2章的数据，其余释放
2. **统一使用VirtualList**：Outline、StoryThreads、RevisionCenter等列表组件全部使用 `rc-virtual-list`（项目已有依赖）
3. **Task Store自动清理**：任务完成/失败后自动 `clearStream()`，保留最近10个流
4. **Novel Store切换清理**：`setCurrentNovelId` 时清空旧数据
5. **全局ErrorBoundary**：在Novel workspace层添加错误边界，崩溃时显示恢复UI而非白屏
6. **列表分页**：StoryThreads、RevisionCenter等表格启用分页（每页50条）

## 是否解决

已解决

## 预期效果

- 400+章小说浏览流畅无卡顿
- 长时间生成session不会因内存溢出崩溃
- 页面崩溃可恢复，不丢失进度
