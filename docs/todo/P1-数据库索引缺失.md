# P1 - 数据库索引缺失导致大规模查询缓慢

> 优先级：P1（严重）
> 影响范围：200+章后查询变慢3-10倍
> 实现难度：低
> 类别：后端-数据库

---

## 问题

当前19个索引覆盖了排序场景，但**WHERE条件过滤的高频查询缺少索引**。400+章、50+角色、100+时间线事件的规模下，全表扫描导致查询从10ms退化到500ms+，上下文构建从500ms退化到3-5秒。

## 原因

缺少以下关键索引：
- `chapters(novelId, status)` — 按状态过滤章节（如查找所有draft章节）
- `storyArcs(novelId, arcOrder)` — 按小说查弧并排序
- `characters(novelId, roleType)` — 按角色类型过滤
- `storyMemoryCheckpoints(novelId, scopeType, scopeId)` — 检查点查询
- `timelineEvents(novelId, arcId, status)` — 按弧和状态过滤事件

## 解决方式

1. **添加5个缺失索引**：在 `db.ts` 的迁移逻辑中补充上述索引
2. **使用复合索引**：确保WHERE和ORDER BY的字段在同一索引中
3. **添加查询性能监控**：在开发模式下记录慢查询（>100ms）
4. **索引有效性验证**：通过 `EXPLAIN QUERY PLAN` 验证索引被使用

## 是否解决

已解决

## 预期效果

- 400+章小说的查询响应时间保持在50ms以内
- 上下文构建时间从3-5秒降至500ms以内
- UI操作流畅无卡顿
