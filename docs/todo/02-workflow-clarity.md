# 步骤清晰度与阻塞提示

## 问题
- 用户进入页面后，不清楚应该先看哪里、先做什么。
- 推荐下一步和真实阻塞条件主要藏在工作台逻辑里，不够直观。
- AI 动作和人工编辑动作混在一起，难以判断先后顺序。

## 原因
- 当前步骤逻辑主要存在于 `workflow.ts`，但页面只显示了部分推荐信息。
- 缺少统一的页面级步骤条和任务优先顺序提示。
- 动作按钮只按功能堆放，没有按“生成 / 补全 / 修复”语义收口。

## 解决措施
- 在工作台、人物页、地图页、正文页增加共享步骤条。
- 后续把 `workflow.ts` 的 blocker 进一步直接映射到页面内提示区，而不只是在执行失败时弹出提示。
- 继续统一按钮语义，让 AI 动作尽量显式区分生成、补全、修复。

## 状态
- 状态：处理中
- 说明：高频页面的步骤条已补；阻塞项内嵌展示仍需继续下沉到更多页面。
