# 风格指纹硬约束化

## 一、目标

把参考文风从“氛围提示”升级为“可检查的写作约束”。系统应能分析用户参考文本，抽取句长、段落、对白、描写密度、禁用模式，并在生成后检查是否偏离。

## 二、当前已完成

- `style-analysis.service.ts` 已补齐长样本文本代表性采样，并输出句长、段长、对白占比、抽象词密度、禁用模式和示例摘录。
- `context.service.ts` 已将风格指纹拆成 `styleReference` 与 `styleHardGuard`，前者进入 `styleTemplate`，后者进入不可裁剪硬约束。
- 新增 `style-compliance.service.ts`，会在生成后做句长、段长、对白占比、抽象词密度和禁用模式的规则化校验。
- `chapter.service.ts` 会在 Critic 后和最终落盘前两次写入 `style_compliance`，严重偏离时直接触发重写。
- `context-impact.service.ts` 已新增独立章节门项 `style_compliance`，并写入分数、问题 key 与门禁快照。
- 质量看板已新增风格硬约束汇总、卷级风险和章节详情展示。

## 三、交付结果

- 风格指纹已从软参考升级为“软参考 + 硬约束 + 合规复检”三层结构。
- 禁用模式、句长范围、段落长度、对白占比和抽象词密度都已进入硬约束/复检链路。
- 风格合规分已持久化到 `reviewNotesJson` 和章节门分数中，无需新增表即可回溯。
- 风格严重偏离时会直接推高 `rewrite_required`，并在章节门中以 `rewrite` 级别拦截。

## 四、详细设计

### 4.1 风格指纹拆层

将风格指纹分为两层：

| 层级 | 内容 | 用途 |
|---|---|---|
| styleReference | 叙事技巧、气质、节奏、示例摘录 | 软参考 |
| styleHardGuard | 禁用模式、句长范围、段落长度、对白规则、描写密度 | 硬约束和复检 |

`styleHardGuard` 应进入硬约束预算，不能被软裁剪优先丢弃。

### 4.2 StyleComplianceChecker

新增风格合规检查：

- 平均句长偏差。
- 段落长度偏差。
- 禁用模式命中。
- 对白规则命中。
- 描写密度偏差。
- 抽象词密度偏差。

输出：

```ts
StyleComplianceResult {
  score: number
  status: 'pass' | 'warning' | 'rewrite'
  deviations: string[]
  rewriteHints: string[]
}
```

### 4.3 Prompt 注入策略

Writer 使用：

- 风格硬约束。
- 2-3 条正向写法要求。
- 禁用模式。

Rewriter 使用：

- 风格偏差报告。
- 需要修复的段落类型。
- 不模仿具体作者表达，只修正抽象风格指标。

### 4.4 合规边界

- 只能学习抽象写作特征，不能要求模仿特定在世作者的独特表达。
- 示例摘录只用于分析和提示，不应大量复用原文。
- 风格合规不能压过合同兑现和连续性。

## 五、实施步骤

1. 将 `forbiddenPatterns` 提升为硬约束候选。
2. 在上下文构造中拆出 `styleReference` 和 `styleHardGuard`。
3. 新增风格合规检查，先覆盖句长、段落、禁用模式。
4. 将合规结果写入审校意见和章节门。
5. 风格偏差严重时触发 Rewriter。

## 六、验收标准

- 风格指纹中的禁用模式进入生成前硬约束。
- 生成后能看到风格合规分。
- 句长、段落、对白和禁用模式偏差可解释。
- 风格偏差严重时进入重写，而不是只展示建议。

## 七、风险与建议

- 风格约束不能太窄，否则会压制剧情推进。
- 不要把参考文本具体句子作为可复用素材。
- 风格合规应服务“更像人写”，不是制造新的模板腔。
