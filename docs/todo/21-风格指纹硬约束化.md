# 风格指纹硬约束化

## 一、目标

把参考文风从“氛围提示”升级为“可检查的写作约束”。系统应能分析用户参考文本，抽取句长、段落、对白、描写密度、禁用模式，并在生成后检查是否偏离。

## 二、当前已完成

- `style-analysis.service.ts` 能分析参考文本，输出平均句长、句式偏好、叙事技巧、对白风格、描写密度、节奏、语调、禁用模式、示例摘录。
- `buildStyleFingerprintPromptSection` 会把 `forbiddenPatterns` 注入“禁用模式”。
- `context.service.ts` 会把风格指纹放入 `styleTemplate`。
- `ThemeVoice` 已有视角、文风、对白规则、描写规则和禁用表达字段。

## 三、当前缺口

- 风格指纹仍偏软参考，不是硬约束。
- 参考文本最多分析前 4 个 8000 字块，长参考样本覆盖不足。
- 生成后没有做风格命中率检查。
- 禁用模式没有进入不可裁剪硬约束。
- 风格偏离不会自动触发 Rewriter。

## 四、详细设计

### 4.1 风格指纹拆层

将风格指纹分为两层：

| 层级 | 内容 | 用途 |
|---|---|---|
| styleReference | 叙事技巧、气质、节奏、示例摘录 | 软参考 |
| styleHardGuard | 禁用模式、句长范围、段落长度、对白规则、描写密度 | 硬约束和复检 |

`styleHardGuard` 应进入硬约束预算，不能被软裁剪优先丢弃。

### 4.2 StyleComplianceChecker

新增风格合规检查：

- 平均句长偏差。
- 段落长度偏差。
- 禁用模式命中。
- 对白规则命中。
- 描写密度偏差。
- 抽象词密度偏差。

输出：

```ts
StyleComplianceResult {
  score: number
  status: 'pass' | 'warning' | 'rewrite'
  deviations: string[]
  rewriteHints: string[]
}
```

### 4.3 Prompt 注入策略

Writer 使用：

- 风格硬约束。
- 2-3 条正向写法要求。
- 禁用模式。

Rewriter 使用：

- 风格偏差报告。
- 需要修复的段落类型。
- 不模仿具体作者表达，只修正抽象风格指标。

### 4.4 合规边界

- 只能学习抽象写作特征，不能要求模仿特定在世作者的独特表达。
- 示例摘录只用于分析和提示，不应大量复用原文。
- 风格合规不能压过合同兑现和连续性。

## 五、实施步骤

1. 将 `forbiddenPatterns` 提升为硬约束候选。
2. 在上下文构造中拆出 `styleReference` 和 `styleHardGuard`。
3. 新增风格合规检查，先覆盖句长、段落、禁用模式。
4. 将合规结果写入审校意见和章节门。
5. 风格偏差严重时触发 Rewriter。

## 六、验收标准

- 风格指纹中的禁用模式进入生成前硬约束。
- 生成后能看到风格合规分。
- 句长、段落、对白和禁用模式偏差可解释。
- 风格偏差严重时进入重写，而不是只展示建议。

## 七、风险与建议

- 风格约束不能太窄，否则会压制剧情推进。
- 不要把参考文本具体句子作为可复用素材。
- 风格合规应服务“更像人写”，不是制造新的模板腔。
