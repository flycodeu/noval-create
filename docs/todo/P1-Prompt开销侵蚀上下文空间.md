# P1 - Prompt开销侵蚀上下文空间

> 优先级：P1（严重）
> 影响范围：150+章后上下文被截断
> 实现难度：中
> 类别：后端-Prompt工程

---

## 问题

上下文预算（mega级16000 tokens）中，各类prompt补充指令累计消耗1000+ tokens：生产补充要求（+200）、最终成稿补充要求（+300）、节奏指导（+150）等。实际可用于故事上下文的仅约12000 tokens。对于400+章小说：

- 20章回溯窗口×200-300字摘要 = 4000-6000 tokens
- 15个角色状态 = 2000 tokens
- **剩余仅4000 tokens**用于线索、物品、世界规则、连续性——严重不足

## 原因

- `story-prompts.ts` 中各补充section持续膨胀，但未纳入token预算计算
- `context.service.ts:989-1022` 的预算分配未扣除prompt固定开销
- 新增的节奏指导、对话指令、去AI味指令等进一步压缩可用空间
- 缺少prompt压缩或按需裁剪机制

## 解决方式

1. **将prompt固定开销纳入预算计算**：`buildChapterContext()` 现已按 `scenePlan / draft / review / rewrite` 预估固定prompt开销与输出预留，再分配故事上下文预算
2. **按阶段构建context**：章节主流程不再复用一份通用context，而是为规划、初稿、审校、重写分别构建上下文
3. **Prompt动态裁剪**：`story-prompts.ts` 按 `simple / standard / key` 章节类型选择性注入增强指令，简单章节不再带完整补充段
4. **分层指令注入**：核心指令始终保留，增强指令只在 standard / key 章节注入，关键章节再额外强化弧推进与结果兑现要求
5. **提升mega预算底线**：350k+/800k+/150万+ 长篇小说的上下文预算底线已提升到 `14000 / 18000 / 22000` tokens，并优先保住故事弧、连续性、开放线索和角色状态

## 是否解决

已解决

## 预期效果

- 400+章小说的上下文不再被prompt开销挤压
- 关键故事信息（线索、角色、世界规则）获得充足空间
- 章节质量不因prompt膨胀而下降
