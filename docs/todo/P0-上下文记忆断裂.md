# P0 - 上下文记忆断裂（长程遗忘）

> 优先级：P0（致命）
> 影响范围：全书逻辑崩塌
> 实现难度：高

---

## 问题

当前系统对百万字小说（约300-400章）仅保留最近8-10章的上下文窗口。第1-100章的剧情细节、伏笔、人物状态在生成第200章时几乎完全丢失。跨越50章以上的长线伏笔无法被AI感知，导致前后矛盾、伏笔悬空、剧情逻辑断裂。

## 原因

- `context.service.ts` 中 `resolveRecentContextWindow()` 最大仅回溯10章（约3万字），百万字小说有97%的内容不在上下文中
- 记忆检查点（`storyMemoryCheckpoints`）虽存在卷级摘要，但摘要粒度过粗——mega模式仅7个阶段摘要，平均每个摘要覆盖14万字
- Token预算硬顶（7200-8000 tokens），P3优先级的历史摘要经常被截断或丢弃
- 无分层记忆压缩机制：缺少「卷摘要→部摘要→弧摘要→章摘要」的递进式记忆

## 解决方式

1. **实现分层记忆架构**：建立四级摘要体系（Novel→Volume→Part→Arc），每级保留关键信息的不同粒度
2. **引入伏笔追踪表**：为 `storyThreads` 添加 `plantedChapter`、`lastReferencedChapter`、`reminderInterval` 字段，定期在上下文中注入即将到期的伏笔
3. **动态记忆召回**：根据当前章节涉及的角色、地点、物品，从历史章节中召回相关摘要片段（向量检索或关键词匹配）
4. **扩展Token预算**：对mega级别小说，将上下文预算提升至12000-16000 tokens，利用大模型128K窗口
5. **记忆检查点细化**：mega模式下每20章生成一个检查点（而非每卷），确保摘要粒度足够

## 是否解决

已解决 — 2026-04-04

已实施以下修复：
1. `resolveRecentContextWindow()` 回溯窗口从 5-10 章扩展到 8-20 章
2. Token预算从 6000-8000 提升至 10000-16000（`buildChapterContext` 默认预算从 6000→10000，mega 级别 budgetFloor 从 8000→16000��
3. `storyThreads` 表新增 `plantedChapter`、`lastReferencedChapter`、`reminderInterval` 字段，支持伏笔定期提醒
4. `buildActiveThreadsContext()` 增加长线伏笔提醒机制：超过 reminderInterval 章未引用的线索自动注入上下文
5. 活跃线索显示上限从 6 条扩展到 10 条

## 预期效果

- 第300章仍能准确引用第10章的伏笔
- 跨卷角色弧线保持连贯
- 长线悬念在合理时机收束
