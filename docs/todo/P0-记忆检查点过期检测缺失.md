# P0 - 记忆检查点过期检测缺失

> 优先级：P0（致命）
> 影响范围：mega级小说后期弧线失去连贯性
> 实现难度：中
> 类别：后端-记忆系统

---

## 问题

`checkpointsNeedRefresh()` 仅检查 `checkpoint.version < novel.contextVersion`，但**并非所有影响上下文的变更都会递增contextVersion**。角色改名、时间线事件修改、物品属性变更等操作不触发版本递增，导致检查点可能在活跃项目中**数周内过期而不被标记刷新**。

## 原因

- `story-memory.service.ts:362-371` 依赖 `contextVersion` 作为唯一过期判断依据
- 角色名称变更、时间线事件修改、物品属性变更等操作未递增 `novel.contextVersion`
- 缺少基于时间或章节进度的辅助过期判断
- mega模式（400+章）下，检查点可能覆盖100+章未被刷新

## 解决方式

1. **扩展版本递增触发点**：角色、时间线、物品、世界规则的CRUD操作均递增 `contextVersion`
2. **基于章节进度的过期策略**：检查点的 `lastRefreshedChapterNum` 与当前章节差值超过阈值（如30章）时自动标记过期
3. **基于时间的辅助检测**：检查点超过7天未刷新时触发警告
4. **脏标记机制**：每个实体修改时在检查点上设置 `dirty` 标记

## 是否解决

已解决

## 预期效果

- 检查点始终反映最新的角色/物品/世界观状态
- 消除因检查点过期导致的后期弧线与前期设定不一致
- mega级小说全程保持记忆准确性
