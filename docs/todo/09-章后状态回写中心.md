# 章后状态回写中心

## 一、目标

把“写完一章”从正文保存动作，升级成“事实抽取 -> 状态差异 -> Canon 确认 -> 统一写回”的长篇稳定性中枢。

## 二、当前已完成

- [x] `chapter.service.ts` 写作后会刷新人物状态版本、世界状态版本、时间线结构锚点、故事记忆检查点。
- [x] `character-state.service.ts` 已能按章节生成人物状态摘要与漂移预警。
- [x] `world-state.service.ts` 已能按章节生成世界状态摘要、冲突和预警。
- [x] 系统已具备章节摘要、连续性状态、实体发现和上下文脏标记机制。

## 三、当前未完成

- [ ] 没有独立的 `章后状态回写中心` 页面。
- [ ] 没有显式的“正文事实抽取结果”审阅面板。
- [ ] 没有统一的 Canon 确认流程。
- [ ] 没有把线程、伏笔、谜题、关系弧一起纳入回写。
- [ ] 没有失败回写后的人工修正与重试闭环。

## 四、为什么现在要补

- 只存正文、不结构化回写，是上下文漂移的根本原因。
- 当前后台已经在做很多回写，但因为不可见，难以审阅、纠错和扩展到更多资产。

## 五、建议新增内容

- 新增页面：`章后状态回写中心`
- 固定四步流程：
  1. `事实抽取`
  2. `状态 Diff`
  3. `Canon 确认`
  4. `统一写回`
- 回写范围统一覆盖：
  - `人物`
  - `世界`
  - `物品`
  - `关系`
  - `线程`
  - `伏笔`
  - `谜题`
  - `时间轴`

## 六、页面与交互

- 从正文写作完成后自动弹出，或在写作页手动进入。
- 左侧展示本章抽取事实，右侧展示拟写回差异。
- 支持逐项确认、拒绝、修改后再写回。
- 写回失败时自动生成修订任务并保留未确认草稿。

## 七、数据结构 / 状态字段

- 建议新增：
  - `chapter_writeback_runs`
  - `chapter_writeback_diffs`
  - `chapter_fact_extracts`
- 关键字段：
  - `entityType`
  - `entityId`
  - `beforeState`
  - `afterState`
  - `diffReason`
  - `confidence`
  - `canonDecision`
  - `writebackStatus`

## 八、与现有模块的关系

- `正文写作` 负责产出正文。
- `章后状态回写中心` 负责把正文转成 Canon。
- `修订中心` 接收写回失败或冲突任务。
- `质量监控` 读取回写后的结构化状态，而不是依赖正文摘要猜测。

## 九、验收标准

- 每章完成后都能看到结构化回写候选。
- 人物与世界状态写回不再只是后台黑盒。
- 至少支持手动确认、拒绝和重跑。
- 线程、伏笔、谜题等新增资产也能进入同一回写流程。
