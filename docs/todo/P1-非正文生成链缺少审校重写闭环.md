# P1 - 非正文生成链缺少审校重写闭环

> 优先级：P1（严重）
> 影响范围：语言质量、背景主题对齐、上游资产可靠性
> 实现难度：中高

---

## 涉及模块

- `electron/services/asset-quality.service.ts`
- `electron/services/prompts.ts`
- `electron/services/character.service.ts`
- `electron/services/item.service.ts`
- `electron/services/story-thread.service.ts`
- `electron/services/timeline.service.ts`
- `electron/services/subplot.service.ts`
- `electron/services/core-settings.service.ts`

## 问题

正文主链路已经有相对完整的审校重写闭环，但人物、物品、线程、时间轴、支线、地图、世界规则这些非正文资产，过去大多还是“生成 -> 解析 -> 去重/校验 -> 落库”。

这会导致上游资产先带着模板腔、背景漂移、关系失真或空泛摘要进入系统，正文阶段只能被动补救，无法在源头拦截。

## 已实现修复

1. 新增统一资产审校层 `asset-quality.service.ts`，提供：
   - 结构化审校结果
   - 轻问题定向重写
   - 重问题拒收
   - 审校进度回写到任务 `progressJson.assetReview`
2. 下列非正文链路已接入统一闭环：
   - 人物：批量生成、批次生成、单条重写
   - 物品：批量生成、批次生成、单条重写
   - 线程：批量生成、批次生成、单条重写
   - 时间轴：批量生成、批次生成、单条重写
   - 支线：批次生成 + `core-settings` 的后置 polish
   - 地图：root/child 批次在 JSON repair 后再走审校
   - 世界规则：按 section 粒度审校与定向重写
3. 审校通过前的候选不会进入原有落库路径；被拒收的结果只保留在任务观测里，不会静默入库。
4. `TaskCenter` 已能展示资产类型、质检阶段、严重度、修法、风险和备注，不再只靠自由文本 warning。

## 实现方式

- 审校维度覆盖：
  - 题材 / 背景 / 世界规则贴合度
  - 主线目标 / 核心冲突 / 章节进度一致性
  - 模板腔、设定味、抽象空话、语言风险
  - 与人物 / 物品 / 地图 / 时间轴 / 其他资产的冲突风险
- 处理路径：
  - 轻问题：保持 JSON 结构不变，做定向重写
  - 重问题：直接拒收，本轮结果不落库
- 观测方式：
  - 不新增数据库字段
  - 统一写入任务 `progressJson.assetReview`

## 是否解决

已解决 — 2026-04-05

当前状态：

- 非正文主生成链已经补上“审校 -> 重写/拒收 -> 观测回写 -> 再进入原校验/落库”的闭环
- 正文侧天然只会消费已通过审校并成功落库的资产

## 仍保留的实现边界

- 这轮没有新增资产级数据库状态位，审校观测依赖任务进度数据而不是实体字段。
- 支线仍保留原有业务校验和 merge 逻辑；统一审校层负责质量治理，不替代已有业务约束。

## 预期效果

- 上游资产更接近可直接写作的故事材料，而不是粗糙设定稿
- 背景偏移、主题跑偏、角色动机空泛等问题能在资产层被截住
- 正文阶段的审校压力下降，整体生成链更稳定
