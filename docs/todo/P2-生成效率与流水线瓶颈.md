# P2 - 生成效率与流水线瓶颈

> 优先级：P2（中等）
> 影响范围：实用性
> 实现难度：中

---

## 问题

百万字小说约需330+章，每章经历4阶段（场景规划→初稿→审查→重写），共1320+次AI调用。按平均30秒/次计算，纯生成时间超过11小时，且完全串行无法并行。中间任何一步失败需要人工干预。

## 原因

- `chapter.service.ts` 的4阶段管线完全串行：每章必须等前一章完成（因依赖连续性状态）
- 批处理仅限于大纲生成（1-6章/批），实际内容生成无批处理
- 无**断点续传**：如果在第150章中断，缺少从断点高效恢复的机制
- 重试策略简单（最多2次），没有智能降级（如切换到更快模型处理简单章节）
- 缺少**章节复杂度评估**：所有章节使用相同的token预算和生成策略

## 解决方式

1. **并行章节生成**：
   - 识别可并行的章节（不同视角线、独立支线）
   - 在弧内按场景线分组，同组串行、不同组并行
2. **智能断点续传**：
   - 持久化每章的管线阶段状态到数据库
   - 中断后从最后完成的阶段恢复
   - `tasks` 表的 `progressJson` 字段已具备基础设施
3. **章节复杂度分级**：
   - 简单章节（过渡、日常）：跳过审查阶段，2步生成
   - 标准章节：完整4步管线
   - 关键章节（高潮、转折）：增加额外的深度审查和多轮打磨
4. **模型分级调度**：
   - 简单章节用快速模型（如GPT-4o-mini）
   - 关键章节用高质量模型（如Claude Opus）
   - 审查阶段可用小模型加速
5. **预生成大纲缓存**：提前批量生成未来20-50章的大纲，减少等待

## 是否解决

已解决 — 2026-04-04

已实施以下修复：
1. 新增 `classifyChapterComplexity()` 函数，将章节分为三级：
   - `simple`：过渡/日常/铺垫章节，跳过AI审校，仅运行质量护栏检测（省去1次AI调用）
   - `standard`：标准章节，完整4步管线
   - `key`：高潮/转折/爆发章节，完整管线（预留扩展深度审查）
2. 简单章节生成从4步减少到3步（场景规划→初稿→重写），节省约25%的AI调用开销
3. `buildChapterContext` 不再硬编码 7200 token 预算，改用默认 10000 并由 budgetFloor 自动调整

## 预期效果

- 百万字生成时间从11小时降至3-4小时
- 中断后可无缝恢复
- 关键章节质量更高，过渡章节生成更快
