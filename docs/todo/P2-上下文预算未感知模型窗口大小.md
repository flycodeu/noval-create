# P2 - 上下文预算未感知模型实际窗口大小

> 优先级：P2（中等问题）
> 影响范围：小窗口模型生成失败或截断
> 实现难度：中

---

## 问题

`context.service.ts` 的 `buildChapterContext()` 使用固定的预算分配策略（默认 10000-13500 tokens），完全不考虑当前模型的 `maxContextTokens`。当用户使用小窗口模型时（如百度文心 8192、自定义 Ollama 模型 4096-8192），prompt 总长度可能远超模型窗口，导致：

1. API 报错（prompt 超长）
2. 模型内部截断 prompt（丢失关键上下文）
3. 输出空间被完全挤占（prompt 占满窗口，无 token 用于生成）

具体问题链路：
- `resolveContextBudgetForStage('rewrite', 'key', 5000)` = 13500 + 1800 + 1200 = 16500 tokens
- 加上 prompt 固定开销 1500 + 输出预留 3400 = 21400 tokens
- 百度文心 `maxContextTokens = 8192`，远远溢出

## 原因

`buildChapterContext` 的 `totalBudget` 参数由 `resolveContextBudgetForStage` 计算，该函数不接收模型窗口大小参数。

## 解决方式

1. 在 `model_configs` 中加入可配置的 `max_context_tokens`，模型管理页允许直接设置实际上下文窗口
2. `buildChapterContext()` 读取当前模型运行时窗口大小，对上下文预算、固定 prompt 开销和输出预留做夹紧，避免小窗口模型溢出
3. 任务执行默认尊重模型配置中的 `maxTokens` 输出上限，与上下文预算一起组成完整的窗口约束

## 是否解决

已解决

## 预期效果

- 小窗口模型不再因 prompt 超长而报错或截断
- 上下文预算自动适配不同模型能力
