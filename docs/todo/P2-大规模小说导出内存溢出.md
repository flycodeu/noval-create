# P2 - 大规模小说导出内存溢出

> 优先级：P2（中等）
> 影响范围：百万字小说导出失败
> 实现难度：低
> 类别：后端-导出

---

## 问题

导出功能将整本小说内容拼接为单个字符串后一次性写入文件。百万字小说（120万字符+）导致内存峰值达500MB-1GB，DOCX格式更甚。内存紧张的设备上会直接崩溃。

## 原因

- `export.service.ts:30-125` 在内存中构建完整内容字符串
- `fs.writeFileSync()` 同步写入，阻塞主线程
- DOCX库 `docx` 需要在内存中构建完整文档对象
- 无流式写入机制

## 解决方式

1. **流式写入txt/md**：使用 `fs.createWriteStream()` 逐章写入
2. **自动分卷导出**：大规模小说不再强制导出为单文件，而是导出到目录并生成 `manifest.json`
3. **DOCX按卷/区间拆分**：大书会按卷或章节区间生成多个较小的 DOCX，避免构建超大单文档
4. **移除同步整本写入**：不再使用 `fs.writeFileSync()` 拼整本字符串，改为异步写入和分块导出

## 是否解决

已解决

## 预期效果

- 百万字小说导出内存占用控制在100MB以内
- 导出过程不阻塞UI
- 支持分卷导出
