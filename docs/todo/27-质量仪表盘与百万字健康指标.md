# 质量仪表盘与百万字健康指标

## 一、目标

在现有质量监控基础上，增加百万字生产视角。当前模块要回答的核心问题只有一个：现在能不能继续生成下一批？

本模块的定位固定为“健康汇总层”，而不是质量修复引擎。

## 二、修复状态

- 已完成 百万字健康聚合：`quality-dashboard.service.ts` 现已输出 `productionReadiness / batchHealth / continuityHealth / contractDelivery / batchReview` 五组批量生产摘要。
- 已完成 继续下一批总灯：质量监控页已在总览区展示生产就绪度、批次健康、连续性健康和合同交付灯。
- 已完成 批次复盘摘要：最近批次的回查、回写待处理、复现问题和下一批避免项已进入质量仪表盘。
- 已完成 创作总览速览：`Overview` 页已补充百万字健康速览，可在进入正文前先看生产灯。

## 三、模块定位与边界

`27-质量仪表盘与百万字健康指标` 当前只负责健康汇总层能力：

- 回答“现在能不能继续下一批”。
- 展示生产就绪度、批次健康、连续性健康、合同交付和批次复盘。
- 提供暂停建议、风险摘要和下一批避免项。
- 在质量监控页与创作总览页提供批次级生产视角。

本模块当前不包含以下增强层能力：

- 风险成因解释。
- 修法建议。
- 质量页直接动作入口。
- 承诺兑现率、角色声音区分度、成长-代价平衡、信息揭示节奏等增强指标。
- 修订建议生成、场景重写、时间轴同步、状态同步等修复引擎能力。

上述增强能力统一归入 `33-质量监控升级为修复引擎`，不继续并回本模块状态。

- 已补充召回降级、检查点滞后、章后回写、批量任务状态、合同交付和反馈复现的统一汇总。

## 五、详细设计

### 4.1 百万字健康面板

新增五个区域：

- `Production Readiness`：是否可继续下一批。
- `Batch Health`：当前批次状态、失败章、待确认项。
- `Continuity Health`：状态跳变、召回降级、checkpoint 新鲜度。
- `Anti-AI Recurrence`：AI 味复现率和动态禁用升级。
- `Contract Delivery`：合同兑现、支线推进、伏笔回收。

### 4.2 核心指标

建议阈值：

| 指标 | 目标 |
|---|---:|
| 章节门 ready 率 | >= 90% |
| 合同 blocker | 0 |
| Canon 回写待确认 | <= 3 章 |
| AI 味跨章复现率 | <= 10% |
| 召回连续降级 | <= 2 章 |
| 支线超期未处理 | 0 |
| checkpoint 间隔 | <= 10 章 |

### 4.3 总灯状态

| 状态 | 含义 |
|---|---|
| ready | 可以继续生成下一批 |
| warning | 可以继续，但建议先处理风险 |
| blocked | 不建议继续，必须修复关键问题 |

`blocked` 条件：

- 合同 blocker > 0。
- 连续召回失败 >= 3 章。
- Canon 回写积压过多。
- AI 味复现超过阈值。
- 关键状态跳变未确认。

### 4.4 批次复盘

每批结束生成：

- 通过章节数。
- 重写次数。
- 待确认回写。
- 主要复现问题。
- 召回健康。
- 下一批必须避免。

## 六、落地结果

1. 已在 dashboard 数据层增加百万字健康聚合。
2. 已加入召回、反馈复现、合同验证、批次状态和章后回写指标。
3. 已在创作总览展示总灯速览。
4. 已在质量监控页增加批次健康详情。
5. 已为最近批次生成复盘摘要。

## 七、验收标准

- 系统能明确回答“现在能不能继续批量生成下一批”。
- 风险能定位到卷、批次、章节和具体模块。
- 用户不需要逐章点开才能发现系统性问题。
- 批次复盘能直接转化为下一批生成约束。

## 八、风险与建议

- 指标不要太多，首页只放总灯和关键 blocker。
- 质量分不能替代可解释问题列表。
- 初期阈值可保守，等实际生成数据积累后再调。

## 九、与 33 的职责边界

当前文档解决的是“能否继续生成下一批”的健康汇总问题，已经具备发现问题、定位风险和给出暂停建议的能力；它不负责解释原因、生成修法和落动作。

职责拆分固定如下：

- `27` 负责健康汇总、总灯、暂停建议和批次复盘。
- `33` 负责风险解释、修法建议、动作入口和增强指标。

后续增强统一并入 `33-质量监控升级为修复引擎`，`27` 不再通过叠加修复能力改变完成状态。
