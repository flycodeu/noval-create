## 四、详细设计

### 4.1 百万字健康面板

新增五个区域：

- `Production Readiness`：是否可继续下一批。
- `Batch Health`：当前批次状态、失败章、待确认项。
- `Continuity Health`：状态跳变、召回降级、checkpoint 新鲜度。
- `Anti-AI Recurrence`：AI 味复现率和动态禁用升级。
- `Contract Delivery`：合同兑现、支线推进、伏笔回收。

### 4.2 核心指标

建议阈值：

| 指标 | 目标 |
|---|---:|
| 章节门 ready 率 | >= 90% |
| 合同 blocker | 0 |
| Canon 回写待确认 | <= 3 章 |
| AI 味跨章复现率 | <= 10% |
| 召回连续降级 | <= 2 章 |
| 支线超期未处理 | 0 |
| checkpoint 间隔 | <= 10 章 |

### 4.3 总灯状态

| 状态 | 含义 |
|---|---|
| ready | 可以继续生成下一批 |
| warning | 可以继续，但建议先处理风险 |
| blocked | 不建议继续，必须修复关键问题 |

`blocked` 条件：

- 合同 blocker > 0。
- 连续召回失败 >= 3 章。
- Canon 回写积压过多。
- AI 味复现超过阈值。
- 关键状态跳变未确认。

### 4.4 批次复盘

每批结束生成：

- 通过章节数。
- 重写次数。
- 待确认回写。
- 主要复现问题。
- 召回健康。
- 下一批必须避免。

2. 已加入召回、反馈复现、合同验证、批次状态和章后回写指标。
3. 已在创作总览展示总灯速览。
4. 已在质量监控页增加批次健康详情。
5. 已为最近批次生成复盘摘要。

## 六、验收标准

- 系统能明确回答“现在能不能继续批量生成下一批”。
- 风险能定位到卷、批次、章节和具体模块。
- 用户不需要逐章点开才能发现系统性问题。
- 批次复盘能直接转化为下一批生成约束。

## 七、风险与建议

- 指标不要太多，首页只放总灯和关键 blocker。
- 质量分不能替代可解释问题列表。
- 初期阈值可保守，等实际生成数据积累后再调。
