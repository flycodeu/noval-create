# 质量仪表盘与百万字健康指标

## 一、目标

在现有质量监控基础上，增加百万字生产视角。仪表盘要能回答一个核心问题：现在能不能继续生成下一批？

## 二、当前已完成

- `quality-dashboard.service.ts` 已聚合语言漂移、章节门、对白指纹、故事弧推进、世界状态、章节功能、卷级风险。
- 写作页和质量监控页已展示不少章节级和全书级指标。
- `chapterGateRuns` 能保存章节门历史。

## 三、当前缺口

- 缺少百万字生产 SLA。
- 缺少批次级健康视图。
- 缺少“继续生成下一批”的总灯。
- 召回可用率、Canon 回写完成率、AI 味复现率、合同兑现率没有统一呈现。

## 四、详细设计

### 4.1 百万字健康面板

新增五个区域：

- `Production Readiness`：是否可继续下一批。
- `Batch Health`：当前批次状态、失败章、待确认项。
- `Continuity Health`：状态跳变、召回降级、checkpoint 新鲜度。
- `Anti-AI Recurrence`：AI 味复现率和动态禁用升级。
- `Contract Delivery`：合同兑现、支线推进、伏笔回收。

### 4.2 核心指标

建议阈值：

| 指标 | 目标 |
|---|---:|
| 章节门 ready 率 | >= 90% |
| 合同 blocker | 0 |
| Canon 回写待确认 | <= 3 章 |
| AI 味跨章复现率 | <= 10% |
| 召回连续降级 | <= 2 章 |
| 支线超期未处理 | 0 |
| checkpoint 间隔 | <= 10 章 |

### 4.3 总灯状态

| 状态 | 含义 |
|---|---|
| ready | 可以继续生成下一批 |
| warning | 可以继续，但建议先处理风险 |
| blocked | 不建议继续，必须修复关键问题 |

`blocked` 条件：

- 合同 blocker > 0。
- 连续召回失败 >= 3 章。
- Canon 回写积压过多。
- AI 味复现超过阈值。
- 关键状态跳变未确认。

### 4.4 批次复盘

每批结束生成：

- 通过章节数。
- 重写次数。
- 待确认回写。
- 主要复现问题。
- 召回健康。
- 下一批必须避免。

## 五、实施步骤

1. 在 dashboard 数据层增加百万字健康聚合。
2. 加入召回、反馈复现、合同验证、批次状态指标。
3. 在创作总览展示总灯。
4. 在质量监控页增加批次健康详情。
5. 批次结束自动生成复盘摘要。

## 六、验收标准

- 系统能明确回答“现在能不能继续批量生成下一批”。
- 风险能定位到卷、批次、章节和具体模块。
- 用户不需要逐章点开才能发现系统性问题。
- 批次复盘能直接转化为下一批生成约束。

## 七、风险与建议

- 指标不要太多，首页只放总灯和关键 blocker。
- 质量分不能替代可解释问题列表。
- 初期阈值可保守，等实际生成数据积累后再调。
