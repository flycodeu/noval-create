# 伏笔与回收账本

## 一、目标

把伏笔从“线程里的一个提醒”升级成可追踪、可回收、可审计的独立资产。

## 二、当前已完成

- [x] `story_threads` 已有 `plantedChapter / targetPayoffChapter / resolvedChapter`。
- [x] `story-thread.service.ts` 提供 `getForeshadowSnapshot`。
- [x] 质量看板已经展示 `pending / dueSoon / overdue / resolved` 伏笔状态。
- [x] 写作上下文已会读取 `dueForeshadows`。
- [x] 已新增独立 `foreshadow_ledger` 数据表，伏笔不再只能混在线程里。
- [x] 伏笔资产已支持 `sourceChapterId / sourceSegmentId / plantMethod / salienceLevel / payoffMethod / impactScope / linkedEndgameCommitmentId`。
- [x] 终局设计保存后会自动为 `长线回收清单` 同步伏笔账本草稿，并与终局承诺建立硬绑定。

## 三、当前未完成

- [ ] 没有“本章埋下了哪些新伏笔”的显式回写。
- [ ] 还没有独立的前台 `伏笔与回收账本` 页面。

## 四、为什么现在要补

- 长篇最容易出现“埋过很多点，但系统不知道怎么收”。
- 当前做得到“记得有伏笔”，但做不到“控制显著度、安排回收方式、衡量兑现影响”。

## 五、建议新增内容

- 新增页面：`伏笔与回收账本`
- 每条伏笔至少维护：
  - `埋设位置`
  - `埋设方式`
  - `当前显著度`
  - `预期回收章节`
  - `回收方式`
  - `回收后的影响范围`
- 支持按：
  - `主线伏笔`
  - `人物伏笔`
  - `世界观伏笔`
  - `谜题伏笔`
  分类查看

## 六、页面与交互

- 允许从故事线程导入为伏笔草稿，但不强制一一映射。
- 支持从章节和场景回写新伏笔。
- 提供“接近目标回收章位”和“已超期”的专门视图。
- 支持从终局设计或卷级设计反向筛出必须回收项。

## 七、数据结构 / 状态字段

- 建议新增：
  - `foreshadow_ledger`
  - `foreshadow_payoffs`
- v1 最少字段：
  - `title`
  - `sourceChapterId / sourceSegmentId`
  - `plantMethod`
  - `salienceLevel`
  - `targetPayoffChapter`
  - `payoffMethod`
  - `impactScope`
  - `status`
  - `linkedThreadId`
  - `linkedEndgamePromise`

## 八、与现有模块的关系

- `故事线程` 管故事线。
- `伏笔与回收账本` 管爆点与兑现。
- `章节合同` 负责规定本章必须埋什么或收什么。
- `质量监控` 继续负责预警伏笔债务。

## 九、验收标准

- 能新增、检索、回写独立伏笔资产。
- 能区分伏笔与故事线程。
- 章节写完后可回写新伏笔或已回收伏笔。
- 质量看板可直接读取新账本，而非只依赖线程推断。
